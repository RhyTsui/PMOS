## 一、系统演进路线（原始 → 抽象）

```

v0.3  账号池 + 覆盖率评估

v0.5  精简聚焦：采得全 + 采得准 + 能理解
```

## 二、提炼出的 10 条通用设计原则

### 原则 1：管线分离，快慢解耦
**来源**：v0.1
**原始表述**："采集（快）→ 队列 → 解析（慢）→ 入库"，避免"解析拖死采集"
**通用化**：采集层必须快进快出，耗时的 LLM 抽取/评分异步处理，互不阻塞

### 原则 2：多入口覆盖，不依赖单一路径
**来源**：v0.2, v0.5, v0.8
**原始表述**："搜索流 + 推荐流 + 相关推荐流 + 主页流"
**通用化**：情报采集必须多入口（RSS/API/爬取/搜索/订阅），任何单点失效都不能导致漏采

### 原则 3：覆盖率可量化，漏采可检测
**来源**：v0.3, v0.5
**原始表述**："Coverage = 已采集广告 / 估计广告总量"，"如果 24h 新增广告 < 阈值 → 说明漏采"
**通用化**：必须量化"采到了多少"，必须有漏采检测机制。不能凭感觉认为"采够了"

### 原则 4：种子决定上限，不是爬虫决定上限
**来源**：v0.10, v0.11
**原始表述**："采集能力上限，不是由'爬多少'决定，而是由'种子系统质量'决定"
**通用化**：采集什么、怎么发现新方向，取决于种子（关键词/实体/话题/源）的质量和自进化能力

### 原则 5：种子必须自进化
**来源**：v0.11, v0.12, v0.13
**原始表述**："Seed → 采集 → 新广告 → 新关键词 → 新 Seed"，自动评分 + 淘汰 + 扩展
**通用化**：种子不是静态配置，必须根据采集效果自动评分、自动淘汰低效种子、自动发现新种子

### 原则 6：去重是结构化的前提
**来源**：v0.3, v0.16
**原始表述**："同一广告的不同剪辑/文案/Hook → 聚合为一个 Family"
**通用化**：同一事件在多个源出现必须合并，必须从碎片信息中聚合出结构化事件

### 原则 7：趋势检测 = 异常检测 + 增长检测
**来源**：v0.14
**原始表述**："Cluster Growth Rate + Embedding Drift + Seed Activation Spike"
**通用化**：检测某类事件突然增多（增长）、新类型出现（异常）、讨论开始重复（饱和）

### 原则 8：结构解析而非原始堆砌
**来源**：v0.5, v0.16, v1.0
**原始表述**：从视频中提取 Hook + 卖点 + CTA + 游戏类型
**通用化**：采集到的原始信息必须经过结构化抽取，输出可直接消费的结论，而不是堆原文

### 原则 9：系统必须自进化
**来源**：v0.12, v1.8
**原始表述**："自动发现'有效 seed'、自动淘汰无效 seed、自动扩展新的 seed 空间"
**通用化**：系统每周自动评估采集质量，自动发现问题，自动寻找更好的工具/方法

### 原则 10：采集的终点不是"更多数据"，而是"结构压缩能力"
**来源**：v1.0
**原始表述**："把所有广告家族 → 压缩成可复用的'创意公式'"
**通用化**：最终目标是从海量信息中提炼出可复用的模式和规律，而不只是存更多文章

## 三、从"广告素材"到"文本情报"的映射

| 原始广告概念 | 情报平台对应 | 说明 |
|-------------|------------|------|
| 广告视频 | 文章/帖子/公告 | 采集对象从视频变为文本+图片 |
| OCR（画面文字） | OCR（文章图片文字） | 图片解析保留，但目标是提取文字信息 |
| ASR（语音转文字） | ❌ 不需要 | 没有视频/音频 |
| Hook（前3秒吸引句） | 事件标题 | 一句话概括核心信息 |
| 卖点（产品利益点） | 关键事实 | 涉及谁、发生什么、影响多大 |
| CTA（行动号召） | 行动建议 | 对不同角色意味着什么 |
| 游戏类型 | 事件类型 | 上线/测试/版号/买量/舆情… |
| 广告家族（Family） | 事件合并 | 同一事件多源报道合并 |
| 广告变体 | 同一事件的不同角度报道 | 合并后保留多视角信息 |
| 创意模板 | 事件模式 | 同类事件的标准化结构 |
| 推荐流 | RSS/订阅流 | 日常更新的主要来源 |
| 搜索流 | 搜索 API | 定向搜索特定关键词 |
| 账号人格 | 视角配置 | 不同源/不同维度 = 不同信息切面 |
| 投放预测 | 趋势检测 | 某类事件是否正在增长 |
| 爆款概率 | 信号评分 | 事件重要度 0-100 |

## 四、当前场景不适用、但保留供参考的概念

以下概念在原始广告场景中有价值，但当前文本情报场景暂不需要：

| 概念 | 来源 | 为什么暂不需要 | 未来可能复用场景 |
|------|------|--------------|----------------|
| 视频 Embedding | v0.13 | 没有视频 | 如果未来做广告素材分析 |
| RL 强化学习种子选择 | v0.12 | V1.0 规则评分足够 | 数据量积累后 V2.0 |
| 多 Agent 竞争进化 | v1.8 | 情报平台不生成内容 | 如果未来做广告生成 |
| 行为引擎（反风控） | v0.6-v0.8 | 文本采集反爬弱于视频 | 如果采集强反爬平台 |
| 广告生命周期 | v0.15 | 事件跟踪 V2.0 再做 | V2.0 事件追踪 |
| ASR 语音识别 | v0.1 | 没有音频内容 | 如果采集视频/播客 |

## 五、一句话总结

> **采集系统的本质不是"爬更多"，而是"种子质量 × 多入口覆盖 × 结构压缩能力"。**
>
> 这个思想从广告素材采集到文本情报采集完全通用。
> 原始文档的 26 版迭代证明了一个道理：系统必须自进化，否则就会退化。
