# 07-角色-关注矩阵

> 版本：1.0 | 创建时间：2026-06-18 | 状态：设计中
> 定义 7 个角色的关注维度，驱动 LLM 抽取（actionAdvice）和信号路由（audienceTags）。

---

## 一、设计原则

1. **角色 ≠ 部门**：角色是「看情报时的视角」，一个人可以同时是「老板 + 战略」视角
2. **关注维度可配置**：写在 YAML 配置中，不在代码里硬编码
3. **交叉覆盖**：一条情报可能同时命中多个角色
4. **actionAdvice 按角色输出**：LLM 抽取时必须为每个命中的角色给出行动建议

---

## 二、角色定义

### 角色 1：老板（Boss）

> 关心战略级信号：什么值得做、什么有风险、钱和人的方向

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 战略信号 | 行业大势、赛道变化 | 新赛道、蓝海、红海、转型 |
| 资本动作 | 融资/并购/IPO | 融资、并购、收购、上市 |
| 爆款信号 | 超级产品出现 | 爆款、现象级、破圈 |
| 行业趋势 | 技术/平台/政策大方向 | AI、云游戏、版号收紧 |
| AI 应用 | AI 在游戏行业的落地 | AI NPC、AI 美术、AI 测试 |
| 组织变革 | 大公司的组织架构调整 | 裁员、换帅、事业部拆分 |
| 技术演进 | 引擎/平台/基建变化 | Unreal 6、Unity、跨平台 |

**audience_tag**: `老板`

---

### 角色 2：战略（Strategy）

> 关心赛道方向：去哪里、不去哪里、竞争格局怎么变

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 新赛道 | 新品类/新平台/新商业模式 | 开放世界、Roguelike、小游戏 |
| 出海 | 海外市场机会和挑战 | 日韩、东南亚、欧美、本地化 |
| 平台政策 | 渠道规则变化 | App Store 抽成、Google Play 新规 |
| 资本并购 | 行业整合信号 | 收购、合并、投资 |
| 竞争格局 | 头部产品/公司变化 | 市占率、排名、新品冲击 |

**audience_tag**: `战略`

---

### 角色 3：发行（Publisher）

> 关心产品节奏：什么时候上、怎么推、节奏对不对

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 上线 | 竞品上线时间/节奏 | 公测、正式上线、首发 |
| 测试 | 竞品测试节点 | 内测、删档、限号、技术测试 |
| 预约 | 预约量/预约节奏 | 预约破百万、预约开启 |
| 版号 | 版号下发动态 | 版号、审批、过审 |
| 渠道 | 渠道合作/分成变化 | 联运、联运比例、渠道独家 |
| 发行节奏 | 竞品的市场节奏 | 预热、定档、跳票 |
| 买量 | 竞品投放动作 | 大规模投放、素材爆量 |

**audience_tag**: `发行`

---

### 角色 4：运营（Operations）

> 关心用户侧：活跃度、留存、口碑、活动效果

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 活动 | 竞品运营活动 | 周年庆、赛季、限时活动 |
| 版本更新 | 大版本/新赛季/新角色 | 2.0 版本、新赛季、新英雄 |
| 用户反馈 | 玩家评价/投诉 | 差评、退款、评分下降 |
| 社区舆情 | 社区情绪/事件 | 玩家抗议、炎上、口碑逆转 |
| 留存 | 留存/流失信号 | DAU 下滑、流失、回流活动 |

**audience_tag**: `运营`

---

### 角色 5：广告投放（Ad/Media Buyer）

> 关心投放侧：素材趋势、投放强度、平台变化

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 买量素材 | 创意素材趋势 | 真人素材、AI 生成、UGC 风格 |
| 投放平台 | 渠道/平台变化 | 巨量引擎、腾讯广告、TikTok |
| 创意趋势 | 素材创意方向 | 剧情向、实机演示、主播带货 |
| 投放强度 | 投放量级变化 | 日均投放、加量、收缩 |

**audience_tag**: `广告投放`

---

### 角色 6：数据部（Data）

> 关心技术基建：数据怎么做、工具怎么选、效率怎么提

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 数据架构 | 数据平台/仓库建设 | 数据中台、实时数仓、ETL |
| 技术演进 | 数据技术栈更新 | ClickHouse、dbt、Airflow |
| AI 提效 | AI 在数据工作中的应用 | 自动归因、预测模型、LLM 分析 |
| 行业最佳实践 | 同行的数据方法论 | A/B 测试、用户画像、归因 |
| 数据服务 | 数据产品/工具 | BI 工具、数据报表、自助分析 |

**audience_tag**: `数据部`

---

### 角色 7：产品（Product）

> 关心产品本身：玩法、题材、美术、商业化

| 维度 | 说明 | 关键词示例 |
|------|------|-----------|
| 玩法 | 游戏机制/玩法创新 | Roguelike、开放世界、自走棋 |
| 题材 | 题材/IP/世界观 | 三国、二次元、科幻、末日 |
| 美术 | 美术风格/技术 | 卡通渲染、像素、UE5 |
| 商业化 | 付费模式/变现 | 抽卡、Battle Pass、赛季通行证 |
| 系统设计 | 系统设计/社交/养成 | 公会、赛季制、社交系统 |

**audience_tag**: `产品`

## 五、在系统中的使用方式

### 5.1 LLM 抽取时

```
Prompt 模板：

你是游戏行业情报分析师。请从以下文章中提取情报信息。

对于每个关键事实，请给出针对不同角色的行动建议：
- 老板视角：这影响什么战略决策？
- 发行视角：这影响什么发行节奏？
- 运营视角：这影响什么用户策略？
- ...（根据 audienceTags 动态生成）

参考角色-关注矩阵（role-matrix.yaml）。
```

### 5.2 信号评分时

```typescript
// 评分公式中的角色覆盖因子
const roleCoverageBonus = (
  matchedRoles: string[],   // 命中的角色数
  totalRoles: number = 7,
): number => {
  // 命中角色越多，信号越重要
  return Math.min(1.0, matchedRoles.length / 3); // 命中 3 个角色就满分
};
```

### 5.3 信号推送时

```typescript
// 根据 audienceTags 路由到对应角色的 Dashboard / 日报板块
function routeSignal(signal: Signal): RouteTarget[] {
  return signal.audienceTags.map(tag => ({
    role: tag,
    section: ROLE_SECTION_MAP[tag],  // 日报中的板块
    priority: signal.priority,
  }));
}
```

## 六、扩展机制

- 新角色：在 YAML 中增加 `roles.xxx` 即可
- 新事件类型：在 YAML 中增加 `event_type_role_relevance.xxx` 即可
- 角色权重可调：修改关联强度矩阵即可影响评分
- 不需要改代码、不需要改数据库（audienceTags 是字符串数组）
