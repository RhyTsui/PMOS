# 小乔智投进入实施阶段准入评审

## 1. 评审结论

小乔智投第三阶段设计已具备进入第四阶段工程拆解的基础，但不是所有模块都可以无条件开工。

准入结论：

- 可直接进入实施拆解：对话路由、项目权限与跨项目上下文、资产与证据沉淀。
- 可有条件进入实施拆解：问数闭环、定时报表、包交付、异常排查、指标解释、需求沟通、个人记忆、能力发现、连弩 Trace。
- 不进入一期实施：市场情报、预测、广告投放自动执行。
- 暂不进入自动化实现：自动学习规则。

## 2. 准入标准

一个模块进入实施阶段，至少满足：

1. 用户触发流程明确。
2. 项目和权限规则明确。
3. 必填 slot 与追问规则明确。
4. 真实服务边界明确。
5. 数据模型和状态字段明确。
6. 失败闭环明确。
7. 验收样本或断言明确。
8. 不依赖 Chat 伪造业务事实。

## 3. 模块准入判断

| 模块 | 准入状态 | 准入条件 |
|---|---|---|
| 对话路由 | 通过 | 实施时必须保持规则、配置、知识、工具边界分层 |
| 项目权限与跨项目上下文 | 通过 | 实施时所有工具调用必须使用有效项目上下文 |
| 资产与证据沉淀 | 通过 | 实施时不得把 Trace 当资产或证据 |
| 问数闭环 | 有条件通过 | 先冻结 MCP 返回样本、测试集归属矩阵、UI 状态契约 |
| 定时报表与自动化 | 有条件通过 | 先冻结任务状态、延迟策略、产物资产引用 |
| 包交付与联调 | 有条件通过 | 先冻结上报检查、后台更新检测、联调报告样本 |
| 异常排查 | 有条件通过 | 先冻结诊断 Workflow 返回样本和证据分类 |
| 指标解释 | 有条件通过 | 先冻结内部口径库结构化字段 |
| 需求沟通与 Case | 有条件通过 | 先冻结 Case 创建返回模型和需求类型模板 |
| 个人记忆与知识库隔离 | 有条件通过 | 先冻结个人知识库 Key 配置流程和校验反馈 |
| 能力发现与服务绑定 | 有条件通过 | 先冻结能力注册快照、健康状态、schema 版本字段 |
| 连弩 Trace | 有条件通过 | 先与连弩 SDK 对齐 TraceEnvelope 和断言字段 |
| 市场情报 | 不通过 | 二期需求未设计 |
| 预测 | 不通过 | 三期需求未设计 |
| 广告投放自动执行 | 不通过 | 四期需求未设计 |
| 自动学习规则 | 不通过 | 定义未冻结，不得按自学习 Agent 实施 |

## 4. 建议实施批次

### 4.1 第一批

目标：先打通自由对话到真实执行的最低闭环。

- 对话路由。
- 项目解析与权限。
- 能力发现与服务绑定。
- 问数闭环最小链路。
- Trace 基础发送。

第一批完成标准：

- 能正确识别问数意图。
- 能处理顶部项目与用户明示项目冲突。
- 能发现已上线 MCP。
- 能真实调用问数 MCP。
- 能解析结果并展示证据与下一步建议。
- 能发送 Trace 到连弩或记录发送失败。

### 4.2 第二批

目标：补齐用户高频业务闭环。

- 定时报表。
- 资产与证据沉淀。
- 个人记忆与知识库隔离。
- 指标解释。
- 需求沟通与 Case。

第二批完成标准：

- 自动化产物默认进入资产。
- 即时查询结果由用户保存后进入资产。
- 权限变化后历史会话和资产按项目动态过滤。
- 指标解释优先内部口径库。
- 需求沟通能追问、确认、创建真实 Case。

### 4.3 第三批

目标：补齐复杂 Workflow 场景。

- 包交付与联调。
- 异常排查。
- 失败 Case 复盘。

第三批完成标准：

- 包交付状态由真实上报检查、后台更新检测、联调结果派生。
- 上报检查未通过不提示提审或更新。
- 联调失败自动生成 Case。
- 异常排查没有证据时只输出假设，不输出确定结论。

## 5. 实施阶段风险

| 风险 | 等级 | 处理原则 |
|---|---|---|
| MCP 已上线但能力发现未命中 | P0 | 先做能力发现快照和绑定校验 |
| 项目解析仍使用顶部项目兜底 | P0 | 明示项目优先，无权限阻断，不回退 |
| 问数只验证 MCP 不验证 UI 闭环 | P0 | 验收必须包含渲染、证据、建议 |
| 包状态由 Chat 生成 | P0 | 状态和结论必须由 Workflow / MCP 派生 |
| 个人记忆仍写入默认知识库 Key | P0 | 用户个人 Key 缺失时不得写入个人记忆 |
| Trace 与连弩字段不一致 | P1 | 先冻结字段映射，再扩大评测 |
| 资产未按最新权限过滤 | P0 | 读取时按最新项目权限过滤 |

## 6. 进入第四阶段前置清单

进入工程实施清单前，需确认：

- 问数 MCP 返回样本库已补齐。
- 包交付三个关键服务样本已补齐。
- 连弩 SDK 字段映射已确认。
- 个人知识库 Key 配置流程已确认。
- 资产和证据脱敏规则已确认。
- Case 创建服务返回模型已确认。

若这些前置项未完全补齐，仍可启动第一批最小闭环，但不得把未冻结契约的模块标记为已完成。
