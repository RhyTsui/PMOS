# 个人记忆与知识库用户隔离系统设计

## 1. 对应需求

本设计对应：

- `docs/prd-v2.2/19-个人记忆与知识库用户隔离需求设计.md`
- `docs/prd-v2.2/18-意图路由知识库与能力闭环设计准入评估.md`
- `docs/prd-v2.2/20-对话路由需求PRD.md`
- `docs/design-v1/01-对话路由系统设计.md`
- `docs/design-v1/02-项目权限与跨项目上下文系统设计.md`

本文解决的是多用户场景下的记忆和知识库隔离问题。系统不能继续把个人记忆写到默认用户、固定知识库或全局知识库 Key 下，也不能把个人记忆、通用知识库、个人知识库和业务资产混成同一个对象。

## 2. 设计目标

个人记忆与知识库的目标不是做一个新的知识库平台，而是在小乔 Chat 中提供可验证的用户级记忆闭环：

- 个人记忆按登录用户隔离。
- 通用知识库由超管配置，普通用户只读检索。
- 个人知识库由用户自己配置 Key，只服务本人记忆同步和个人 RAG。
- 保存到个人知识库必须真实写入记录，并返回同步状态。
- 未配置个人 Key 时允许保存本地个人记忆，但不能宣称已同步知识库。
- RAG 来源必须可区分、可追溯、可展示。
- 个人记忆不能覆盖项目权限、内部工具结果、指标口径库或包交付状态。

## 3. 当前实现核对

当前已有基础：

- `user-scope.ts` 已能从登录态解析 `user_scope_key`。
- `user-memory-store.ts` 已有本地记忆存储、列表、搜索、归档和同步状态字段。
- `/api/xiaoqiao/memory` 已有创建、查询和同步调用基础。
- `dataki-memory-sync.ts` 已能把记忆同步到 Dataki 知识库。
- `runtime-config.ts` 已有全局模型与知识库服务配置。
- `ChatContainer.tsx` 已经有真实保存和取消入口：保存时调用 `POST /api/xiaoqiao/memory`，取消时调用 `DELETE /api/xiaoqiao/memory/{id}`。
- `MemoryPanel` 已有记忆列表、搜索、新增、归档和删除交互基础。

当前风险：

- `user-memory-store.ts` 仍有 `DEFAULT_USER_ID = 'user-001'` 兜底。
- `useConversation.ts` 仍有 `MEMORY_USER_ID = 'user-001'`，Debug 记忆会串到默认用户。
- `/api/xiaoqiao/memory` 仍读取 query/body 中的 `user_id`，没有把登录态解析出的 `user_scope_key` 作为唯一隔离依据。
- `dataki-memory-sync.ts` 仍有固定知识库名称 `小乔智投-徐韵-记忆库` 和默认用户。
- 个人知识库 Key 仍未形成用户级配置，当前知识库配置主要是系统全局配置。
- 记忆同步默认走全局 Dataki 配置，可能把个人记忆写入系统通用知识库。
- RAG 来源还没有统一的 `RagSourceRef`，通用知识、个人记忆、个人知识库和工具结果容易混淆。

## 4. 核心产品规则

### 4.1 四类对象边界

| 对象 | 作用 | 权限 | 写入方 | 是否资产 |
|---|---|---|---|---|
| 通用知识库 | SOP、业务口径、受控知识、组织共识 | 全员可读 | 超管 / 管理员 | 否 |
| 个人知识库 | 用户保存内容、个人经验、个人工作笔记 | 仅本人 | 本人 / 系统代本人同步 | 否 |
| 个人记忆 | 多轮上下文、偏好、确认字段、未完成任务线索 | 仅本人 | 本人 / 系统抽取 | 否 |
| 我的资产 | 报表、定时报表结果、包交付记录、Case、证据包 | 按项目动态过滤 | Workflow / 用户保存 / 自动化 | 是 |

### 4.2 写入规则

- 个人记忆只能写到当前登录用户的 `user_scope_key`。
- 普通用户不能写系统通用知识库。
- 系统通用知识库 Key 不能作为个人记忆同步目标。
- 用户未配置个人知识库 Key 时，只保存本地个人记忆，状态为 `pending_config` 或 `skipped_no_config`。
- 用户配置个人知识库 Key 后，后续记忆可同步到个人知识库，历史待同步记忆可手动补同步。

### 4.3 读取规则

- 通用知识库可参与业务知识、SOP、术语和口径补充。
- 个人记忆可参与低风险上下文继承，例如常用媒体、常用维度、报表格式偏好。
- 个人知识库可参与用户主动保存内容的检索。
- 项目数据、包状态、联调结果、上报检查结果必须走内部工具，不能由知识库召回直接回答。
- 个人记忆中的项目上下文只能作为低置信度继承信号，最终项目仍必须经过 `ProjectResolution` 和权限校验。

### 4.4 冲突优先级

冲突处理按来源类型决定，不做简单“内部优先”或“外部优先”：

- 项目权限冲突：权限系统优先。
- 项目数据冲突：内部 MCP / Workflow 工具结果优先。
- 指标口径冲突：内部口径库和受控知识优先，外部来源只补充。
- 用户个人偏好冲突：用户最新明确确认优先，其次个人记忆。
- 个人记忆与公司事实冲突：个人记忆不能覆盖公司事实。

## 5. 系统流程

### 5.1 保存消息到个人知识库

1. 用户点击消息上的保存入口。
2. 前端发送消息内容、会话 ID、消息 ID、来源类型和可选关键词。
3. 后端从登录态解析 `UserScope`，生成 `user_scope_key`。
4. 后端忽略前端传入的任意隔离用 `user_id`，只使用 `user_scope_key`。
5. 后端创建 `PersonalMemoryRecord`。
6. 后端读取 `UserKnowledgeConfig`。
7. 未配置个人知识库：记录为待同步，返回真实状态。
8. 已配置但测试失败：记录为同步失败，返回失败原因。
9. 已配置且可用：调用 Dataki / 知识库服务写入个人知识库。
10. 前端按返回状态展示已同步、待配置、同步失败或取消成功。

### 5.2 取消保存

1. 前端携带已保存的 `memory_id` 调用删除接口。
2. 后端校验该记忆属于当前 `user_scope_key`。
3. 本地记录删除或归档。
4. 一期不默认删除远端个人知识库文档，只停止本地引用；如远端支持删除，后续作为 P1 增强。
5. 前端取消高亮，并展示真实处理结果。

### 5.3 手动同步我的记忆

1. 用户在右下角知识库弹窗点击“同步我的记忆”。
2. 后端解析当前用户。
3. 后端筛选当前用户未归档、未同步或同步失败的记忆。
4. 后端读取当前用户个人知识库配置。
5. 无配置时返回 `skipped_no_config`。
6. 配置无效时返回 `failed` 和错误。
7. 配置有效时按日期或批次生成个人知识库文档。
8. 写入成功后更新每条记忆的 `sync_status`、`document_id`、`synced_at`。

### 5.4 Chat 上下文编译

1. Route Engine 接收用户消息。
2. Context Compiler 解析登录用户、角色、项目、页面和会话上下文。
3. 只检索当前 `user_scope_key` 的个人记忆。
4. 根据问题类型决定是否检索通用知识库或个人知识库。
5. 所有召回内容统一进入 `RagSourceRef`。
6. Route Decision 和最终回答必须保留来源类型。
7. 工具请求仍必须经过能力发现、权限校验和项目解析。

## 6. 前端职责

前端负责：

- 在右下角弹窗增加“知识库”入口。
- 展示通用知识库状态，但不展示超管 Key。
- 展示个人知识库配置状态、最近测试时间、最近同步时间和失败原因。
- 支持个人知识库 Key 填写、保存、测试、清除。
- 支持知识库平台跳转地址。
- 支持“同步我的记忆”。
- 保存消息时只在 API 成功后高亮。
- 同步失败或未配置 Key 时展示真实状态，而不是只显示保存成功。
- 取消保存时调用删除接口，成功后取消高亮。

前端禁止：

- 把本地高亮当成保存成功。
- 自行生成或信任隔离用 `user_id`。
- 展示明文个人知识库 Key。
- 把个人记忆显示为公司知识或业务工具结果。
- 把个人知识库同步失败隐藏成成功。

## 7. 后端职责

后端负责：

- 从登录态解析 `UserScope`。
- 生成并使用 `user_scope_key`。
- 保存、搜索、更新、删除记忆时强制按 `user_scope_key` 过滤。
- 保存用户级知识库配置，并对 Key 做安全存储和脱敏返回。
- 测试个人知识库连接。
- 调用 Dataki / 知识库服务同步个人记忆。
- 区分系统通用知识库配置和用户个人知识库配置。
- 生成 RAG 来源引用。
- 写入 Trace 和 Evidence 事件。

后端禁止：

- 用 `user-001` 作为普通用户默认隔离值。
- 信任请求体或 query 中的 `user_id`。
- 用系统通用知识库 Key 写入个人记忆。
- 用固定个人知识库名称写入所有用户记忆。
- 在个人知识库配置不存在时静默回退到通用知识库。
- 让用户读取或删除其他用户的记忆。

## 8. Workflow / Skill / MCP 边界

### 8.1 Chat

Chat 负责：

- 保存入口。
- 上下文编译。
- RAG 来源编排。
- 来源展示。
- 追问和结果表达。

Chat 不负责：

- 伪造知识库同步成功。
- 用知识库召回替代业务工具执行。
- 绕过用户隔离直接读写记忆。

### 8.2 Skill

Skill 可以提供：

- 受控术语归一化。
- 指标解释。
- 个人记忆摘要抽取。
- RAG 召回结果重排。

Skill 必须返回结构化来源，不得直接输出不可追溯结论。

### 8.3 MCP / 知识库服务

MCP / Dataki / 知识库服务负责：

- 知识库列表查询。
- 知识库连接测试。
- 文档创建或更新。
- 文档检索。

知识库服务不负责小乔的用户权限判断。小乔必须在调用前完成用户隔离和权限校验。

## 10. API / 事件 / Trace 契约

### 10.1 API

```ts
GET /api/xiaoqiao/user/knowledge-config
PUT /api/xiaoqiao/user/knowledge-config
POST /api/xiaoqiao/user/knowledge-config/test
DELETE /api/xiaoqiao/user/knowledge-config

GET /api/xiaoqiao/memory
POST /api/xiaoqiao/memory
GET /api/xiaoqiao/memory/search
DELETE /api/xiaoqiao/memory/{id}
POST /api/xiaoqiao/memory/sync
POST /api/xiaoqiao/memory/{id}/sync
```

约束：

- 用户级接口必须从请求登录态解析 `user_scope_key`。
- 管理端如需查看用户记忆状态，必须走单独管理权限接口。
- `POST /memory` 的请求体可以带来源信息，但不能决定记忆归属用户。
- `GET /memory/search` 只返回当前用户记忆。
- `DELETE /memory/{id}` 必须校验归属。

### 10.2 Trace

每次保存、检索和同步必须记录：

- `user_scope_key`
- `memory_id`
- `memory_type`
- `source`
- `source_conversation_id`
- `source_message_id`
- `sync_status`
- `knowledge_base_id`
- `document_id`
- `rag_source_type`
- `operation`
- `result_status`
- `error_code`
- `error_message`

### 10.3 Evidence

个人记忆不是业务 Evidence。只有当个人记忆被用于解释“为什么系统沿用了某个偏好或上下文”时，才作为来源引用展示。

业务 Evidence 仍来自工具结果、Workflow 结果、Case、Trace 和资产。

## 11. Prompt 与配置边界

写进代码：

- 用户隔离解析。
- 记忆归属校验。
- 通用知识库和个人知识库的写入边界。
- 同步状态机。
- 来源类型枚举。
- 禁止个人记忆覆盖业务工具结果的优先级规则。

写进配置：

- 通用知识库地址和系统 Key。
- 用户个人知识库连接配置。
- 受控术语词典来源。
- 记忆类型、重要度默认值、同步批量大小。
- RAG 来源启停策略。

写进 Prompt：

- 个人记忆摘要抽取 JSON。
- RAG 来源解释表达。
- 低风险上下文继承说明。
- 追问文案。

Prompt 禁止：

- 生成用户隔离字段。
- 伪造知识库同步结果。
- 把个人记忆写成公司事实。
- 根据知识库召回生成内部数据、包状态、联调结果或上报检查结论。

## 12. 失败闭环

### 12.1 未登录或无法解析用户

不保存个人记忆，不检索个人记忆。提示用户当前无法识别登录身份。

### 12.2 未配置个人知识库 Key

本地个人记忆保存成功，状态为 `skipped_no_config` 或 `pending_config`。提示用户可在右下角知识库入口配置后同步。

### 12.3 个人 Key 无效

记忆保存成功，同步失败，返回失败原因。不能回退写入通用知识库。

### 12.4 知识库服务不可用

记忆保存成功，同步状态为 `failed`，记录错误。用户可稍后手动同步。

### 12.5 记忆归属不匹配

拒绝读取、删除或同步，返回无权限。不能暴露该记忆是否属于哪个用户。

### 12.6 历史 `user-001` 记忆

默认标记为 legacy，不进入普通用户检索。能识别真实用户时迁移到对应 `user_scope_key`；无法识别时仅允许超管审计。

## 13. 验收场景

- 用户 A 保存消息，用户 B 搜索不到该记忆。
- 用户 A 删除自己的保存，前端星标取消，用户 B 不受影响。
- 前端传入 `user_id=user-001`，后端仍保存到当前登录用户。
- 未配置个人知识库 Key 时，保存成功但状态不是 `synced`。
- 配置错误个人 Key 时，测试失败，通用知识库检索不受影响。
- 配置正确个人 Key 后，待同步记忆可以补同步。
- 个人记忆同步时不会使用系统通用知识库 Key。
- 固定 `小乔智投-徐韵-记忆库` 不再作为所有用户同步目标。
- 通用知识库可被普通用户检索，但普通用户不能写入。
- 指标口径解释优先引用内部口径库，不被个人记忆覆盖。
- 用户问项目数据时，个人记忆只能提供低置信度上下文，最终请求项目仍由 `ProjectResolution` 决定。
- 包状态、联调结果、上报检查结论不会由个人知识库召回生成。
- RAG 回答展示 `personal_memory`、`personal_knowledge`、`system_common_knowledge` 或 `tool_result` 来源类型。
- 历史 `user-001` 记忆不会默认暴露给所有用户。

## 14. 工程实施映射

P0：

- 移除个人记忆主链路中的 `user-001` 默认用户。
- `/api/xiaoqiao/memory`、`search`、`sync`、`delete` 强制从登录态解析 `user_scope_key`。
- 新增用户级知识库配置存储和接口。
- `dataki-memory-sync` 改为按用户个人知识库配置同步。
- 通用知识库配置只用于全员只读检索，不参与个人记忆写入。
- Chat 保存入口按真实 `sync_status` 展示。
- RAG 来源增加 `RagSourceRef`。
- Trace 增加保存、搜索、同步和来源引用事件。

P1：

- 右下角知识库弹窗完整配置体验。
- 待同步记忆批量补同步。
- 个人记忆列表展示同步状态和失败原因。
- 个人记忆参与 Route / Context Compiler 的低风险上下文继承。
- Legacy `user-001` 记忆迁移或审计工具。
- 个人 RAG 命中率、减少追问次数、同步成功率等指标。

后续：

- 自动记忆抽取策略优化。
- 记忆冲突处理和用户纠错。
- 个人知识库容量、过期、清理和远端删除策略。
