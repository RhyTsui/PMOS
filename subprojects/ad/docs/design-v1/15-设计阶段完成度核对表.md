# 小乔智投设计阶段完成度核对表

## 1. 核对口径

每个需求模块按以下维度核对：

- 流程：是否定义用户触发、系统判断、执行、反馈和闭环。
- 状态机：是否存在明确状态或说明无需状态机。
- 数据模型：是否有关键对象、字段和权限字段。
- 接口契约：是否定义输入、输出、错误、证据引用。
- 前后端职责：是否明确 Chat、前端、后端、服务层分工。
- MCP / Workflow 边界：是否避免 Chat 写假功能。
- 失败闭环：是否定义追问、阻断、Case、下一步建议。
- 验收规则：是否能证明真实可用。

状态定义：

- `充分`：可进入实施拆解。
- `有条件充分`：主设计成立，但实施前需补字段样本或外部契约。
- `不足`：当前不应进入实施。
- `后续期`：不属于一期实施范围。

## 3. 一期可进入实施的范围

一期可以进入实施拆解的模块：

- 对话路由。
- 项目权限与跨项目上下文。
- 个人记忆与知识库隔离。
- 问数闭环。
- 定时报表与自动化任务。
- 包交付与联调。
- 异常排查。
- 指标解释。
- 需求沟通与 Case。
- 能力发现与服务绑定。
- 资产与证据沉淀。
- 连弩 Trace 评测接入。

其中“有条件充分”的模块不是不能实施，而是实施前必须冻结对应服务返回样本、字段枚举或 SDK 契约。

## 4. 不进入一期实施的范围

- 市场情报：二期能力，当前只保留融合回答策略方向。
- 预测：三期能力，当前不进入工程拆解。
- 广告投放自动执行：四期能力，当前不进入工程拆解。
- 自动学习规则：当前只接受“规则沉淀、Case 沉淀、评测样本沉淀”的方向，不能设计成裸 Agent 自学习。
