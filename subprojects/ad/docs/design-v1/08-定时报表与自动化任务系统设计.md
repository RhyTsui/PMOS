# 定时报表与自动化任务系统设计

## 1. 文档目的

本文定义小乔智投一期的定时报表与自动化任务设计，承接：

- `docs/prd-v2.2/06-数据查询报表与定时报表PRD.md`
- `docs/prd-v2.2/09-我的资产与自动化任务中心PRD.md`
- `docs/design-v1/04-数据查询与报表系统设计.md`
- `docs/design-v1/07-问数编排与结果呈现系统设计.md`

本文重点解决：

- 用户如何从一次问数结果进入定时报表。
- 用户如何单独创建、查看、编辑、停用定时任务。
- 自动化任务如何绑定项目、权限和资产。
- 定时报表创建时如何确认数据延迟策略。
- 自动化产物如何进入我的资产。
- 定时任务如何复用未来的 Skill / Workflow。

## 2. 设计目标

定时报表不是简单的 cron，而是“可追溯、可复用、可权限过滤的自动化产物生成机制”。

目标：

- 用户可以从问数结果中创建定时报表。
- 用户可以在自动化任务中心单独创建和管理定时报表。
- 定时报表创建时必须确认数据延迟策略。
- 自动化任务产物默认写入我的资产。
- 报表模板可以跨项目复用，但任务运行时必须绑定项目和权限。
- 自动化任务和会话一样可以支持多项目，但一期主要服务仍以单项目为主。
- 自动化任务的历史产物、资产、Trace 都要按用户动态项目权限过滤。

## 3. 当前规则确认

已确认产品规则：

- 查询结果只有用户保存后才写入资产。
- 自动化任务生产的产物默认进入资产。
- 报表草稿默认不保存。
- 定时报表创建时必须确认数据延迟策略。
- 报表模板可以跨项目复用。
- 自动化任务绑定项目，处理方式与会话类似，可以多项目。
- 当前不按项目隔离展示会话和资产，但展示时必须根据项目权限动态过滤。
- 我的资产、自动化新增和编辑都要增加项目字段、项目查看和筛选。
- Trace 在连弩平台可以完整回放，小乔侧保留必要 trace id 和证据引用。

## 4. 核心概念

### 4.1 ReportTemplate

报表模板描述“报表长什么样”，不是某次运行结果。

模板可以包含：

- 指标集合。
- 维度集合。
- 默认筛选。
- 相对时间窗口。
- 展示结构。
- 图表偏好。
- 口径说明要求。
- 数据源要求。

模板可以跨项目复用，但不能绕过运行时项目权限。

### 4.2 ScheduledReportTask

定时报表任务描述“什么时候、对哪些项目、按哪个模板或查询配置运行”。

任务必须包含：

- 项目绑定。
- 执行频率。
- 执行时间。
- 数据延迟策略。
- 报表模板或查询配置。
- 创建人。
- 任务状态。
- 失败处理策略。

### 4.3 ReportAsset

定时报表每次执行成功后生成正式资产。

资产必须包含：

- 任务 id。
- 模板 id 或查询配置。
- 项目绑定。
- 执行时间。
- 数据窗口。
- 数据延迟策略。
- 结果摘要。
- Evidence。
- Trace id。

## 5. 创建入口

### 5.1 从问数结果创建

触发方式：

- 用户点击“创建定时报表”。
- 用户说“以后每天生成这个报表”。
- 用户说“每天早上发一下这个结果”。
- 用户说“定时获取这个数据”。

流程：

1. 系统读取当前 `ReportQueryPlan` 和 `ReportQueryResult`。
2. 提取项目、指标、维度、筛选、时间窗口、展示结构。
3. 生成定时报表候选配置。
4. 追问或确认频率、执行时间、数据延迟策略。
5. 用户确认后创建 `ScheduledReportTask`。
6. 任务进入自动化任务中心。
7. 后续执行产物默认进入我的资产。

### 5.2 从自动化任务中心创建

用户可以直接进入自动化任务中心创建：

1. 选择任务类型：定时报表。
2. 选择项目。
3. 选择报表模板或新建查询配置。
4. 配置频率和执行时间。
5. 确认数据延迟策略。
6. 选择失败通知和产物归档规则。
7. 保存任务。

### 5.3 从报表模板创建

用户可以从模板创建任务：

1. 选择模板。
2. 选择运行项目。
3. 填充模板需要的筛选字段。
4. 确认数据延迟策略。
5. 创建任务。

## 6. 数据延迟策略

### 6.1 为什么必须确认

广告数据存在延迟、回流、修正和口径刷新。定时报表如果不确认数据延迟策略，会产生“每天自动生成但数据不稳定”的问题。

因此创建定时报表时必须确认：

- 报表统计哪一天或哪段时间。
- 在什么时候执行。
- 数据延迟多久后认为可用。
- 失败或数据未就绪时如何处理。

### 6.2 策略模型

```ts
type DataDelayPolicy = {
  policy_id: string
  mode: 'fixed_delay' | 'data_ready_check' | 'manual_confirm'
  delay_hours?: number
  data_window_offset_days: number
  retry_policy: {
    max_retries: number
    retry_interval_minutes: number
  }
  on_not_ready: 'skip' | 'retry' | 'generate_with_warning' | 'create_case'
  user_confirmed_at: string
}
```

### 6.3 推荐策略

一期推荐：

- 默认 `fixed_delay`。
- 默认查询 T-1 数据。
- 默认在每天固定时间执行。
- 如果数据未就绪，先重试；多次失败后生成失败记录，不生成正常报表资产。

可选策略：

- `data_ready_check`：后续接入数据就绪检查 MCP / Workflow。
- `manual_confirm`：高风险报表需要人工确认后生成。

## 7. 项目与权限

### 7.1 项目绑定

任务必须绑定项目：

```ts
type TaskProjectBinding = {
  project_refs: string[]
  project_mode: 'single' | 'multi'
  created_with_project_refs: string[]
}
```

规则：

- 包交付类任务必须单项目。
- 定时报表可以多项目，但一期默认鼓励单项目。
- 多项目任务运行时必须分别校验项目权限和数据范围。
- 用户权限变化后，任务仍保留，但不可见项目产物不展示。

### 7.2 权限变化处理

权限变化影响：

- 自动化任务列表展示。
- 任务详情展示。
- 历史产物资产展示。
- Trace 证据展示。

规则：

- 如果用户失去某项目权限，任务中该项目相关数据不可见。
- 多项目任务中仍有可见项目时，展示可见部分，并提示部分项目不可见。
- 完全无可见项目时，任务在列表中可隐藏或显示为无权限摘要，具体由后台权限策略决定。
- 不删除历史数据，只按项目权限动态过滤展示。

## 8. 状态机

### 8.1 任务状态

```ts
type ScheduledTaskStatus =
  | 'draft'
  | 'active'
  | 'paused'
  | 'running'
  | 'failed'
  | 'disabled'
  | 'archived'
```

状态说明：

- `draft`：配置未完成，不调度。
- `active`：已启用，等待调度。
- `paused`：用户暂停。
- `running`：当前有执行实例。
- `failed`：最近一次执行失败，但任务未必停用。
- `disabled`：系统禁用，例如权限或配置不可用。
- `archived`：归档，不再执行。

### 8.2 执行实例状态

```ts
type ScheduledTaskRunStatus =
  | 'scheduled'
  | 'checking_data_ready'
  | 'running'
  | 'success'
  | 'partial_success'
  | 'empty'
  | 'failed'
  | 'skipped'
  | 'case_created'
```

状态说明：

- `scheduled`：已进入调度队列。
- `checking_data_ready`：检查数据是否就绪。
- `running`：正在执行查询或报表生成。
- `success`：产物生成成功并进入资产。
- `partial_success`：多项目或多子查询部分成功。
- `empty`：执行成功但没有数据。
- `failed`：执行失败。
- `skipped`：按策略跳过。
- `case_created`：失败已沉淀 Case。

## 9. 执行流程

### 9.1 调度触发

1. Scheduler 扫描 active 任务。
2. 判断是否到执行时间。
3. 创建 `ScheduledTaskRun`。
4. 根据数据延迟策略判断数据窗口。
5. 检查项目权限和任务配置。
6. 调用问数编排链路或报表 Workflow。
7. 生成结果。
8. 写入资产。
9. 写入 Trace 和执行记录。

### 9.2 调用问数链路

定时报表复用问数编排链路，但输入不是用户自然语言，而是结构化查询配置：

```ts
type ScheduledReportQueryInput = {
  task_id: string
  run_id: string
  project_refs: string[]
  report_template_id?: string
  report_query_plan?: ReportQueryPlan
  metrics: string[]
  dimensions: string[]
  filters: Record<string, unknown>
  date_window: DateWindow
  data_delay_policy: DataDelayPolicy
}
```

复用点：

- Manifest 能力发现。
- 字典解析。
- MCP 调用。
- 结果解析。
- 质量检查。
- Trace。
- Evidence。

不同点：

- 不需要自然语言追问。
- 缺关键配置时直接标记任务配置失败。
- 执行产物默认入资产。

## 10. 产物入资产

自动化任务生产的结果默认进入资产。

资产规则：

- 每次成功 run 生成一个资产。
- `partial_success` 可生成资产，但必须标记部分失败。
- `empty` 是否生成资产由策略决定；默认生成执行记录，不生成正式报表资产。
- `failed` 不生成报表资产，但生成失败记录或 Case。

资产字段：

```ts
type ScheduledReportAsset = {
  asset_id: string
  asset_type: 'scheduled_report_result'
  task_id: string
  run_id: string
  template_id?: string
  project_binding: TaskProjectBinding
  data_window: DateWindow
  data_delay_policy: DataDelayPolicy
  result_snapshot: {
    row_count: number
    columns: string[]
    summary?: string
    sample_rows?: Array<Record<string, unknown>>
  }
  evidence_refs: string[]
  trace_id: string
  created_at: string
}
```

## 13. Workflow / Skill / MCP 边界

Chat 负责：

- 从对话中识别创建定时报表意图。
- 提取当前问数结果。
- 引导用户确认频率、执行时间、数据延迟策略。
- 展示创建结果。

Workflow 负责：

- 定时报表创建流程。
- 调度执行。
- 多步骤报表生成。
- 失败重试和 Case 创建。

MCP / Skill 负责：

- 真实数据查询。
- 字典解析。
- 数据就绪检查。
- 后续通知能力。

资产服务负责：

- 自动化产物入资产。
- 项目权限动态过滤。
- 资产归档。

## 15. 失败闭环

### 15.1 失败类型

- 任务配置不完整。
- 项目权限失效。
- 数据未就绪。
- MCP 不可用。
- 字典解析失败。
- 报表返回为空。
- 结果解析失败。
- 资产写入失败。

### 15.2 处理策略

| 失败类型 | 处理 |
|---|---|
| 配置不完整 | 任务置为 failed，提示用户编辑 |
| 项目权限失效 | 跳过无权限项目；完全无权限则 disabled |
| 数据未就绪 | 按策略重试、跳过或生成 warning |
| MCP 不可用 | 重试，多次失败生成 Case |
| 字典解析失败 | 任务 failed，要求修正 alias / 筛选 |
| 空结果 | 记录 empty，按策略决定是否生成资产 |
| 解析失败 | 生成 Case，保留原始返回摘要 |
| 资产写入失败 | 结果保留为 run 记录，不展示为已入资产 |

## 16. 验收场景

P0：

- 从问数结果创建每日定时报表，必须确认数据延迟策略。
- 自动化任务执行成功后，产物默认进入我的资产。
- 查询结果未保存时，不进入我的资产。
- 报表草稿默认不保存。
- 任务绑定项目，任务列表支持项目筛选。
- 用户失去项目权限后，看不到该项目任务产物。
- 任务执行失败时，不生成正常报表资产。
- MCP 失败时生成失败记录，必要时生成 Case。

P1：

- 模板跨项目复用，运行时重新校验项目权限。
- 多项目任务部分成功。
- 任务立即运行。
- 历史 run 查看。
- Trace 跳转连弩回放。

P2：

- 数据就绪检查 MCP。
- 小闪通知。
- 定时触发任意 Skill / Workflow。
- 失败智能重试策略。
