# 问数闭环与测试集验收细化设计

> 主文档：`07-问数编排与结果呈现系统设计.md`、`04A-MCP能力发现与问数归属矩阵.md`。
> 本文只细化问数闭环、MCP 能力映射、slot 补参、字典解析、真实调用、结果渲染、下一步建议和验收分层。暂不展开资产沉淀系统和连弩 Trace。

## 1. 细化目标

问数是小乔智投一期最基础服务。MCP 本身已有上线基础，当前工程重点不是“补一个 MCP”，而是让 Chat 稳定完成：

1. 正确识别问数意图和报表域。
2. 把用户自然语言补成 MCP 可执行入参。
3. 调用真实字典和报表 MCP。
4. 正确解析结果。
5. 用表格、图表、质量状态和下一步建议展示。
6. 失败时能区分问题所在，不用成功口吻兜底。

## 2. 测试集反推的责任归属

问数测试集每条用例必须先归属到责任层，禁止默认判定为 MCP 缺失。

| 测试集诉求 | 首要归属 | Chat 侧工作 |
|---|---|---|
| 日报、周报、月报 | `mcp_native + chat_mapping_required` | 选择 day report，映射 `timeType` |
| 小时报表、实时、截至某小时 | `mcp_native + chat_mapping_required` | 选择 hour report，映射小时口径 |
| ROI、回收、回本、累计 ROI | `mcp_native + chat_mapping_required` | 选择 ROI report，确认 `dataType` |
| 留存、次留、注册留存 | `mcp_native + chat_mapping_required` | 选择 retention report，确认 `retentionType` |
| 素材、创意、素材标签 | `mcp_native + chat_mapping_required` | 选择 material report，解析素材维度 |
| 媒体、终端、团队、账户、包体、优化师 | `mcp_native + dictionary_required` | 先调字典 tool，回填 ID |
| TopN、最高、最低、排序 | `orchestrator_postprocess` | 基于真实 rows 排序 |
| 环比、差值、占比 | `orchestrator_postprocess` | 基于真实 rows 和基准期计算 |
| 总计与明细核对 | `orchestrator_postprocess` | 多次查询或基于明细汇总校验 |
| 表格、图表、来源、建议 | `ui_required` | 渲染结构化结果和状态建议 |
| 空结果、权限失败、tool 失败 | `failure_closure` | 区分失败类型并给下一步 |

## 3. 报表域路由

`report_query` 必须细分到可执行报表域。

```ts
type ReportQuestionType =
  | 'ad_daily_report'
  | 'ad_hour_report'
  | 'ad_roi_report'
  | 'ad_retention_report'
  | 'ad_material_report'
  | 'ad_dictionary_lookup'
  | 'report_diagnosis_candidate'
```

路由规则：

- “消耗、激活、注册、付费、成本、收入、媒体拆分”优先 `ad_daily_report`。
- “小时、实时、截至 X 点、分时段”优先 `ad_hour_report`。
- “ROI、回收、回本、累计 ROI、区间 ROI”优先 `ad_roi_report`。
- “留存、次留、D1/D7、注册留存、设备留存”优先 `ad_retention_report`。
- “素材、创意、素材标签、制作人、上传人”优先 `ad_material_report`。
- “为什么下降、异常、对不上、没数据”在查数后生成诊断候选，不直接跳过问数。

## 4. Slot 补参

### 4.1 项目

MCP 通常需要 `appId`。用户可能说项目名、游戏名、应用名、简称或 appId。

规则：

- 用户明示项目优先于顶部项目。
- 明示项目无权限时阻断，不回退顶部项目。
- 多候选时追问。
- 包含多个项目时，只有支持多项目的查询才执行，否则拆分或追问。

### 4.2 日期

必须解析成明确字段：

```ts
type DateSlot = {
  startDate: string
  endDate: string
  timeType: 'DAY' | 'NATURAL_WEEK' | 'NATURAL_MONTH' | 'HOURLY'
  dh?: number | number[]
  raw: string
}
```

规则：

- “昨天、近 7 天、本月、上周、二月”必须转成绝对日期。
- 无效日期阻断执行。
- 用户没给时间时可以追问；如果产品配置允许默认时间，也必须在回答中显式说明。

### 4.3 指标和口径

| 用户表达 | 处理 |
|---|---|
| ROI / 回收 | 选择 ROI 报表 |
| 累计 ROI | `dataType` 映射累计口径 |
| 区间 ROI | `dataType` 映射区间口径 |
| 留存 | 未明确类型时追问 |
| 次留 / D1 | 映射留存窗口 |
| 注册留存 / 设备留存 | 映射 `retentionType` |
| 自然量 / 广告量 | 映射 `promotionSource` |

### 4.4 维度和筛选

维度类表达：

- 按媒体拆。
- 按团队拆。
- 按应用类型拆。
- 媒体 + 团队。
- 分素材。

筛选类表达：

- 只看巨量。
- 只看安卓。
- 某团队。
- 某账户。
- 某包体。
- 某优化师。

规则：

- 维度映射 `subGroup` 或 tool 支持的分组字段。
- 筛选必须通过字典解析成 ID。
- 不确定是维度还是筛选时，优先追问。

## 5. 字典解析

字典解析链路：

```text
alias 命中
-> 检查项目/appId
-> 调用对应字典 MCP
-> 解析候选
-> 唯一命中则回填 ID
-> 多候选/空结果则追问
```

字典映射：

| Slot | 字典能力 | 回填字段 |
|---|---|---|
| 媒体 | `get_dict_zt_all_media` / `get_dict_zt_media` | `mediaId` |
| 终端 | `get_dict_zt_rpt_os_type_v2` | `osTypes` |
| 团队 | `get_dict_zt_label_team` | `teamIds` |
| 应用类型 | `get_dict_zt_app_package_type` | `appPackageType` |
| 账户 | `get_dict_zt_account` | `accountId` |
| 包体 | `get_dict_zt_rpt_package` | `pkgId` |
| 优化师 | `get_dict_zt_optimizer` | `optimizerIds` |

禁止：

- 把“巨量”“安卓”“某团队”直接塞进报表 tool。
- 未命中 alias 时扫描所有中文词并猜测筛选项。
- 字典空结果时继续调用报表 tool。
- 字典 tool 缺失时输出成功结果。

## 6. MCP 入参构造

入参构造必须读取 tool schema，只传 schema 支持的字段。

基础字段：

```ts
type ReportToolInputBase = {
  appId: string | number
  startDate: string
  endDate: string
  promotionSource?: string
  timeType?: string
}
```

默认值边界：

| 字段 | 可默认 | 说明 |
|---|---|---|
| `promotionSource` | 可 | 默认广告量，但回答要说明 |
| `timeType` | 可 | 根据问题映射日/周/月/小时 |
| `appId` | 不可 | 必须来自项目解析 |
| `mediaId` | 不可 | 必须来自字典 |
| `dataType` | 条件可 | 语义明确才填 |
| `retentionType` | 条件可 | 留存类型明确才填 |

## 7. 执行与结果解析

执行状态：

```ts
type ReportExecutionStatus =
  | 'success'
  | 'partial_success'
  | 'empty'
  | 'missing_input'
  | 'dictionary_unmatched'
  | 'permission_denied'
  | 'tool_failed'
  | 'parse_failed'
  | 'not_configured'
```

结果解析必须输出：

```ts
type ReportQueryResult = {
  status: ReportExecutionStatus
  question_type: ReportQuestionType
  tool_name?: string
  server_name?: string
  input_summary: Record<string, unknown>
  rows: Array<Record<string, unknown>>
  columns: string[]
  metrics: string[]
  dimensions: string[]
  date_range: { startDate: string; endDate: string }
  resolved_filters: Record<string, unknown>
  quality_check: ReportQualityCheck
  recommended_actions: RecommendedAction[]
  message: string
}
```

红线：

- `rows` 只能来自真实 MCP 返回或基于真实 rows 的后处理。
- MCP 调用失败时，`status` 不能是 `success`。
- 解析失败时要保留失败类型，不能输出空表伪装成功。

## 8. 后处理

P0：

- 表格列提取。
- 数值列格式识别。
- 空结果诊断。
- 复合查询分块展示。
- 基础图表建议。

P1：

- TopN。
- 排序。
- 环比 / 同比。
- 差值 / 差异比例。
- 总计与明细核对。
- 派生指标计算。

后处理约束：

- 只能基于真实 rows。
- 不同报表域的结果必须保留来源块。
- 派生指标必须有公式来源或内部口径。

## 9. UI 结果渲染

成功结果：

- 查询条件摘要。
- 核心指标摘要。
- 表格。
- 可选图表。
- 数据来源和更新时间。
- 筛选解析说明。
- 下一步建议。

空结果：

- 显示“没有返回数据”。
- 展示可能原因：条件过窄、无权限、数据延迟、字典范围无数据。
- 给出放宽条件或确认筛选建议。

失败结果：

- 显示失败位置：项目解析、字典、tool、结果解析、权限。
- 给出可执行下一步：补字段、换项目、重试、生成 Case。
- 不展示成功卡片样式。

复合查询：

- 顶部展示计划摘要。
- 每个子查询单独展示状态。
- 部分成功时展示成功块和失败块。

## 10. 下一步建议

建议必须由状态驱动：

| 状态 | 建议 |
|---|---|
| `success` | 继续按媒体/团队/素材拆分，生成定时报表，转诊断候选 |
| `empty` | 放宽时间或筛选，确认字典名称，检查数据延迟 |
| `missing_input` | 补充项目、时间、指标或口径 |
| `dictionary_unmatched` | 确认名称，选择候选，直接提供 ID |
| `permission_denied` | 切换有权限项目或申请权限 |
| `tool_failed` | 重试或生成 Case |
| `parse_failed` | 生成工程排查 Case |

## 11. 失败闭环

失败分类：

```ts
type ReportFailureType =
  | 'route_error'
  | 'project_resolution_error'
  | 'slot_error'
  | 'dictionary_error'
  | 'tool_selection_error'
  | 'mcp_call_error'
  | 'result_parse_error'
  | 'postprocess_error'
  | 'ui_contract_error'
  | 'permission_error'
  | 'data_empty_or_unavailable'
```

闭环规则：

- 缺字段：追问。
- 字典多候选：让用户选择。
- 字典空结果：要求确认名称或 ID。
- MCP 缺失：进入能力缺口，不说已完成。
- MCP 调用失败：允许重试；仍失败时生成 Case。
- 解析失败：生成工程排查 Case。
- 空结果：先解释范围和条件，不急于生成 Case。

## 12. 验收分层

每条测试集用例至少验收：

| 层 | 验收点 |
|---|---|
| 路由 | 是否命中正确报表域 |
| 项目 | 是否使用用户明示项目，是否校验权限 |
| Slot | 日期、指标、维度、口径是否解析正确 |
| 字典 | alias 是否调用真实字典 tool |
| Tool | 是否选择正确 MCP tool |
| 调用 | 是否真实调用，失败是否暴露 |
| 解析 | rows、columns、metrics 是否正确 |
| 后处理 | TopN、排序、环比、核对是否基于真实 rows |
| UI | 表格、图表、空结果、失败块是否正确 |
| 建议 | 下一步建议是否随状态变化 |

P0 必须覆盖：

- 日报 / 周报 / 月报。
- 小时报表。
- ROI。
- 留存。
- 素材。
- 媒体、终端、团队、应用类型、账户、包体、优化师字典。
- 空结果。
- 权限失败。
- tool 失败。
- 复合查询部分成功。

## 13. 工程实施清单

P0：

- 将问数测试集转换为 `ReportTestCaseCapabilityMapping`。
- 报表域路由从粗 `report_query` 细分到 `ReportQuestionType`。
- 项目解析和权限校验进入问数执行前置。
- 完成日期、指标、维度、口径 slot 解析。
- 完成媒体、终端、团队、应用类型、账户、包体、优化师字典解析。
- MCP 入参构造按 schema 过滤字段。
- 结果解析输出统一 `ReportQueryResult`。
- 前端结果卡支持成功、空结果、失败、部分成功。
- 下一步建议按状态生成。
- 失败 Case 区分缺字段、缺能力、tool 失败、解析失败。

P1：

- TopN、排序、环比、占比、总计核对。
- 图表渲染验收。
- 复合查询计划可视化。
- 测试集失败归因面板。
