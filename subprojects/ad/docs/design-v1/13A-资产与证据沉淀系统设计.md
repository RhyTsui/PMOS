# 小乔智投资产与证据沉淀系统设计

## 1. 设计定位

本设计独立定义“小乔智投”中用户可见、可复用、可追溯的资产与证据沉淀机制。它不等同于 Trace，也不承担连弩评测平台职责。

- 资产：用户或自动化流程需要后续查看、复用、归档、筛选的业务产物。
- 证据：支撑某个结论、建议、状态或 Case 的来源引用。
- Trace：执行链路的完整回放与评测记录，归属连弩接入设计，不在本文展开。

资产与证据的目标不是“多存”，而是让业务闭环可验证、可追溯、可权限过滤。

## 2. 对应需求

- 查询结果只有用户保存后才写入资产。
- 自动化任务和定时报表产物默认写入资产。
- 报表模板可以跨项目复用，产物必须绑定项目。
- 会话、资产、自动化任务均可包含多个项目，但必须根据用户最新项目权限动态展示。
- 包交付、异常排查、需求沟通、指标解释等结论必须有证据来源。
- 系统无力完成时，需沉淀失败 Case、已确认信息、已调用能力、失败原因和下一步建议。

## 3. 核心产品规则

### 3.1 资产沉淀规则

| 场景 | 是否默认入资产 | 规则 |
|---|---:|---|
| 用户即时问数结果 | 否 | 只有用户点击保存后才生成资产 |
| 定时报表产物 | 是 | 每次任务成功产出默认生成资产 |
| 自动化任务产物 | 是 | 自动化结果默认进入资产并绑定任务 |
| 报表模板 | 是 | 模板可跨项目复用，但执行结果必须绑定实际项目 |
| 包交付结果 | 条件入资产 | 正式交付结论、联调报告、失败 Case 可沉淀 |
| 异常排查报告 | 条件入资产 | 用户保存或流程生成 Case 时沉淀 |
| 指标解释回答 | 否 | 默认只展示来源；用户保存后可作为知识参考资产 |
| 需求沟通草稿 | 否 | 只有确认提交 Case / 需求池后才沉淀 |

### 3.2 证据沉淀规则

- 证据不是日志，证据必须能支撑一个用户可见结论。
- 没有证据的诊断、包状态、指标口径、数据结论只能标记为“待验证”或“部分完成”。
- 证据可以引用 MCP / Workflow / Skill 的返回结果，但前端展示必须经过权限和脱敏处理。
- 知识库可以作为术语、口径、SOP、方法论证据来源，但不能作为实时项目数据、权限、包状态、联调状态的事实来源。
- 证据应保留来源系统、采集时间、项目引用、调用引用和摘要，避免只保存一段自然语言。

### 3.3 权限展示规则

- 会话、资产、自动化任务、证据均绑定 `project_refs`。
- 用户项目权限动态变化后，资产和证据展示必须按最新权限过滤。
- 当前阶段不做“会话 / 资产按项目隔离展示”，但所有列表和详情必须支持项目筛选与不可见项目遮蔽。
- 如果一个资产包含多个项目，用户只能看到自己仍有权限的项目数据；无权限项目部分以“因权限变更不可见”占位，不展示原始数据。

## 4. 系统流程

### 4.1 即时问数保存为资产

1. 用户发起问数。
2. Chat 完成意图、项目、slot、字典、MCP 调用和结果解析。
3. 前端展示结果、证据来源和下一步建议。
4. 用户点击保存。
5. 后端根据结果、项目、证据引用创建资产。
6. 我的资产展示该资产，并按当前权限动态过滤。

关键约束：未保存的即时查询结果不写入资产库，但可以在会话中保留回答内容和 EvidenceRef。

### 4.2 定时报表产物自动入资产

1. 用户创建定时报表，必须确认数据延迟策略。
2. 任务绑定项目、模板、执行频率、数据延迟策略。
3. 调度触发后调用真实问数能力。
4. 成功产出报表后自动创建资产。
5. 小闪通知或会话提示可引用资产 ID。
6. 用户在我的资产中查看、筛选、归档。

关键约束：任务本身和任务产物都要绑定项目；报表模板可跨项目复用，不能把模板的项目当成结果项目。

### 4.3 包交付证据沉淀

1. 包交付 Workflow 获取上报检查报告。
2. 通过后，根据包类型等待媒体后台更新或智投后台更新。
3. 检测到新版本后触发联调。
4. 联调完成后生成可投 / 不可投结论。
5. 结论必须引用上报检查、后台更新检测、联调报告、截图或日志。
6. 失败时自动生成 Case，并绑定证据。

关键约束：Chat 不直接生成包状态、可投结论或联调结论；只能展示 Workflow / MCP 派生结果。

### 4.4 失败 Case 沉淀

当系统多轮追问后仍无法完成，或真实工具调用失败且不能恢复时：

1. 保留原始用户问题。
2. 记录已确认信息、缺失信息、项目上下文、权限判断。
3. 记录已调用能力、调用结果、失败分类。
4. 生成 Case 或待处理记录。
5. 告知用户当前无法完成、已生成 Case、建议等待处理或补充信息。

## 5. 数据模型

### 5.1 AssetRecord

```ts
type AssetType =
  | 'query_result'
  | 'scheduled_report_result'
  | 'report_template'
  | 'automation_result'
  | 'package_delivery_result'
  | 'diagnosis_report'
  | 'demand_case'
  | 'evidence_bundle';

interface AssetRecord {
  asset_id: string;
  asset_type: AssetType;
  title: string;
  owner_user_id: string;
  project_refs: ProjectRef[];
  source_type: 'conversation' | 'automation_task' | 'workflow' | 'manual_save';
  source_ref: {
    conversation_id?: string;
    message_id?: string;
    task_id?: string;
    workflow_run_id?: string;
    case_id?: string;
  };
  payload_ref: string;
  evidence_refs: string[];
  visibility: 'private' | 'team_visible' | 'role_visible';
  created_at: string;
  updated_at: string;
  archived_at?: string;
}
```

### 5.2 EvidenceRef

```ts
type EvidenceType =
  | 'mcp_result'
  | 'workflow_result'
  | 'skill_result'
  | 'knowledge_source'
  | 'external_source'
  | 'user_confirmation'
  | 'system_event'
  | 'screenshot'
  | 'case_record';

interface EvidenceRef {
  evidence_id: string;
  evidence_type: EvidenceType;
  title: string;
  summary: string;
  source_system: string;
  source_object_type: string;
  source_object_id: string;
  project_refs: ProjectRef[];
  captured_at: string;
  source_time_range?: {
    start: string;
    end: string;
  };
  sensitivity: 'public' | 'internal' | 'project_restricted' | 'user_private';
  raw_payload_ref?: string;
  display_payload_ref?: string;
}
```

```ts
interface AssetVisibilityResult {
```

## 6. 接口契约

### 6.1 查询资产列表

`GET /api/xiaoqiao/assets`

请求参数：

- `asset_type`
- `project_id`
- `owner_user_id`
- `created_from`
- `created_to`
- `include_archived`

响应必须返回：

- 资产基本信息。
- 可见项目。
- 不可见项目数量。
- 最新证据摘要。
- 来源会话 / 任务 / Workflow 引用。

### 6.2 保存会话结果为资产

`POST /api/xiaoqiao/assets`

请求字段：

- `conversation_id`
- `message_id`
- `asset_type`
- `title`
- `project_refs`
- `payload_ref`
- `evidence_refs`

服务端必须校验：

- 用户对 `project_refs` 有权限。
- `payload_ref` 与 `message_id` 或任务结果一致。
- `evidence_refs` 不越权。

### 6.3 查看证据详情

`GET /api/xiaoqiao/evidence/{evidence_id}`

响应根据权限返回：

- 可展示摘要。
- 脱敏后的展示内容。
- 原始来源引用。
- 不可见原因。

## 7. 前后端职责

### 7.1 前端职责

- 在问数结果、报表结果、包交付结论、诊断结论处展示来源引用。
- 对即时问数提供“保存到我的资产”入口。
- 在我的资产弹窗或页面中提供项目字段、项目筛选、归档、历史查看。
- 对部分不可见资产展示遮蔽状态，不展示无权限项目数据。
- 不在前端伪造 EvidenceRef 或可投结论。

### 7.2 后端职责

- 创建和维护 AssetRecord、EvidenceRef。
- 对每次读取按最新项目权限过滤。
- 将 Workflow / MCP / Skill 的结构化结果转换为可引用证据。
- 在自动化任务成功产出后创建资产。
- 在失败闭环中创建 Case 并绑定证据。

### 7.3 MCP / Workflow 边界

- MCP / Workflow 返回业务事实和原始执行结果。
- Chat 编排层只负责绑定证据、解析摘要、组织回答。
- 资产服务负责资产生命周期和权限展示。
- 知识库只提供术语、口径、SOP、方法论来源，不承载实时资产事实。

## 8. 失败闭环

| 失败点 | 系统行为 |
|---|---|
| 保存资产失败 | 不提示已保存；保留会话结果，提示用户可重试 |
| EvidenceRef 不存在 | 不允许生成“有证据”结论，标记为部分完成 |
| 用户权限变化 | 展示可见部分，隐藏无权限项目数据 |
| 自动化产物创建资产失败 | 任务状态标记为产物沉淀失败，保留执行结果引用，支持重试 |
| 包交付证据缺失 | 不输出可投结论，转为待验证或 Case |
| 多轮无法补齐 | 生成 Case，记录已确认信息和缺失信息 |

## 9. 验收规则

1. 即时问数结果未保存时，不出现在我的资产。
2. 用户保存问数结果后，资产详情能看到结果、项目、来源消息和证据。
3. 定时报表任务成功后，默认生成资产。
4. 用户失去某项目权限后，历史会话、资产、自动化产物中的该项目数据不可见。
5. 包交付可投结论必须引用上报检查、后台更新检测和联调结果。
6. 诊断结论没有 EvidenceRef 时不能标记为确定结论。
7. 失败 Case 必须包含原问题、已确认信息、已调用能力、失败原因和下一步建议。
