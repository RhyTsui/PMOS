投放包直交付需求文档

目标：通过 获取广告包 服务，直接交付通过检测的投放包给投放侧。

背景 目标 流程 状态 页面建议 验收标准

背景

当前智投 chat 的定位，已经从“应用管理、包管理、分包工具、线下验收、线下联调协助”逐步转向“直接交付可用的投放包给投放侧”。

过去的方式是先给工具，再由运营、QA、联调同学协助用户一步步完成包管理、验收和联调；新的目标是把前置流程自动化，最终直接输出“已经通过我们检测、可以交付投放”的包。

目标

  1. 让用户在最短路径上拿到“通过检测的投放包”。
  2. 以“获取广告包”服务作为第一入口，自动汇聚符合条件的包。
  3. 只依赖最少输入完成判断，输入不全时明确提示缺失项。
  4. 将包的检测、分包、共享、联调、状态展示统一到一条可交付链路里。
  5. 最终给投放侧看到的是“可用包列表”，而不是一堆中间工具和人工协助动作。

流程

1. 项目初始化与包规范检验

先判断当前项目下有哪些包符合交付规范，再决定是否进入包列表。

识别范围 官方母包 巨量包 腾讯包 快手包 联运包
最小输入

只需要：出母包、提审。缺失时要明确提示。

2. 智投包列表生成

将可交付包整理成面向投放的包列表，展示每个包的地址、归属、上报验收状态、审核状态、联调状态。

3. 分包自动生成

根据媒体类型自动生成对应分包，减少人工分包成本。

  • 官方渠道包 310003：自动生成爱奇艺广告、百度搜索、百度信息流、UC头条、百度品专、神马搜索、超级粉丝通、网易有道、官网、市场分包。
  • 巨量 / 腾讯 / 快手包：自动创建 1 个市场星图分包、1 个广告分包、1 个广告星图分包、1 个广告直播分包、1 个市场直播分包，并同步媒体后台分包。

4. 联调与共享

巨量 / 腾讯 / 快手包在联调前，需要先查找户里应用、共享给指定账户，再自动执行联调；其他媒体包在分包后直接自动联调。

5. 最终交付视图

用户最终看到的是可直接使用的包，不是工具信息。

状态定义

状态类型
  • 上报验收状态
  • 审核状态
  • 联调状态
  • 可交付状态
示例状态
  • 待补齐
  • 待验收
  • 验收通过
  • 审核中
  • 审核通过
  • 联调中
  • 联调通过
  • 不通过
  • 可交付

页面建议

  • 建议把“获取广告包”作为第一入口，用户先从这里进入。
  • 页面结构建议：顶部输入状态、中部可交付包列表、右侧过程展开区、底部缺失输入和异常原因。
  • 输入不完整时先提示，不盲目往下跑。
  • 结果优先展示可交付包，中间过程只在展开时查看。

验收标准

  1. 只要输入了出母包和提审，就能进入包检测流程。
  2. 输入缺失时，系统能明确提示缺少什么。
  3. 310003 官包能自动生成对应分包列表。
  4. 巨量 / 腾讯 / 快手包能自动生成 5 类分包并同步媒体后台。
  5. 联调状态能在包列表里看到。
  6. 最终页面能直接展示可交付包，而不是工具信息。

待确认问题

  • “获取广告包”服务的最终入参字段是否统一命名。
  • 出母包和提审的来源是手输、项目配置，还是后台自动带入。
  • 分包模板是否需要支持后续媒体扩展。
  • 联调失败后是否要自动进入人工接管流程。
