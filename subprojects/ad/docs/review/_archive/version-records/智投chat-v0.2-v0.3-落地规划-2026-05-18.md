# 智投chat v0.2 / v0.3 落地规划

## 总体方向
把 chat 从“能问”推进到“能交付、能追踪、能消歧、能回看”。  
v0.2 先做稳定闭环，v0.3 再补平台化能力和跨模块编排。

## v0.2 计划

### 功能需求
- 新增一个独立入口和交互形态，承接投放包直交付相关需求。
- 项目筛选、包直交付、结果摘要、任务查看继续增强。
- 项目包列表支持更多状态和可用性展示。
- 继续补强联调结果摘要层，成功只给结论和证据，失败只给最后失败步骤和原因。
- 报表问数时展示真实 tool 请求与返回，不再出现 mock 数据。

### 提示词优化需求
- 数据排查 agent 固定 skill 组合。
- 使用帮助只负责歧义解释和规则说明，不直接充当执行兜底。
- 能力发现优先于知识解释，知识库先参与歧义消解，再决定是否调用 tool。

### 其他模块
- 后端：chat 后端接口、任务状态、MCP 工具发现、结果摘要。
- MCP：报表、联调、项目包列表、监控、排查能力补齐。
- 前端：入口页、快捷示例、结果承接、日志查看。
- 测试：回归意图路由、能力发现、歧义确认、缺参追问、结果输出。

## v0.3 计划

### 功能需求
- 打通从“项目初始化 -> 识别对象 -> 获取包 -> 分包 -> 联调 -> 结果交付”的全流程。
- 监控、定时任务、报表编排、项目包列表、可用状态等入口统一承接。
- 增强历史回看与证据留档。

### 提示词优化需求
- 完善意图消歧规则库。
- 完善追问策略，减少一次性错误选择。
- 完善结果生成约束，避免正文输出过程产物。

### 其他模块
- 建立统一能力目录。
- 建立统一 workflow/state machine。
- 建立统一日志与证据结构。

## 风险提示
- 同名能力过多时，仍可能出现候选歧义，需要继续加规则。
- MCP 返回结构不稳定时，前端步骤解析可能再出错。
- 如果后续新增入口较多，入口层与会话层容易互相抢焦点，需要提前统一交互语义。

## 建议的执行顺序
1. 先发 `v0.1.2`。
2. 再做 `v0.2` 的新入口和交互。
3. 最后推进 `v0.3` 的全流程打通和平台化能力。
