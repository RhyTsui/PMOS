# 小乔智投 Framer Motion 应用场景设计

日期：2026-05-20  
状态：待评审  
范围：动效设计探索，不改当前产品代码。

## 1. 结论

Framer Motion 适合用于“小乔智投”的轻量状态表达、进入退出过渡、列表变化和任务过程感知，不适合替代业务逻辑，也不适合参与高频流式消息渲染的核心链路。

建议原则：

1. 先用于低风险 UI 外层，不进入数据链路。
2. 只增强“感知正在处理”和“状态变化清晰”，不做炫技动画。
3. 每个动效单独提交，方便回退。
4. 业务组件先 CSS 动效，确认需要更强状态编排时再上 Framer Motion。

## 2. 适合应用的场景

### 2.1 新会话欢迎区

状态：已小范围尝试，适合继续微调。

用途：

- 欢迎区轻入场。
- Logo icon 轻微缩放 / 透明度过渡。
- 快捷入口卡片错峰出现。
- PromptCard hover 上浮。

推荐动效：

- 页面进入：`opacity 0 -> 1`，`y 8 -> 0`
- 卡片进入：stagger children，每张延迟 40-60ms
- hover：`y -3/-4`，shadow 增强

风险：

- 低。
- 只影响空态页，不影响消息过程。

### 2.2 快捷入口卡片

状态：适合。

用途：

- 分类卡片 hover 上浮。
- 内部快捷问题轻微位移。
- hover 时边框和光晕平滑过渡。
- 点击后轻微按压反馈。

推荐动效：

- `whileHover={{ y: -4 }}`
- `whileTap={{ scale: 0.985 }}`
- 子按钮 hover 使用 CSS 即可，不必全部 Motion 化。

风险：

- 低。
- 注意不要改变点击写入输入框的现有逻辑。

### 2.3 思维链折叠 / 展开

状态：可作为第二阶段尝试，第一版建议先 CSS。

用途：

- 展开 / 收起高度过渡。
- 当前步骤切换时平滑移动。
- 新步骤进入时淡入。
- 失败步骤出现时轻微提示。

推荐动效：

- `AnimatePresence` 管理步骤进入退出。
- `layout` 管理步骤高度变化。
- 当前步骤使用 CSS 呼吸点和进度条，减少 Motion 参与高频状态。

风险：

- 中。
- 思维链是高频流式更新组件，Motion 如果包太深，可能造成重复渲染和滚动抖动。

建议：

- 第一版只用 CSS。
- 如果后续需要“步骤平滑插入”和“展开高度动画”，再单独上 Framer Motion。

### 2.4 调用与来源展开

状态：适合小范围。

用途：

- 来源条展开 / 收起。
- 点击日志后右侧侧边栏进入。
- 来源标签 hover 和打开状态过渡。

推荐动效：

- 右侧侧边栏：`x 24 -> 0`，`opacity 0 -> 1`
- 遮罩：`opacity`
- 来源条：`height` 或 `opacity + y`

风险：

- 中低。
- 注意不要影响移动端侧边栏层级。

### 2.5 右侧侧边栏 / 移动端抽屉

状态：适合。

用途：

- PC 右侧面板滑入。
- 移动端底部 / 全屏抽屉滑入。
- 切换日志、记录、来源时内容淡入。

推荐动效：

- PC：`x: 28 -> 0`
- Mobile：`y: 32 -> 0`
- 退出：`opacity 1 -> 0`

风险：

- 中。
- 需要谨慎处理 z-index，之前移动端侧边栏和顶部重叠出现过问题。

### 2.6 会话列表运行状态

状态：可做，但建议非常克制。

用途：

- 执行中的会话在操作按钮区域显示 spinner。
- 会话列表新增 / 删除 / 排序时平滑过渡。
- 移动端折叠按钮的小点出现 / 消失。

推荐动效：

- spinner 用 CSS，不用 Motion。
- 会话列表位置变化可用 `layout`。

风险：

- 中。
- 会话列表频繁变化，如果 Motion 影响 hover 操作按钮，需要避免。

### 2.7 确认组件 / 缺参追问

状态：适合。

用途：

- 确认按钮进入。
- 选择后按钮组收起。
- 缺参项逐条出现。

推荐动效：

- `AnimatePresence`
- `staggerChildren`
- 按钮 `whileTap`

风险：

- 低。
- 适合提升“追问不是一段文字，而是可操作步骤”的感知。

### 2.8 任务结果卡片 / Artifact

状态：适合。

用途：

- 成功结果卡片出现。
- 失败原因区展开。
- 证据条进入。
- 报表卡片切换 tab。

推荐动效：

- 结果出现：`opacity + y`
- 失败原因：height auto
- tab 切换：shared layout underline

风险：

- 中低。
- 不要影响最终正文可读性。

## 3. 暂不建议应用的场景

### 3.1 流式正文逐字渲染

原因：

- 当前消息已经有流式输出。
- Framer Motion 包裹每段文字可能增加渲染开销。
- 容易造成跳字、滚动抖动、光标不稳定。

建议：

- 保持现有流式逻辑。
- loading 三点可以用 CSS。

### 3.2 联调步骤主组件

原因：

- 联调组件刚稳定。
- 当前核心风险是数据结构、轮询和截图展示，不是动效。
- Motion 扩进去会增加排查复杂度。

建议：

- 暂不动。
- 后续只可在“步骤展开 / 收起”局部尝试。

### 3.3 项目选择器

原因：

- 项目选择器刚稳定。
- 移动端和 YokaUI 对接都比较敏感。

建议：

- 不引入 Framer Motion。

### 3.4 高频虚拟列表

原因：

- 会话列表、日志列表、长步骤列表如果数据量大，Motion 会增加性能风险。

建议：

- 只做容器进入退出，不逐行复杂动画。

## 4. 推荐实施分级

### A 级：可以直接尝试

1. 新会话欢迎区进入。
2. PromptCard hover / tap。
3. 快捷入口卡片错峰出现。
4. 确认按钮组进入 / 选择反馈。

特点：

- 影响范围小。
- 回退简单。
- 不碰业务链路。

### B 级：确认后尝试

1. 思维链展开 / 收起高度动画。
2. 思维链步骤插入动画。
3. 调用与来源展开。
4. 右侧侧边栏滑入。
5. 任务结果卡片出现。

特点：

- 体验提升明显。
- 需要浏览器验收。
- 要保证不影响滚动和移动端层级。

### C 级：暂缓

1. 联调组件步骤流。
2. 流式正文。
3. 项目选择器。
4. 长日志列表。

特点：

- 容易影响稳定性。
- 不符合当前“先稳业务链路”的优先级。

## 5. 小乔智投动效体系建议

### 5.1 动效语义

| 语义 | 动效 | 使用场景 |
| --- | --- | --- |
| 正在处理 | 三点波浪 / 呼吸点 | 思维链、输入框、任务状态 |
| 新内容出现 | opacity + y | 卡片、确认项、结果 |
| 状态变化 | layout transition | 会话列表、步骤列表 |
| 可点击 | hover 上浮 / tap 按压 | 快捷入口、确认按钮 |
| 面板打开 | slide + fade | 右侧侧边栏、移动端抽屉 |
| 当前焦点 | 淡蓝边光 | 当前步骤、当前任务 |

### 5.2 默认参数

| 参数 | 建议值 |
| --- | --- |
| duration | 0.18s - 0.28s |
| ease | cubic-bezier(0.4, 0, 0.2, 1) |
| hover y | -3px / -4px |
| tap scale | 0.985 |
| stagger | 0.04s - 0.06s |
| opacity 起点 | 0 / 0.6 |

### 5.3 视觉约束

1. 不做强霓虹。
2. 不做赛博朋克。
3. 不做游戏化弹跳。
4. 不让动效抢结论正文。
5. 不让动效影响滚动、点击和输入。

## 6. 第一阶段建议

第一阶段只做 A 级场景：

1. 新会话欢迎区。
2. PromptCard。
3. 快捷入口卡片。
4. 确认组件。

不做：

1. 思维链 Motion 化。
2. 联调组件 Motion 化。
3. 项目选择器 Motion 化。
4. 消息正文 Motion 化。

原因：

- 这四个 A 级场景是体验收益高、风险低、回退简单的区域。
- 思维链正在做单独设计规范，应先完成 CSS 版本，再判断是否需要 Motion。

## 7. 回退策略

每个 Motion 场景单独提交。

推荐提交粒度：

1. `motion: polish empty chat entry`
2. `motion: polish prompt card interactions`
3. `motion: add confirmation choice transitions`

回退方式：

```bash
git revert <commit>
```

不建议一次提交同时改：

- 新会话页
- 思维链
- 侧边栏
- 联调组件

## 8. 需要确认

1. 是否接受 Framer Motion 只先用于 A 级场景。
2. 思维链第一版是否仍先用 CSS，不引入 Motion。
3. 右侧侧边栏是否纳入第二阶段 Motion 尝试。
4. 确认组件是否作为下一个低风险试验点。
