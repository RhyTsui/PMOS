## 5. 重要约束与经验

1. 新会话页视觉优化不能改动消息过程组件。
2. 新会话页视觉优化不能改动项目选择器。
3. 新会话页视觉优化不能改动快捷入口数据、模板、点击行为。
4. 新会话页视觉优化不能改动发送消息、上传文件、语音、附件逻辑。
5. 视觉动效要服务“AI 智能感”和“专业可信感”，不要强霓虹、赛博朋克、游戏化。
6. Logo 后方单独大光束容易像脏背景；更好的方式是整体环境背景承接光感。
7. 多色 PromptCard 与蓝色流光不搭；统一冷白/雾蓝底更稳。
8. 每次 `build` 后必须重启 `8002`，否则容易出现新 HTML 引旧 chunk 导致页面打不开。

## 6. 后续建议

1. 如果继续优化新会话页，优先看真实浏览器效果，不要只按静态规范推进。
2. 如果对 Framer Motion 不满意，可单独 revert：
   - `git revert 7dd9a88`
3. 如果只对后续视觉收敛不满意，可按提交粒度回退：
   - `git revert bded13b`
   - `git revert 73b9466`
4. 建议后续把“会话整理 / 日报 / 蒸馏 / 记忆同步”做成稳定工作流：
   - 用户请求关闭会话前，自动生成会话归档。
   - 将用户关键诉求、AI 执行动作、提交记录、遗留风险写入文档。
   - 同步一份短记忆到 Codex/Dataki 知识库，便于下次继续。
