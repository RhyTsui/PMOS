# 小乔智投思维链视觉交互设计规范

日期：2026-05-20  
状态：待评审  
范围：仅覆盖会话消息中的思维链组件，不覆盖联调组件、调用与来源、项目选择器和最终结果正文。

## 1. 设计目标

思维链不是结果交付区，而是让用户理解“小乔正在如何推进任务”的过程区。

本次设计只解决四类问题：

1. 等待时用户不知道是否还在执行。
2. 折叠时用户不知道当前进行到哪一步、耗时多久。
3. 展开时步骤过多，顺序和当前步骤不清晰。
4. 历史步骤仍显示转圈，造成“任务卡住”的误判。

不做的事情：

1. 不改 Agent / Skill / MCP 的业务链路。
2. 不改联调组件的数据展示。
3. 不把工具请求和返回铺在思维链外层。
4. 不新增传统后台式详情页。

## 2. 组件定位

思维链属于会话过程组件，位置保持当前顺序：

1. 思维链
2. 联调 / 报表 / 排查等动态组件
3. 调用与来源
4. 正文结果

每一层职责：

| 层级 | 展示内容 | 不展示内容 |
| --- | --- | --- |
| 思维链 | 路由判断、关键步骤、当前进度、耗时 | 大段 JSON、日志、截图 |
| 动态组件 | 任务结构化过程，如联调步骤、报表配置 | Agent 路由细节 |
| 调用与来源 | 工具、知识库、日志入口 | 用户结论 |
| 正文结果 | 成功结论、失败原因、可交付结果 | 过程产物 |

## 3. 折叠态设计

折叠态只展示一行，目标是让用户知道“有没有在跑、跑到哪、跑了多久”。

结构：

```text
思维链  [动态状态]  当前步骤 / 最新动作  01:24                         展开
```

规则：

1. 标题固定为“思维链”。
2. 运行中展示三点波浪动画，不使用大 spinner。
3. 当前步骤展示最新 running 步骤；若没有 running，则展示最后一个 completed / error 步骤。
4. 耗时使用分秒格式，例如 `01:24`，超过 1 小时显示 `1:02:08`。
5. 折叠态不展示步骤序号，避免一行过载。
6. 折叠态背景保持当前浅蓝体系，不改成深蓝。
7. 折叠态右侧只保留“展开 / 收起”。

视觉建议：

```text
┌──────────────────────────────────────────────────────────────┐
│ 💡 思维链  •••  查询报表数据                     01:24  展开 │
└──────────────────────────────────────────────────────────────┘
```

## 4. 展开态设计

展开态展示顺序、状态和必要说明，但默认不展示技术内容。

结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 💡 思维链  •••  查询报表数据                     01:24  收起 │  sticky
├──────────────────────────────────────────────────────────────┤
│ ✓ 1. 识别处理路径                                  00:01     │
│   已进入看数据处理路径                                      │
│                                                              │
│ ✓ 2. 查询知识库                                    00:02     │
│   已确认指标口径和项目上下文                                  │
│                                                              │
│ ◌ 3. 调用报表工具                                  00:18     │
│   正在获取近 7 天大盘数据                                    │
│   ━━━━━━━━━━━━━━━──  轻量流动进度条                           │
│                                                              │
│   查看请求与返回                                              │
└──────────────────────────────────────────────────────────────┘
```

展开态规则：

1. 标题栏吸顶，颜色不因展开/收起发生明显跳变。
2. 每个步骤一行主信息：状态图标、序号、步骤名、耗时。
3. 步骤描述只展示中文摘要，最多两行，超过省略。
4. 运行中的步骤使用呼吸点 + 轻量流动进度条。
5. 已完成步骤只显示对勾，不再转圈。
6. 失败步骤显示错误图标和失败原因摘要。
7. 工具请求、参数、返回默认收起，点击“查看请求与返回”后用代码块展示。
8. 一次最多直接展开最近 8 个步骤；更早步骤折叠为“已完成 N 步”，点击再展开。

## 5. 状态规则

### 5.1 状态来源

以步骤状态字段为主：

| 原状态 | 展示状态 | 图标 |
| --- | --- | --- |
| loading / running / pending | 进行中 | 呼吸点 |
| completed / success | 已完成 | 对勾 |
| error / failed | 失败 | 警示 |
| skipped | 跳过 | 灰点 |

### 5.2 历史步骤纠偏

如果出现多个步骤同时为 running：

1. 默认只有最后一个 running 步骤展示进行中。
2. 更早 running 步骤如果后面已有 completed / running 步骤，则前端显示为已完成。
3. 如果后端明确返回 error，则保留失败。

这样解决“第 1 步还在转圈，但任务已经到第 10 步”的视觉问题。

### 5.3 去重规则

同一轮消息中，按以下优先级生成唯一 key：

1. `step.key + started_at + index`
2. `label + content + index`
3. 最终兜底 `message_id + index`

如果出现相同 key：

1. 合并相邻重复步骤。
2. 保留最新状态。
3. 请求 / 返回合并到同一步详情里。

## 6. 动效规范

动效目标是“用户知道还在工作”，不是炫技。

允许：

1. 三点波浪：用于标题栏运行中状态。
2. 呼吸点：用于当前 running 步骤。
3. 轻量流动进度条：用于当前步骤下方。
4. 当前步骤左侧淡蓝光边：用于视觉锚点。
5. 展开 / 收起高度过渡：200ms 左右。

禁止：

1. 强霓虹。
2. 大面积旋转 spinner。
3. 多个历史步骤同时闪动。
4. 卡片整体剧烈跳动。
5. 影响文字阅读的背景粒子或扫光。

推荐参数：

| 动效 | 时长 | 透明度 | 说明 |
| --- | --- | --- | --- |
| 三点波浪 | 1.2s | 0.45-1 | 标题栏 |
| 呼吸点 | 1.6s | 0.35-1 | 当前步骤 |
| 流动进度条 | 1.8s | 0.2-0.5 | 当前步骤底部 |
| 展开过渡 | 180-240ms | - | 高度和透明度 |

## 7. 信息治理规则

思维链主视图只展示中文、用户能理解的过程信息。

主视图禁止直接展示：

1. 英文 tool 名。
2. JSON 参数。
3. 原始返回体。
4. HTTP、SSE、schema、contract 等内部词。
5. 时间戳。
6. 超长错误堆栈。

这些内容只能进入“查看请求与返回”或“调用与来源”。

## 8. 移动端规则

1. 折叠态仍为一行，但步骤名允许省略。
2. 展开态最大高度为当前屏幕的 45%-55%，内部滚动。
3. 标题栏吸顶。
4. 点击区域高度不小于 36px。
5. 技术详情代码块横向滚动，不撑开页面。

## 9. 与现有实现的关系

当前实现位置：

- `frontend/src/src/components/cognitive/ChatContainer.tsx`
- `ThinkingChain`
- Ant Design X `ThoughtChain`
- `buildThinkingStep` 位于 `frontend/src/src/app/api/chat/route.ts`

建议实现策略：

1. 先只改 `ThinkingChain` 展示层。
2. 新增纯前端 `normalizeThinkingSteps`，处理去重、历史 running 纠偏、耗时格式化。
3. 不改后端 SSE 协议。
4. 不改 `buildThinkingStep`。
5. 不改联调组件和调用与来源。

## 10. 需要评审确认的问题

1. 折叠态标题是否固定使用“思维链”，不再改为“思考过程”。
2. 展开态是否默认只直接展示最近 8 个步骤，更早步骤折叠成分组。
3. 多个 running 步骤时，是否同意前端只保留最后一个为进行中。
4. 技术请求 / 返回是否仍允许在单步内展开查看，还是只放到调用与来源。
5. 动效是否先用 CSS 实现，不扩大 Framer Motion 到思维链。
6. 是否允许后续把 Ant Design X `ThoughtChain` 替换为本地轻量 timeline，以获得更强控制力。

## 11. 第一版改动范围建议

第一版只做视觉和展示治理：

1. 折叠态显示最新步骤和分秒耗时。
2. 展开态步骤标题行统一：状态、序号、步骤名、耗时。
3. 历史 running 纠偏。
4. 重复步骤去重。
5. 技术详情默认收起。
6. 当前步骤增加轻量进度条。

第一版不做：

1. 不改 Agent / Skill / MCP。
2. 不改联调组件。
3. 不改调用与来源。
4. 不引入新的运行时依赖。
5. 不调整消息正文结果规则。
