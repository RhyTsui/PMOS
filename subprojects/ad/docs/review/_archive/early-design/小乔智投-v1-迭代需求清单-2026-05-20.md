# 小乔智投 v1 迭代需求清单

更新时间：2026-05-20  
来源文档：`docs/review/小乔智投-v1-产品策略与信息架构-2026-05-20.md`

## 1. 迭代目标

v1 的核心目标不是继续扩展“能问什么”，而是把小乔智投从当前对话入口收敛成稳定的 AI 投放服务台。

目标结果：

1. 用户知道小乔是谁、能帮什么、怎么开始。
2. 前台能力按 7 个工作意图组织，而不是按系统功能组织。
3. Agent / Skill / MCP / Workflow / Artifact 边界清晰。
4. 核心任务能从对话进入执行过程，并沉淀结果。
5. 结果正文只交付结论，过程和证据放在思维链、动态组件、调用与来源、任务记录里。

## 2. 版本拆分

### v1.0：定位与入口统一

目标：

统一产品命名、首页文案、入口定义和基础交互，不改变复杂业务链路。

需求清单：

| 编号 | 需求 | 类型 | 优先级 | 说明 |
| --- | --- | --- | --- | --- |
| V1.0-01 | 产品名称统一为“小乔智投” | 前端 / 文案 | P0 | 替换前台用户可见的“智投Chat / 智投chat”旧称呼 |
| V1.0-02 | 产品定位统一为“AI 投放服务台” | 前端 / 文案 | P0 | 不再用“AI 数据BP”作为对外定位 |
| V1.0-03 | 首页欢迎语调整 | 前端 | P0 | 使用“我是小乔，你的 AI 投放服务台...” |
| V1.0-04 | 首页入口说明调整 | 前端 | P0 | 使用“这些入口会自动带入标准提问模板” |
| V1.0-05 | 7 个入口统一为 Intent Launcher | 前端 / 配置 | P0 | 验流程、查异常、看数据、拼报表、提需求、问逻辑、追情报 |
| V1.0-06 | 入口点击带入标准模板 | 前端 / 配置 | P0 | 不跳传统页面，进入对话输入 |
| V1.0-07 | “行业动态”前台入口并入“追情报” | 前端 / 产品 | P0 | 行业动态不单独作为一级入口 |
| V1.0-08 | 首屏移动端入口展示规则确认 | 前端 | P1 | 移动端保留两列按钮，减少说明文案 |
| V1.0-09 | 管理页配置项同步新命名 | 后台配置 | P1 | 后台可继续维护入口文案和模板 |

验收标准：

- 首屏不再出现“智投Chat”作为产品定位。
- 用户可见主定位为“小乔智投 / AI 投放服务台”。
- 入口数量和名称与 v1 策略一致。
- 点击入口后不会跳传统菜单页。

## 3. v1.1：意图识别与模板路由稳定

目标：

让自然语言输入和 7 个入口都能稳定进入对应 Agent / Skill，而不是落入普通问答或直接暴露 MCP。

需求清单：

| 编号 | 需求 | 类型 | 优先级 | 说明 |
| --- | --- | --- | --- | --- |
| V1.1-01 | 建立 7 个入口的 intent 定义 | Agent / 提示词 | P0 | 每个入口定义触发词、排除词、必要上下文 |
| V1.1-02 | 入口模板进入上下文 | 前端 / Agent | P0 | 点击模板后，模型思维链能看到模板意图和当前项目 |
| V1.1-03 | 自然语言路由优先找 Agent / Skill | Agent Router | P0 | 找不到 Agent / Skill 再进入 MCP 工具发现 |
| V1.1-04 | MCP 工具发现不直接替代业务意图 | Agent Router | P0 | 工具是执行层，不是用户意图层 |
| V1.1-05 | 歧义问题先检索知识库 | Agent / Dataki | P0 | 如“应用列表”先判断智投应用、媒体应用、项目应用 |
| V1.1-06 | 缺参追问使用确认组件 | 前端 / Agent | P1 | 不用大段正文追问，尽量按钮化、轻量化 |
| V1.1-07 | 对话上下文支持“重试一下” | Agent / 上下文 | P0 | 继承上一轮失败任务，不把“重试一下”当关键词 |
| V1.1-08 | 思维链展示路由判断 | 前端 / Agent | P1 | 展示进入哪个 Agent / Skill，避免只显示普通对话 |
| V1.1-09 | 工具请求与返回默认收起 | 前端 | P1 | 报表、配置、联调等工具返回不直接铺在思维链外层 |

验收标准：

- “获取指间山海的应用列表”能先判断含义，再调用正确工具或追问。
- “重试一下”能接上上一轮上下文。
- 用户不需要知道 MCP 名称也能完成任务。
- 思维链能解释为什么进入某个业务路径。

需求清单：

| 编号 | 需求 | 类型 | 优先级 | 说明 |
| --- | --- | --- | --- | --- |

| V1.3-02 | 统一结果模型 | 后端 | P0 | Artifact 类型、标题、摘要、来源、可回看内容 |

| V1.3-04 | 自动联调任务接入统一任务模型 | 后端 / 前端 | P1 | 保留现有联调组件，不重做交互 |

## 8. 第一批建议实施范围

建议第一批只做 v1.0 + v1.1 的一部分，避免再次大范围误改。

第一批建议范围：

1. 更新首页产品定位和 7 个入口。
2. 保持当前项目选择器、联调组件、调用与来源组件不动。
3. 将“行业动态”前台入口并入“追情报”。
4. 建立 7 个入口的 Agent / Skill 路由定义文档。
5. 补充 20 条意图识别测试用例。
6. 不重做任务侧栏，只先定义模型和后续承载方式。

第一批不做：

- 不重构联调组件。
- 不重构项目选择器。
- 不新建传统菜单。
- 不大改右侧侧边栏。
- 不重做后台管理页。
- 不一次性实现所有 Agent。

## 9. 风险与约束

1. 首页入口改名会影响后台运行时配置，需要做迁移或兼容。
2. “追情报”合并行业动态、榜单、素材分析，路由需要避免误触发。
3. 报表 MCP 当前有数据一致性风险，必须纳入测试。
4. 自动联调组件刚稳定，v1 第一批不应改动。
5. 项目选择器刚稳定，v1 第一批不应改动。
6. 旧文档大量使用“智投Chat”，需要分阶段更新，不建议一次性批量替换全部历史文档。
