# 小乔智投 v1 产品策略与信息架构

更新时间：2026-05-20  
适用范围：小乔智投前台产品、Agent / Skill / MCP 编排、知识库建设、任务与结果承载设计

## 1. 最终命名

产品名称：

> 小乔智投

产品定位：

> AI 投放服务台

一句话介绍：

> 小乔智投是面向发行/投放团队的 AI 投放服务台，统一承接数据监测、异常排查、流程验收、报表生成、需求对接、知识问答和行业情报服务。

本轮命名调整后，不再将产品描述为“AI 数据BP”或“智投Chat”。

原因：

- 当前产品承载的不只是数据分析能力，也包括产品、测试、开发和既有工具体系共同沉淀出的投放服务能力。
- “数据BP”容易把产品能力限制在数据分析和业务解释。
- “Chat”容易把产品能力限制在聊天问答。
- “中台”容易让前台用户感知复杂、后台化。
- “AI 投放服务台”能覆盖数据监测、分包工具、异常排查、流程验收、报表生成、需求对接、知识问答、行业情报和 MCP 工具调用。

推荐展示：

> 小乔智投  
> AI 投放服务台

## 2. 产品原点

小乔智投要解决的问题不是“用户缺一个聊天框”，而是发行/投放团队在日常投放支持中，需要频繁依赖多个团队、多个系统和多种经验判断：

- 查数据
- 看异常
- 验投放流程
- 生成和解释报表
- 确认包、分包、联调和回传状态
- 提数据、对接、采集、监测需求
- 理解归因、回传、指标、出包规范
- 追踪行业动态、榜单变化、平台政策和素材趋势

过去这些能力分散在数据、产品、测试、开发、运营和工具系统中。小乔智投的核心价值，是把这些能力通过 AI 服务台的方式统一承接，让用户用自然语言发起需求，并在同一个工作界面里看到过程、证据、结果和下一步。

## 3. 产品定义

小乔是人格化服务入口。

智投是投放场景。

AI 投放服务台是产品品类。

因此，小乔智投不是普通 AI 助手，也不是传统 BI、传统广告后台或工具菜单集合。

它应该被定义为：

> 面向发行/投放团队的 AI 投放服务台，通过对话入口、工作意图入口、Agent 工作流、知识库和 MCP 工具，帮助用户完成投放相关的数据、流程、报表、需求、知识和情报服务。

## 4. 前台设计原则

### 4.1 不使用传统菜单组织能力

前台不按以下方式组织：

> 菜单 → 页面 → 表单 → 功能

前台按以下方式组织：

> 用户目标 → 工作意图入口 → 对话推进 → Agent 执行 → 过程展示 → 结果交付 → 任务沉淀

无菜单不是没有入口，也不是没有结构。

无菜单的含义是：

- 不把业务用户前台做成后台功能树。
- 不让用户先理解系统结构。
- 不让用户先选择底层工具。
- 不把 MCP、知识库、数据源、采集服务直接暴露为前台主路径。
- 用用户想完成的工作来组织入口。

### 4.2 前台只展示用户能理解的工作意图

前台核心入口统一为 7 个：

1. 验流程
2. 查异常
3. 看数据
4. 拼报表
5. 提需求
6. 问逻辑
7. 追情报

这些入口不是菜单，也不跳转传统页面。

它们是 Intent Launcher：点击后自动带入标准提问模板，进入对话和任务推进。

### 4.3 过程、证据和结果分层

小乔智投不是只返回一段文字。

前台输出需要分层：

- 思维链：展示判断过程、关键步骤和为什么进入下一步。
- 动态组件：展示当前任务的结构化过程，例如联调步骤、报表配置、异常排查链路、情报摘要。
- 调用与来源：展示工具、知识库、来源和日志入口。
- 正文结果：只展示结论、可交付结果、失败原因和下一步。

核心规则：

- 成功：正文只给结论和可交付结果。
- 失败：正文只给最后失败步骤、原因、建议下一步。
- 进行中：不输出最终结果正文，只持续更新过程区。

## 5. 首页文案

### 5.1 主欢迎语

> 我是小乔，你的 AI 投放服务台。
>
> 可以帮你看数据、查异常、验流程、拼报表、提需求、问逻辑、追情报。  
> 你可以直接输入问题、需求或操作任务，我会调用数据、知识库和工具继续推进。

### 5.2 入口说明

> 你也可以直接从下面开始，这些入口会自动带入标准提问模板。

### 5.3 输入框提示

建议：

> 输入你想查的数据、要排查的异常、要生成的报表、要跟进的需求，或直接问我业务逻辑。

## 6. 7 个入口定义

### 6.1 验流程

定位：

> 检查当前项目哪些包已经通过检测，可以交付投放。

标准模板：

> 帮我检查当前项目哪些包已经通过检测，可以交付投放。请按包名、检测结果、风险项、是否可投放输出。

典型输出：

- 可交付包清单
- 包地址
- 上报验收状态
- 审核状态
- 联调状态
- 风险项
- 下一步建议

### 6.2 查异常

定位：

> 排查操作异常、归因异常、回传异常、采集异常。

标准模板：

> 帮我排查一个异常。请先判断是操作异常、归因异常、回传异常还是采集异常，再按链路给出排查步骤和初步结论。

典型输出：

- 异常类型判断
- 可能原因排序
- 证据链
- 影响范围
- 需要人工确认项
- 下一步动作

### 6.3 看数据

定位：

> 查看广告数据、创意数据、商店数据、行业数据。

标准模板：

> 帮我看一下数据。请先确认项目、时间、渠道、维度和指标，再输出趋势、异常点、原因判断和建议动作。

典型输出：

- 数据摘要
- 趋势变化
- 异常点
- 口径说明
- 基准对比
- 优化建议

### 6.4 拼报表

定位：

> 定制日报、分类汇总、上传数据生成报表。

标准模板：

> 我想拼一个报表。请帮我确认数据源、维度、指标、筛选条件、周期和接收方式，然后生成报表配置。

典型输出：

- 报表配置
- 数据源
- 维度
- 指标
- 周期
- 预览结果
- 定时任务

### 6.5 提需求

定位：

> 自动阅读文档，协助对接新媒体或新增数据需求。

标准模板：

> 我有一个数据或对接需求。请帮我理解需求背景、目标、输入输出、涉及系统、风险点，并整理成可执行需求单。

典型输出：

- 需求理解
- 缺失信息追问
- 输入输出
- 涉及系统
- 风险点
- 可执行需求单
- 后续任务

### 6.6 问逻辑

定位：

> 解释出包规范、归因回传逻辑、指标口径、报表看数方法。

标准模板：

> 请解释这个业务逻辑或数据口径，并告诉我适用场景、常见误区、排查方法和相关文档来源。

典型输出：

- 业务解释
- 适用场景
- 常见误区
- 排查方法
- 知识库来源
- 相关文档

### 6.7 追情报

定位：

> 查看小游戏榜单、广告行业动态、平台政策、素材趋势和排名变化。

标准模板：

> 帮我追踪最近的投放情报，包括小游戏榜单、广告平台政策、行业动态、商店排名、广告素材趋势和对接文档更新。

典型输出：

- 情报摘要
- 变化趋势
- 影响分析
- 风险提示
- 机会点
- 来源引用
- 订阅建议

行业动态不作为前台一级菜单单独出现，归入“追情报”。

## 7. 工作区与任务承载

小乔智投前台不能只有会话流。

以下能力必须有任务状态和结果沉淀：

- 定制日报
- 需求跟踪
- 行业动态订阅
- 榜单追踪
- 异常监控
- 自动化联调
- 报表构建
- 深度行业研究

推荐前台保留任务/结果承载区，用于展示：

- 进行中任务
- 最近结果
- 已订阅情报
- 我的日报
- 我的需求
- 异常追踪
- 联调记录

这个区域不是传统菜单，而是工作状态和结果沉淀。

## 8. Agent / Skill / MCP / Workflow 边界

### 8.1 Agent

Agent 面向业务场景。

例如：

- 验流程 Agent
- 查异常 Agent
- 看数据 Agent
- 拼报表 Agent
- 提需求 Agent
- 问逻辑 Agent
- 追情报 Agent

Agent 负责理解用户目标、选择处理路径、协调 Skill 和 Workflow。

### 8.2 Skill

Skill 是某个场景下稳定的 SOP、工具编排和输出结构。

例如：

- 获取可交付包 Skill
- 数据异常排查 Skill
- 报表问数 Skill
- 自动联调 Skill
- 行业动态分析 Skill
- 创意对比分析 Skill

Skill 必须定义：

- 触发条件
- 必要输入
- 可调用 MCP
- 知识库使用方式
- 思维链步骤
- 输出结构
- 失败处理

### 8.3 MCP

MCP 是工具能力，不直接暴露给业务用户。

用户不应该看到“请选择 MCP 工具”这类表达。

MCP 负责实际读取或执行：

- BI / 报表数据
- 数仓数据
- 分包数据
- 联调任务
- 归因回传数据
- 媒体平台数据
- 行业采集数据
- Dataki 知识库

### 8.4 Workflow

Workflow 是跨步骤、有状态、可追踪的任务流。

适用于：

- 自动化联调
- 定时报表
- 行业动态订阅
- 异常监控
- 需求跟踪
- 采集对接

Workflow 必须有：

- 当前状态
- 当前步骤
- 失败原因
- 过程日志
- 结果沉淀
- 可继续处理的入口

### 8.5 Artifact

Artifact 是最终沉淀物。

例如：

- 可交付包清单
- 报表
- 异常诊断结论
- 需求单
- 情报摘要
- 联调报告
- 知识答案

正文结果只展示 Artifact 的结论和关键可交付内容，不混入过多过程产物。

## 9. Dataki 知识库使用原则

Dataki 不是只在最后补知识。

Dataki 应该贯穿：

- 意图消歧
- 业务词解释
- SOP 选择
- 缺参追问
- MCP 工具选择
- 结果校验
- 回答引用
- 经验沉淀

典型场景：

- 用户说“应用列表”，知识库帮助区分智投应用、媒体应用、项目应用。
- 用户问归因、回传、指标、出包规范，知识库提供标准口径。
- 用户发对接文档，知识库沉淀对接经验。
- 行业动态采集后，知识库作为后续追情报和行业分析的来源。

## 10. 动态推荐

动态推荐是小乔主动服务能力的体现，不是传统菜单。

推荐来源：

- 当前项目
- 最近异常
- 最近任务
- 最近日报
- 包状态
- 联调状态
- 行业情报
- 榜单变化

示例：

- 昨日 ROI 异常，是否分析原因？
- 有 3 个包已通过检测，是否输出交付投放清单？
- AppLovin 对接文档有更新，是否生成影响分析？
- 小游戏畅玩榜变化明显，是否查看近 7 日趋势？
- 你上次创建的日报模板还未完成，是否继续？

## 11. 后台配置边界

后台可以存在，但不是业务用户主路径。

后台承接：

- MCP 工具配置
- Dataki 知识库配置
- 行业动态信源配置
- 采集频率
- 去重规则
- 标签体系
- 日报模板
- 报表模板
- Prompt 模板
- Agent 路由规则
- 任务日志
- 权限配置

前台不能把这些后台能力作为一级入口暴露给普通业务用户。

## 12. v1 成功定义

v1 不以“能聊天”为成功标准。

v1 成功标准：

1. 用户第一次进入页面，能明确知道小乔是谁、能帮什么、怎么开始。
2. 用户可以从 7 个工作意图入口进入标准任务模板。
3. 用户自然输入问题时，小乔能识别是否进入验流程、查异常、看数据、拼报表、提需求、问逻辑或追情报。
4. 需要项目、时间、媒体、指标等上下文时，小乔能只追问必要信息，不重来一遍。
5. 能调用 MCP 和 Dataki，而不是只返回模型编造结果。
6. 过程展示和最终正文分层，不把过程产物堆进最终回复。
7. 长周期任务有状态和结果沉淀。
8. 行业动态归入追情报，不作为前台复杂菜单。
9. 用户不需要理解底层工具链，也能完成投放服务任务。
10. 数据、产品、测试、开发沉淀的支持能力可以通过 Agent / Skill / Workflow 复用。

## 13. 版本拆解建议

### v1.0：服务台定位统一

目标：

- 统一命名为“小乔智投：AI 投放服务台”。
- 首页欢迎语、入口说明、7 个入口完成口径统一。
- 旧的“智投Chat”“AI 数据BP”不再作为前台定位出现。
- 行业动态并入“追情报”。

### v1.1：意图入口与标准模板稳定

目标：

- 7 个入口点击后稳定带入标准模板。
- 自然语言输入能进入对应 Agent。
- 对缺参、歧义、工具选择做统一追问。

### v1.2：任务与结果承载

目标：

- 长周期任务不再只放在聊天流里。
- 任务状态、最近结果、订阅任务开始沉淀。
- 自动联调、定时报表、行业追踪有统一任务模型。

### v1.3：主动推荐

目标：

- 根据项目、异常、日报、包状态、联调状态、行业变化生成动态推荐。
- 从被动问答升级为主动服务。

## 14. 关键底线

- 不要叫“数据BP”，叫“小乔智投：AI 投放服务台”。
- 不要叫“Chat”，避免把产品限制在聊天问答。
- 不要叫“中台”，避免前台用户感知复杂。
- 前台用工作意图组织入口，不使用传统菜单。
- 用户不需要理解 MCP、Dataki、RAG、Workflow 等内部实现。
- 行业动态归入“追情报”，不是一级菜单。
- 最终正文只交付结论和结果，过程放在思维链、动态组件和来源日志中。
