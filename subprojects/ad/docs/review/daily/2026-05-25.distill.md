# 2026-05-25 蒸馏：今天的核心是把“能打开”变成“不会被旧登录态困住”

## 一句话结论

今天最重要的收获不是新增功能，而是修正了登录态闭环：旧 token 不能再把用户困在 `/login` 和首页之间的循环里。

## 蒸馏后的判断

1. **登录态失败必须是可恢复状态**
   - 失效 cookie 不应继续参与路由判断。
   - 首页认证失败后必须主动清理本地状态。
   - 用户应回到可重新登录的页面，而不是停在“正在进入”。

2. **路由守卫不能只判断 token 是否存在**
   - token 存在不代表有效。
   - `/login` 是恢复入口，不应该被旧 token 拦截。
   - 管理页和受保护 API 可以继续做严格校验，但登录页需要保持可达。

3. **外部认证依赖必须有时间边界**
   - 服务端请求如果没有超时，会放大外部服务慢请求的影响。
   - 客户端 8 秒超时不足以覆盖服务端悬挂。
   - 认证服务调用需要服务端和客户端都具备失败出口。

4. **当前阶段的工作重心正在从能力堆叠转向体验闭环**
   - 5 月 22 日主要是上下文、角色、报表、路由、管理能力的系统性合并。
   - 5 月 24-25 日更多是在补齐真实使用中的边界：登录、复制、输入、筛选、重命名、保存、移动端截图。

## 今天沉淀的问题模式

- 不要把“有 cookie”当成“已登录”。
- 不要让登录页成为受保护页面的一部分。
- 不要把外部服务等待交给用户感知。
- 不要让 UI 修复、认证修复、文档材料长期混在一个未提交工作区里。

## 下一步优先级

1. 先提交登录闭环修复。
2. 再拆分 Chat UI 体验调整。
3. 单独清理登录链路乱码文案。
4. 将 PRD v2.2 文档包与截图验收材料纳入阶段 checkpoint。
