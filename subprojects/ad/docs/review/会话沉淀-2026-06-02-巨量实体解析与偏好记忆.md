# 会话沉淀：巨量实体解析与个人偏好记忆

- 日期：2026-06-02
- 范围：报表问数中的媒体实体解析、个人偏好记忆、跨会话上下文复用
- 状态：已实现，代码快照已进入 `d4bbefb`

## 问题背景

用户提到“巨量”或“巨量广告”时，实体解析会反复要求在“巨量广告、抖音游戏、巨量云游戏、UC头条”中确认。这个候选列表来自媒体实体字典和归一化候选匹配，但默认映射和用户偏好没有足够快地参与解析，导致同一用户的重复选择没有被系统记住。

## 决策

- 后台实体解析配置中明确“巨量”类别名默认归一到“巨量广告”。
- 问数提示词增加默认媒体映射说明，避免模型在没有明确上下文时把“巨量”扩散成多个业务线。
- 用户点击候选实体后，将选择写入个人偏好记忆。
- 偏好记忆按登录用户范围生效，不再退化为单会话范围，确保新会话也能复用。
- 报表编排在实体归一化前读取个人偏好，并对历史选择候选进行加权，但保留上下文明显指向其他媒体时的纠偏空间。

## 已落地

- `entity-resolution-config-store` 对媒体别名做默认归一，命中“巨量、巨量引擎、巨量广告、抖音、头条、oceanengine”等口径时默认 canonical 为“巨量广告”。
- `prompt-store` 与 `managed-prompt-seeds` 补充默认媒体映射说明。
- `chat/route` 在用户选择候选实体后写入 `entity-selection` 偏好记忆。
- `compileChatContext` 和报表问数输入使用登录用户范围作为 `userScopeKey`，让偏好跨会话参与解析。
- `report-query-orchestrator` 将偏好候选传给字典实体解析。
- `entity-resolution` 对偏好候选进行置信度加权，减少重复确认。
