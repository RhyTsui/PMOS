# 智投 Chat 主色与辅助色局部定义

> 2026-05-27 更新：本文保留为 5 月 24 日局部色彩落地记录。最新色彩、字体、前端自主渲染和硬编码治理口径，以 `docs/review/智投Chat-前端自主渲染与色彩字体系统-2026-05-27.md` 为准。

本文只约束智投 Chat 当前对话工作台的局部色彩使用，不作为 PMOS 全局规范替换，不触发全局换色。

## 色彩定义

| 类型 | 色值 | 使用位置 | 影响边界 |
| --- | --- | --- | --- |
| 主色 | `#2E75FE` | 主操作、发送按钮、输入框焦点、可执行建议高亮 | 仅用于智投 Chat 高频交互 |
| 主色浅底 | `rgba(46, 117, 254, 0.05)` / `0.10` / `0.14` | hover、选中态、弱提示底色 | 不改变正文阅读区底色 |
| 成功色 | `#00B368` | 复制成功、执行完成、校验通过 | 只表达完成或通过 |
| 警示色 | `#D49600` | 待确认、可继续但存在条件限制 | 不用于危险删除 |
| 危险色 | `#E0204A` | 失败、阻断、删除或不可逆风险 | 只用于需要用户谨慎判断的动作 |
| 信息色 | `#6B46E0` | 信息提示、需求/知识/辅助说明 | 不抢主操作优先级 |
| 文字主色 | `#10233F` | 标题、关键结果 | 不用于弱提示 |
| 文字正文 | `#355070` | 对话正文、结果说明 | 保持长文本可读性 |
| 文字次级 | `#6B7C93` / `#8EA0B8` | 说明、meta 信息、弱提示 | 保持对话阅读层级 |
| 背景与边框 | `#F8FAFC` / `#FFFFFF` / `rgba(46, 117, 254, 0.08)` | 页面背景、卡片、弱边框 | 不制造新的大面积色块 |

## Token 映射

智投 Chat 局部色彩统一从 `src/lib/zhitou-chat-colors.ts` 引用。新增 UI 若属于对话工作台、输入区、结果区、资产引用、证据区或建议动作，默认不得在组件内重新定义同义色值。

| token | 色值 | 用途 |
| --- | --- | --- |
| `primary` | `#2E75FE` | 主操作、输入框焦点、发送按钮、可执行建议高亮 |
| `primaryHoverBg` | `rgba(46, 117, 254, 0.14)` | 主操作 hover、当前选中项强提示 |

| `primaryBorderSubtle` | `rgba(46, 117, 254, 0.16)` | 弱主色边框 |

| `danger` | `#E0204A` | 失败、阻断、删除或不可逆风险 |
| `info` | `#6B46E0` | 信息提示、需求/知识/辅助说明 |

## 使用原则

1. 主色只服务“可以推进任务”的交互，不用于大面积装饰背景。
2. 辅助色只表达状态语义：成功、警示、危险、信息，不能混用。
3. 对话正文优先使用中性文字色，避免蓝色正文造成“全页面都是主色”的问题。
4. 新增局部 token 位于 `src/lib/zhitou-chat-colors.ts`，后续单点优化可逐步引用，不要求一次性替换历史色值。

## 硬编码治理

1. 新增或重写智投 Chat 用户可见组件时，禁止直接写入与本规范同义的十六进制、rgb、rgba、hsl 色值；必须引用 `ZHITOU_CHAT_COLORS` 或 Ant Design 主题 token。
2. 允许局部硬编码的例外只包括：第三方图表库入参、不可控内联 SVG 资源、品牌图片资源、一次性静态验收 HTML。例外必须在同文件附近写明原因，且不得扩散为组件通用色值。
3. 若发现历史组件已有硬编码色值，不要求为了本次局部改动一次性全量替换；但只要触达同一交互区域，应把新增色值收口到 token，避免继续扩大分散定义。
4. 不允许在不同组件里为同一语义新增近似色，例如 `#2f76ff`、`#2e74fe`、`rgba(46,117,254,.12)`。需要新色阶时先补本规范和 `ZHITOU_CHAT_COLORS`。
5. 新色阶必须按语义命名，不按视觉形容命名。推荐命名：`primarySoftBg`、`textMuted`、`borderFaint`；不推荐命名：`blue1`、`lightBlue`、`grayNew`。
6. 色值调整优先改 token，不在调用组件内覆盖；确需局部覆盖时，应说明该覆盖服务的用户状态或交互语义。

## 新增色阶准入

新增 token 前必须同时满足：

1. 现有 token 无法表达该状态或层级。
2. 新色值有明确使用语义、使用边界和不可使用场景。
3. 已检查桌面端与移动端可读性，不造成正文、按钮、提示、边框之间的层级混乱。
4. 已确认不会把页面带回单一蓝色、单一紫色或装饰性色块过重的视觉方向。

新增 token 后必须同步更新：

- `src/lib/zhitou-chat-colors.ts`
- 本规范的 `Token 映射`
- 如涉及可视验收，更新 `docs/review/zhitou-chat-color-spec-2026-05-24.html` 或新增对应截图/验收记录

## 本次落地

- 新增 `ZHITOU_CHAT_COLORS` 与 `ZHITOU_CHAT_COLOR_USAGE`。
- 将输入框内已存在的品牌蓝常量改为引用局部 token。
- 未修改全局主题、页面背景、消息气泡、管理页或其他模块颜色。

## 验收口径

- 色板能明确展示主色、成功、警示、危险、信息、文字和背景边界。
- 输入框主操作仍维持现有视觉，不发生全局换色。
- 后续 UI 验收若要调整色值，只需改局部 token 或继续按单点确认推进。
- 新增或触达的智投 Chat 用户可见组件，不继续引入与本规范同义的硬编码色值。
- Review 时若发现新硬编码色值，结论应标为 `partial` 或 `unsolved`，除非属于本文定义的例外并已说明原因。
