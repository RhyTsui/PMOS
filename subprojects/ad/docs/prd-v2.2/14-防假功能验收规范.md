# 防假功能验收规范

## 1. 什么是假功能

假功能是指前台或 Chat 呈现了“已经完成”的业务结果，但底层没有真实 Workflow / Skill / MCP / 智投接口支撑，或者没有真实数据、证据、状态和记录。

V2.2 的验收重点之一，就是防止假功能进入一期。

## 2. 十类禁止行为

以下情况均视为假功能：

1. 没有调用真实服务，却返回已执行结果。
2. 没有真实数据，却生成具体指标数值。
3. 没有上报报告，却说上报检查通过。
4. 没有联调结果，却说联调成功。
5. 没有媒体后台检测，却说新包已更新。
6. 没有资产写入，却提示已保存。
7. 没有 Case 写入，却提示已提交。
8. 没有项目权限校验，却展示项目数据。
9. 没有内部口径库，却强答内部指标口径。
10. 能力未接入，却使用已完成口吻回复。

## 3. 每个能力上线前必须具备

每个能力进入 `available` 前必须具备：

- 能力注册项。
- 绑定 Workflow / Skill / MCP / 智投接口。
- 入参模型。
- 出参模型。
- 状态定义。
- 错误码。
- Evidence。
- 权限检查。
- Trace。
- 资产或 Case 规则。
- 前台结果呈现方式。

## 4. 能力状态验收

`available`：必须能真实执行并返回证据。
`partially_available`：必须明确哪些环节可执行，哪些环节缺失。
`planned`：不能在用户侧展示为可完成。
`disabled`：必须有不可用原因或替代建议。

## 5. 一期 P0 验收矩阵

一期 P0 必须验收：

- 数据查询真实调用。
- 数据来源和更新时间展示。
- 查询结果保存规则。
- 报表草稿默认不保存。
- 定时报表创建必须确认数据延迟策略。
- 定时报表产物默认入资产。
- 包交付单项目。
- 上报检查调用真实 MCP。
- 联调结果调用真实能力。
- 联调失败生成 Case。
- 指标解释内部口径库优先。
- 会话、资产、自动化项目权限过滤。
- Trace 发送到连弩。

## 6. 验收口径

能力已接入时，可以说“已查询”“系统检查结果显示”。
能力部分接入时，必须说“已完成可用部分检查，以下环节暂未接入”。
能力未接入时，必须说“当前还没有接入可执行服务，不能直接给出最终结论”。
无权限时，必须明确“你当前没有该项目权限”。
