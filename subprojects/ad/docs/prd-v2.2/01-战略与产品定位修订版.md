# 战略与产品定位修订版

## 1. 产品定位

小乔智投定位为：

> 面向广告投放、发行协同、数据分析和流程交付的 AI 投放服务台与任务运行工作台。

它不是通用 ChatBot，也不是一个把所有能力硬写进 Chat 的大模型应用。它的价值是把投放支持工作从口头沟通、人工查数、人工追包、人工排查，升级为可路由、可追问、可调用真实能力、可沉淀证据、可追踪状态、可复用资产的服务闭环。

## 2. 北极星指标

北极星指标定义为：

> 可证据化完成的投放支持任务数。

这里的“完成”不是 Chat 回复一段话，而是满足最低闭环：

1. 正确识别用户意图。
2. 自动补齐已知上下文。
3. 信息不足时追问。
4. 调用真实 Workflow / Skill / MCP / 智投接口。
5. 正确解析执行结果。
6. 输出业务结论和下一步建议。
7. 提供证据来源。
8. 记录 Trace。
9. 按规则沉淀资产、任务、Case 或报表。
10. 系统无力完成时，多轮确认后生成 Case，并告知等待处理。

## 3. 一期产品目标

一期目标是可信服务闭环，不是完整数字优化师。

一期要优先打透三条后端业务闭环：

1. 数据与报表闭环
   覆盖查数、拼报表、报表草稿、报表模板、定时报表、资产保存。

2. 包交付与流程状态闭环
   覆盖包状态、上报检查、媒体后台更新、智投后台更新、联调检查、旧包归档、失败 Case。

3. 异常 / 需求 / 指标逻辑轻闭环
   覆盖异常排查、需求结构化、指标口径解释、知识库查询、无法完成时生成 Case。

一期还要建立两个公共基础：

- 我的资产：承接查询结果、报表、定时报表产物、包交付记录、Case、证据集合。
- 低风险自动化任务中心：优先承接定时报表，后续扩展为定时触发 Skill、包状态巡检、小闪通知等。

## 4. 阶段边界

### 一期

一期必须完成：

- 数据查询真实闭环。
- 拼报表和报表草稿。
- 定时报表。
- 我的资产保存和项目权限过滤。
- 包交付状态查询。
- 上报检查。
- 联调状态解释。
- 联调失败生成 Case。
- 指标口径解释内部优先。
- 角色和项目权限进入主链路。
- Trace 发送到连弩。
- 当前已实现能力纳入统一产品结构。

### 二期

二期做市场情报和外部行业知识融合：

- 行业动态。
- 投放方法论。
- 市场情报报告。
- 内外融合分析。

二期能力不能混入一期核心验收。当前前台已有市场情报入口时，应标为有限支持或后续能力。

### 三期

三期做预测和策略沙盘：

- 投放效果预测。
- 风险模拟。
- 策略对比。
- 决策辅助。

### 四期

四期做受控自动化执行：

- 审批驱动的投放动作。
- 高风险动作确认。
- 多 Agent 协同。
- 受控自动优化。

## 5. 通用能力与内部能力的融合策略

小乔智投不应把通用问题全部拒绝，也不应把外部知识和内部事实混为一谈。

系统策略是按问题类型决定来源：

| 问题类型 | 策略 |
|---|---|
| 内部项目数据 | 只查内部数据源，不外部联网 |
| 内部指标口径 | 内部口径库优先 |
| 内部专业术语 | 先查内部词典、口径库、知识库 |
| 行业通用知识 | 可以联网补充 |
| 投放方法论 | 可外部检索，再结合内部业务约束 |
| 执行动作 | 必须走内部权限、Workflow、Skill 和工具 |
| 内外冲突 | 内部事实优先，外部仅作为参考 |

例如用户问“今天天气如何”，如果企业策略允许通用能力，Chat 可以联网回答并标注来源，但不沉淀为业务资产。
用户问“2026 年投放最新方法论”，可以联网补充行业资料，再结合内部业务场景给建议，但不能伪造内部项目数据。
用户问“ROI 怎么算”，必须先查内部口径库，外部解释只能补充行业概念。

## 6. 长期形态

长期形态可以是数字优化师和多 Agent 协作系统，但当前不能把这个愿景提前写成一期承诺。

当前最优路线是：

1. 先建立可信服务台。
2. 再扩展市场情报。
3. 再进入预测和策略沙盘。
4. 最后进入受控自动化执行。
