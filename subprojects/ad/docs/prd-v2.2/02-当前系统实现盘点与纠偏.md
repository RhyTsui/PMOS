# 当前系统实现盘点与纠偏

## 1. 文档目的

本文件把当前系统已经实现的能力纳入 PRD V2.2。后续需求不是从零开始，也不能因为重写 PRD 而遗漏已有能力。

同时，本文件明确当前实现和目标产品之间的偏差。已经存在的入口、Agent、路由、工具或页面，如果没有真实 Workflow / Skill / MCP / 智投接口承接，不能被视为闭环完成。

## 2. 当前已实现能力

### 2.1 前台与 Chat 基础

当前已经有统一 Chat 入口、推荐问题、角色化体验、我的资产入口、自动化入口等基础。推荐问题中已经覆盖数据分析、报告生成、投放交付、异常排查、指标解释、市场情报和业务协同等方向。

处理方式：

- 保留统一 Chat 入口，作为所有服务的第一入口。
- 保留推荐问题，但根据阶段边界调整展示和可执行状态。
- 市场情报和预测类入口不能作为一期核心能力。
- 我的资产和自动化入口需要升级为项目权限感知能力。

### 2.2 Agent / 能力域配置

当前系统已有 10 个 Agent / 能力域：

- hub
- help
- report
- demand
- diagnosis
- debugging
- delivery
- monitoring
- material
- prediction

处理方式：

- 保留为能力域和路由对象。
- 不把它们表述为“多智能体闭环已经完成”。
- 每个能力域必须绑定可执行 Workflow / Skill / MCP，才能进入可执行状态。

### 2.3 意图路由与规则

当前已有 `intent-router`、`intent-route-rules`、`intent-route-engine` 等基础，可以识别 `report_query`、`demand`、`diagnosis`、`debugging`、`get_delivery_packages`、`monitor`、`material-analysis`、`forecast`、`help`、`general` 等意图。

当前偏差：

- 路由命中不等于真实能力完成。
- 主 Chat 链路真实执行主要集中在 `report_query`。
- 其他意图容易进入兜底或展示层，而非真实闭环。
- 受控术语词典已经沉淀为知识资产，但尚未作为路由前置归一化服务贯穿主链路。
- prompt-store 已有提示词治理基础，但主路由链路尚未把 prompt 版本、输入输出和能力发现绑定为可追踪判断。

纠偏要求：

- 路由结果必须增加能力注册和能力状态。
- 每个可执行意图必须绑定 Workflow / Skill。
- 能力未接入时，Chat 不能输出已执行口吻。
- 增加术语归一化、候选意图、能力发现和追问阶段的 Trace。
- 按 `18-意图路由知识库与能力闭环设计准入评估.md` 补齐第三阶段设计准入。

### 2.4 Context Compiler 与 Slot Resolver

当前已有上下文编译和槽位解析基础，能够处理角色、偏好、业务上下文、槽位状态和路由提示。

当前偏差：

- 项目权限、资产上下文、知识库摘要、历史会话默认项目等还需要正式纳入。
- 主 Chat 执行链路对 roleProfile 的使用不完整。
- 能力发现结果尚未成为 slot 补齐的前置约束。

纠偏要求：

- 路由前必须编译用户、角色、项目、权限、会话、资产、页面上下文。
- 槽位补齐必须基于能力可执行性，不要先追问一堆最终无法执行的信息。
- 受控术语归一化结果和能力注册结果必须进入上下文编译产物。

### 2.5 角色体系

当前已有 `role-profile-store` 和智投角色映射。角色包括设计师、优化师、观察员等。

当前偏差：

- 角色配置存在，但没有完整贯穿路由、权限预检、执行动作和结果展示。

纠偏要求：

- 优化师默认可触发联调相关能力。
- 观察员以只读为主，不触发高风险动作。
- 设计师以素材、创意、需求协同为主。
- 所有角色都要叠加项目权限，不允许只按角色放行。

### 2.6 问数链路

当前 `report_query` 已经具备真实执行基础，会创建 Workflow Task / Run，调用报表查询步骤，写入 Workflow Result，并发送 Trace。

处理方式：

- 作为一期闭环样板。
- 补齐项目权限、资产保存、报表草稿、定时报表、数据延迟策略。
- 其他链路参考问数链路的执行、证据和 Trace 方式建设。

### 2.7 报表、草稿和定时任务

当前已有 report template、report draft、scheduled task、automation template 等基础。

当前偏差：

- 报表草稿定义不清。
- 定时报表创建缺少数据延迟策略。
- 定时报表产物是否默认进入资产未统一。
- 报表模板是否跨项目复用未统一。

纠偏要求：

- 报表草稿是临时工作态，默认不保存。
- 报表模板可跨项目复用，运行时绑定项目并校验权限。
- 定时报表创建必须确认数据延迟策略。
- 定时报表和自动化产物默认进入资产。

### 2.8 Debug Automation

当前已有 Debug Automation、联调/调试自动化服务、任务观察、运行时能力等基础。

当前偏差：

- Debug Automation 更像工具和底层能力，不是完整包交付产品。
- 不能把一次调试成功直接等同于“包可交付投放”。

纠偏要求：

- Debug Automation 纳入联调检查 Skill。
- 联调检查 Skill 纳入包交付 Workflow 和异常诊断 Workflow。
- 包交付结论必须由包状态、上报检查、后台更新、联调检查和证据共同派生。

### 2.9 Trace 与连弩

当前已有 Trace 配置和发送基础。

处理方式：

- 小乔不重建评测平台。
- Trace、评测、回放、证据规则进入连弩平台。
- 小乔需要补齐项目、角色、意图、Workflow、Skill、MCP、Evidence、Asset、Case 等字段。

### 2.10 我的资产

当前已有入口和部分体验基础。

当前偏差：

- 资产类型、写入规则、项目字段、权限过滤、自动化产物、Case 引用需要统一。

纠偏要求：

- 一次查询结果只有用户保存后进入资产。
- 报表草稿默认不保存。
- 自动化和定时报表产物默认进入资产。
- 包交付记录、Case、证据集合可沉淀为资产。
- 资产必须支持项目查看、筛选和动态权限隐藏。

## 3. 禁止继续扩展的方向

以下方向必须停止：

- Chat 直接生成包可投结论。
- Chat 模拟联调结果。
- Chat 模拟上报检查通过。
- 没有真实数据时生成具体指标。
- 没有内部口径库时强答内部指标。
- 没有写资产却提示已保存。
- 没有生成 Case 却提示已提交。
- 没有项目权限检查却展示历史项目数据。
- 把市场情报和预测混入一期 P0。
- 把 Agent 名称当成真实执行能力。
