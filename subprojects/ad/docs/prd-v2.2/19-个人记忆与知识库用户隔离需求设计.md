# 个人记忆与知识库用户隔离需求设计

## 1. 文档目的

本文件补齐个人记忆、通用知识库、个人知识库、用户隔离和 RAG 检索的需求定义。它解决一个已经暴露的核心问题：系统从单用户演示演进到多用户隔离后，原有个人记忆如果仍使用默认用户、默认知识库 key 或固定知识库名称，就会造成记忆错写、检索串库、用户价值不可验证和前台假保存。

本文件不是要求小乔自建知识库平台。小乔只负责用户配置、记忆抽取、同步调用、检索编排、来源标注和结果呈现；知识库平台仍由 Dataki / 现有知识库服务承接。

## 2. 当前实现核对

当前系统已有基础：

- `user-scope` 已能从登录态生成用户作用域 key。
- `user-memory-store` 已有记忆本地存储、列表、搜索、归档和同步状态字段。
- `/api/xiaoqiao/memory` 已有记忆增删改查和同步接口。
- `dataki-memory-sync` 已能把记忆同步到 Dataki 知识库。
- `runtime-config` 已有全局模型与知识库服务配置。
- Chat 前台已有“保存到个人知识库”的交互入口。

当前问题：

- 记忆默认用户仍存在 `user-001` 兜底。
- Debug 多轮上下文仍有硬编码 `MEMORY_USER_ID = 'user-001'`。
- Dataki 记忆同步中存在固定名称 `小乔智投-徐韵-记忆库`。
- 知识库 key 当前主要是全局配置，不支持普通用户配置个人知识库 key。
- “保存到个人知识库”已补充真实 `POST /api/xiaoqiao/memory` 保存和 `DELETE /api/xiaoqiao/memory/{id}` 取消入口，但仍缺少按登录用户强制隔离、用户级个人知识库 Key、真实同步状态分层和 RAG 来源统一标注。
- 通用知识库、个人知识库、个人记忆、资产收藏之间边界不清。

## 3. 产品策略

一期采用“通用知识库 + 个人知识库”并行策略：

- 通用知识库：由超管维护，使用系统级知识库 key，所有用户可读，用于业务 SOP、通用口径、受控知识和组织共识。
- 个人知识库：由用户在右下角弹窗自助配置 key，用于个人记忆、个人收藏、个人确认过的上下文和个人 RAG。
- 个人记忆：小乔从用户操作和对话中沉淀的轻量结构化记忆，必须按用户隔离。
- 资产：正式业务产物，例如报表、定时报表结果、包交付记录、Case 和证据包，不等同于个人记忆。

没有个人知识库 key 时，个人记忆仍可写入本地用户作用域，但不能提示“已同步到个人知识库”。系统应提示“已保存到个人记忆待同步区，配置个人知识库 key 后可同步检索”。

## 4. 右下角知识库入口

右下角弹窗应增加“知识库”按钮。入口职责是让用户理解并管理个人知识库连接，不承担完整知识库管理平台能力。

弹窗内容：

- 通用知识库状态：可用、不可用、最近检测时间。普通用户不展示超管 key。
- 个人知识库状态：未配置、已配置、验证失败、同步中、最近同步成功。
- 知识库跳转地址：打开 Dataki / 知识库平台。
- 个人知识库 key：填写、保存、测试、清除。
- 个人知识库 ID：可选填写；不填时系统可用 key 自动发现可访问知识库。
- 最近一次同步：时间、同步记忆数、失败原因。
- 操作：测试连接、同步我的记忆、清除个人配置。

交互原则：

- key 输入框默认脱敏，支持重新填写覆盖。
- 清除个人 key 只停止后续同步，不自动删除远端知识库文档。
- 测试失败不影响通用知识库检索。
- 普通用户不能修改系统通用知识库配置。

## 5. 个人记忆价值定义

个人记忆一期要同时体现两类价值。

### 5.1 多轮上下文续接

系统应记住：

- 用户常用项目、媒体、应用和终端。
- 用户在联调、排查、报表中的已确认字段。
- 用户偏好的分析维度、报表样式和输出格式。
- 用户最近未完成的任务上下文。

使用方式：

- 自动补齐低风险上下文。
- 高风险动作前展示“沿用上次确认信息”，必要时请用户确认。
- 不把个人记忆当成公司事实。

### 5.2 个人知识沉淀与 RAG

用户主动保存的内容、确认过的经验、常用排查说明和个人工作备注，可以进入个人知识库。

使用方式：

- 检索时标注来源为个人记忆或个人知识库。
- 回答中使用“你之前保存过 / 你之前确认过”的表达。
- 用户可追溯到保存时间、来源会话和同步状态。

价值验证指标：

- 记忆保存次数。
- 同步成功率。
- 个人 RAG 命中次数。
- 回答引用个人记忆次数。
- 因个人记忆减少追问次数。
- 用户删除或修正记忆次数。

## 6. 保存到个人知识库闭环

点击“保存到个人知识库”时，系统必须真实执行，不允许只前端高亮。

标准流程：

1. 解析当前登录用户，生成 `user_scope_key`。
2. 创建个人记忆记录。
3. 判断用户是否配置个人知识库 key。
4. 已配置且验证通过：同步到个人知识库。
5. 未配置或验证失败：保留本地待同步状态。
6. 返回 `memory_id`、`sync_status`、`knowledge_base_id`、`document_id` 或失败原因。
7. 前台按真实状态展示。

前台口径：

- 同步成功：`已保存到个人知识库，并可用于后续个人检索。`
- 未配置 key：`已保存到个人记忆待同步区。配置个人知识库 key 后，可同步到你的知识库。`
- 同步失败：`已保存到个人记忆，但同步知识库失败：{原因}。`

## 7. RAG 检索策略

一期 RAG 来源分层：

| 来源 | 作用 | 权限 | 是否可写 |
|---|---|---|---|
| 受控术语词典 | 路由前归一化 | 全员可读 | 仅管理员维护 |
| 通用知识库 | SOP、通用口径、业务知识 | 全员可读 | 仅超管 / 管理员维护 |
| 个人记忆 | 多轮上下文、个人偏好 | 仅本人 | 系统和本人可写 |
| 个人知识库 | 用户保存内容和个人沉淀 | 仅本人 | 本人可写 |

检索优先级不能简单固定为个人或通用优先，应按问题类型决定：

- 内部术语：先受控术语词典，再通用知识库。
- 指标口径：先内部口径库 / 通用知识库，再外部补充。
- 用户个人偏好、历史确认信息：先个人记忆。
- 用户主动保存过的知识：个人知识库可参与。
- 项目数据、包状态、联调结果：不能靠知识库回答，必须走内部工具。

回答必须标注来源类型：

- `controlled_glossary`
- `system_common_knowledge`
- `personal_memory`
- `personal_knowledge`
- `tool_result`
- `external_source`

## 8. 数据模型

### 8.1 UserKnowledgeConfig

```ts
type UserKnowledgeConfig = {
  user_scope_key: string
  enabled: boolean
  knowledge_base_url: string
  knowledge_base_api_key_masked: string
  knowledge_base_id?: string
  jump_url?: string
  status: 'not_configured' | 'valid' | 'invalid' | 'disabled'
  last_tested_at?: string
  last_sync_at?: string
  last_error?: string
  updated_at: string
}
```

服务端必须加密或安全存储原始 key。前端和普通接口只返回 masked key。

### 8.2 PersonalMemoryRecord

```ts
type PersonalMemoryRecord = {
  memory_id: string
  user_scope_key: string
  content: string
  memory_type: 'preference' | 'context' | 'fact' | 'saved_message' | 'workflow_hint'
  source: 'auto_extract' | 'user_save' | 'agent_summary' | 'system_default'
  source_conversation_id?: string
  source_message_id?: string
  project_refs?: string[]
  keywords: string[]
  importance: number
  sync_status: 'pending' | 'synced' | 'failed' | 'skipped'
  knowledge_base_id?: string
  document_id?: string
  last_error?: string
  created_at: string
  updated_at: string
}
```

### 8.3 RagSourceRef

```ts
type RagSourceRef = {
  source_type:
    | 'controlled_glossary'
    | 'system_common_knowledge'
    | 'personal_memory'
    | 'personal_knowledge'
    | 'tool_result'
    | 'external_source'
  title: string
  source_ref?: string
  user_scope_key?: string
  project_refs?: string[]
  captured_at?: string
  summary: string
}
```

## 9. API 需求

新增或调整以下接口：

- `GET /api/xiaoqiao/user/knowledge-config`
- `PUT /api/xiaoqiao/user/knowledge-config`
- `POST /api/xiaoqiao/user/knowledge-config/test`
- `POST /api/xiaoqiao/memory`
- `GET /api/xiaoqiao/memory/search`
- `POST /api/xiaoqiao/memory/sync`

关键约束：

- API 不再信任前端传入的任意 `user_id` 作为隔离依据。
- 所有用户级接口必须从登录态解析 `user_scope_key`。
- 管理员可查看配置状态，但不能明文查看用户 key。
- 系统通用 key 只用于通用知识检索，不用于写入个人记忆。
- 个人 key 只用于当前用户的个人知识库同步和个人 RAG。

## 10. 历史数据处理

已有 `user-001` 记忆不能继续作为全员默认记忆。

处理方案：

- 标记为 legacy 记忆。
- 若能识别真实用户，则迁移到对应 `user_scope_key`。
- 无法识别用户时，默认只允许超管审查，不进入普通用户检索。
- 固定名称“徐韵记忆库”应改为按用户作用域生成，例如 `小乔智投-{user_scope_key}-记忆库`，前台展示可用用户昵称脱敏。

## 11. 验收标准

- 用户 A 保存个人记忆后，用户 B 无法检索到。
- 未配置个人 key 时，保存只进入待同步区，不提示已同步。
- 配置错误 key 时，测试失败并展示原因，不影响通用知识库检索。
- 配置正确 key 后，个人记忆可同步到用户个人知识库。
- 通用知识库可被所有用户检索，但普通用户不能写入。
- RAG 回答能区分通用知识、个人记忆、个人知识库来源。
- 清除个人 key 后，新增记忆不再同步，旧本地记忆仍按用户隔离可见。
- 历史 `user-001` 记忆不会默认暴露给所有用户。

## 12. 工程优先级

P0：

- 去除个人记忆主链路中的 `user-001` 硬编码。
- 新增用户级知识库配置。
- 修正“保存到个人知识库”为真实 API 调用。
- 同步结果和失败原因进入前台反馈。
- 通用知识库和个人知识库来源标注。

P1：

- 个人 RAG 检索进入 Chat 上下文。
- 记忆价值指标统计。
- 记忆管理列表、删除、归档和重新同步。
- 历史 legacy 记忆迁移工具。

后续：

- 个人记忆自动抽取策略优化。
- 记忆冲突处理。
- 个人知识库容量、过期和清理策略。
