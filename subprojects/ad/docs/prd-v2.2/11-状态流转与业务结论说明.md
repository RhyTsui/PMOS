# 状态流转与业务结论说明

## 1. 通用 Workflow 状态

所有 Workflow 应统一使用以下基础状态：

- `created`：已创建。
- `waiting_input`：等待用户补充信息。
- `running`：运行中。
- `waiting_external`：等待外部系统状态变化。
- `succeeded`：完成。
- `partially_succeeded`：部分完成。
- `failed`：失败。
- `cancelled`：取消。

Chat 展示时不应直接把工程状态暴露给用户，而应转成用户能理解的进展说明。

## 2. 数据查询状态

数据查询状态：

- 已接收问题。
- 等待补充项目 / 时间 / 指标。
- 查询中。
- 查询成功。
- 查询部分成功。
- 查询失败。
- 等待用户保存或转报表。

查询成功后不默认写资产，只有用户保存后才进入资产。

## 3. 报表草稿状态

报表草稿状态：

- 草稿生成中。
- 草稿已生成。
- 等待用户调整。
- 已保存为报表。
- 已保存为模板。
- 已转为定时报表。
- 已丢弃。

草稿默认不保存。用户离开或结束时，不应把草稿自动变成资产。

## 4. 定时报表状态

定时报表状态：

- `draft`：配置草稿。
- `waiting_delay_policy`：等待确认数据延迟策略。
- `active`：已启用。
- `running`：本次运行中。
- `succeeded`：本次运行成功。
- `failed`：本次运行失败。
- `paused`：暂停。

未确认数据延迟策略时，不能进入 `active`。

## 5. 包交付流程状态

包交付流程状态：

- `waiting_package`：等待出包。
- `report_checking`：上报检查中。
- `report_check_failed`：上报不通过。
- `waiting_submission`：等待提审。
- `waiting_media_backend_update`：等待媒体后台更新。
- `waiting_zhitou_backend_update`：等待智投后台更新。
- `integration_checking`：联调检查中。
- `integration_failed`：联调不通过。
- `integration_success`：联调成功。
- `replaced_by_new_package`：已被新包替代。
- `historical_traceable`：历史可追溯。

## 6. 包交付业务结论

包交付业务结论：

- `deliverable`：可交付投放。
- `not_recommended`：不建议交付。
- `pending`：待处理。
- `risk_attention`：风险待关注。
- `historical`：历史包。

流程状态和业务结论要分开。例如“联调检查中”是流程状态，“待处理”是业务结论；“联调不通过”是流程状态，“不建议交付”或“风险待关注”是业务结论。

## 7. 媒体包首次状态流

正常流：

```text
waiting_package
→ report_checking
→ waiting_submission
→ waiting_media_backend_update
→ integration_checking
→ integration_success
```

上报失败：

```text
waiting_package
→ report_checking
→ report_check_failed
```

联调失败：

```text
integration_checking
→ integration_failed
→ case_created
```

## 8. 媒体包更新状态流

正常流：

```text
waiting_package
→ report_checking
→ waiting_media_backend_update
→ integration_checking
→ integration_success
→ old_package_replaced
```

联调失败：

```text
integration_checking
→ integration_failed
→ risk_attention
→ case_created
```

## 9. 官方包 / 智投分包状态流

首次可在上报通过后直接进入分包联调：

```text
waiting_package
→ report_checking
→ integration_checking
→ integration_success
```

更新包：

```text
waiting_package
→ report_checking
→ waiting_zhitou_backend_update
→ integration_checking
→ integration_success
```

## 10. 异常诊断状态

异常诊断状态：

- `created`
- `waiting_input`
- `running`
- `partial`
- `resolved`
- `unresolved`
- `case_created`

异常诊断失败不等于立即结束。系统应先追问，再缩小范围，多轮后仍无法定位再生成 Case。

## 11. Case 状态

Case 状态：

- `created`
- `waiting_owner`
- `processing`
- `resolved`
- `closed`

生成 Case 时必须带已确认事实、未确认问题、已调用能力、Evidence 和下一步建议。
