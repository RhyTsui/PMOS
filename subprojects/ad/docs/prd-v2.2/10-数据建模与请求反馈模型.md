# 数据建模与请求反馈模型

## 1. 建模原则

V2.2 的模型不是只服务前台展示，而是服务 Chat、Workflow、Skill、MCP / 智投接口、资产、Case、Evidence 和 Trace 的统一协作。

所有模型必须满足：

- 带用户和角色上下文。
- 带项目引用。
- 可做权限过滤。
- 可关联 Evidence。
- 可进入 Trace。
- 可沉淀资产或 Case。
- 可表达失败、等待和部分成功。

## 2. ProjectBinding

```ts
type ProjectBinding = {
  project_refs: string[]
  default_project_ref?: string
  last_active_project_ref?: string
  source_project_refs?: string[]
}
```

字段说明：

- `project_refs`：对象涉及的全部项目。
- `default_project_ref`：默认项目，用于历史会话打开时切换项目。
- `last_active_project_ref`：最近活跃项目。
- `source_project_refs`：数据来源项目，可用于跨项目报表或资产追溯。

适用对象：

- Conversation
- Message
- Asset
- Report
- ReportTemplateRun
- ScheduledTask
- AutomationTask
- PackageDeliveryRecord
- CaseRecord
- TraceMetadata

## 3. PermissionContext

```ts
type PermissionContext = {
  user_id: string
  role_id: string
  role_name: string
  allowed_project_refs: string[]
  allowed_actions: string[]
  current_project_ref?: string
}
```

Chat 调用 Workflow / Skill 前必须传入权限上下文。Workflow / Skill 不应只信任自然语言判断，也要进行执行前检查。

## 3.1 ProjectResolution

```ts
type ProjectResolution = {
  ui_selected_project_ref?: string
  explicit_project_mentions: Array<{
    raw: string
    project_ref?: string
    project_name?: string
    confidence: number
    matched_by: 'exact_name' | 'alias' | 'app_id' | 'history' | 'fuzzy'
  }>
  inherited_project_refs: string[]
  effective_project_refs: string[]
  resolution_source:
    | 'explicit_user_project'
    | 'ui_selected_project'
    | 'cross_project_compare'
    | 'history_inherited'
    | 'clarification_required'
  conflict_detected: boolean
  clarification_needed: boolean
  clarification_question?: string
  permission_status: 'allowed' | 'partial_allowed' | 'denied' | 'unknown'
}
```

`ProjectResolution` 用于解决顶部项目与用户明示项目冲突。所有 Workflow / Skill / MCP 请求必须使用 `effective_project_refs`，不能直接使用顶部项目。

## 4. CapabilityRegistryItem

```ts
type CapabilityRegistryItem = {
  capability_id: string
  capability_name: string
  intent_keys: string[]
  domain:
    | 'data_report'
    | 'package_delivery'
    | 'diagnosis'
    | 'demand'
    | 'metric_explanation'
    | 'asset'
    | 'automation'
    | 'market_intelligence'
    | 'prediction'
  binding: {
    workflow_id?: string
    skill_id?: string
    mcp_service_ids?: string[]
    internal_api_refs?: string[]
  }
  status: 'available' | 'partially_available' | 'planned' | 'disabled'
  phase: 'phase_1_p0' | 'phase_1_p1' | 'phase_2' | 'phase_3' | 'phase_4'
  required_slots: string[]
  optional_slots: string[]
}
```

能力注册表用于防止意图命中后直接假装执行。Chat 必须先检查能力状态，再决定调用、追问、生成 Case 或提示未接入。

## 4.1 BusinessTermNormalizeResult

```ts
type BusinessTermNormalizeResult = {
  raw_text: string
  normalized_text: string
  dictionary_version: string
  normalized_terms: Array<{
    raw: string
    standard: string
    category:
      | 'business_object'
      | 'media_channel'
      | 'event'
      | 'metric'
      | 'attribution'
      | 'dimension'
      | 'issue_type'
      | 'action'
      | 'internal_process'
    confidence: number
    source: 'standard_term' | 'alias' | 'abbreviation' | 'context_rule'
    need_clarification: boolean
  }>
  ambiguous_terms: Array<{
    raw: string
    candidates: string[]
    reason: string
  }>
  clarification_questions: string[]
  confidence: number
}
```

术语归一化结果必须进入路由上下文和 Trace。它只用于把用户表达映射到受控业务词，不负责解释业务原因。

## 4.2 RouteDecisionV2

```ts
type RouteDecisionV2 = {
  intent_key: string
  confidence: number
  is_business_related: boolean
  capability_id?: string
  capability_status?: 'available' | 'partially_available' | 'planned' | 'disabled' | 'missing'
  workflow_id?: string
  skill_id?: string
  mcp_service_ids?: string[]
  required_slots: string[]
  missing_slots: string[]
  clarification_needed: boolean
  clarification_stage: 'pre_route' | 'post_route' | 'workflow_runtime' | 'none'
  execution_allowed: boolean
  blocked_reason?: string
  evidence_refs?: EvidenceRef[]
  next_actions: RecommendedAction[]
}
```

最终路由决策必须同时表达“用户想做什么”和“系统当前能不能做”。如果 `execution_allowed=false`，Chat 不能进入执行态，只能追问、提示边界或生成 Case。

## 5. WorkflowRun

```ts
type WorkflowRun = {
  workflow_run_id: string
  workflow_id: string
  workflow_type:
    | 'data_report'
    | 'scheduled_report'
    | 'package_delivery'
    | 'diagnosis'
    | 'demand'
    | 'metric_explanation'
  status:
    | 'created'
    | 'waiting_input'
    | 'running'
    | 'waiting_external'
    | 'succeeded'
    | 'partially_succeeded'
    | 'failed'
    | 'cancelled'
  project_refs: string[]
  user_id: string
  started_at: string
  ended_at?: string
  evidence_refs: EvidenceRef[]
  result_ref?: string
  case_refs?: string[]
}
```

WorkflowRun 是流程运行实例，必须能关联项目、用户、证据和结果。

## 6. SkillRequest / SkillResponse

```ts
type SkillRequest<TInput> = {
  skill_call_id: string
  skill_id: string
  user_id: string
  role_id: string
  project_refs: string[]
  project_resolution?: ProjectResolution
  input: TInput
  permission_context: PermissionContext
  trace_context: {
    conversation_id?: string
    message_id?: string
    workflow_run_id?: string
  }
}

type SkillResponse<TOutput> = {
  skill_call_id: string
  skill_id: string
  status: 'success' | 'partial' | 'failed' | 'waiting'
  output?: TOutput
  errors?: SkillError[]
  evidence_refs: EvidenceRef[]
  warnings?: string[]
  next_actions?: RecommendedAction[]
}
```

Skill 返回必须结构化，不能只返回一段自然语言。

## 7. MCP 请求反馈

```ts
type McpRequest<TInput> = {
  mcp_call_id: string
  mcp_service_id: string
  project_refs: string[]
  input: TInput
  requested_by: {
    user_id: string
    role_id: string
  }
  trace_context: {
    conversation_id?: string
    workflow_run_id?: string
    skill_call_id?: string
  }
}

type McpResponse<TOutput> = {
  mcp_call_id: string
  mcp_service_id: string
  status: 'success' | 'partial' | 'failed' | 'waiting'
  output?: TOutput
  raw_payload_ref?: string
  evidence_ref?: EvidenceRef
  errors?: SkillError[]
  data_freshness?: DataFreshness
}
```

MCP 请求必须带业务上下文，不能只传自然语言。

## 8. EvidenceRef

```ts
type EvidenceRef = {
  evidence_id: string
  evidence_type:
    | 'mcp_result'
    | 'workflow_event'
    | 'data_snapshot'
    | 'package_report'
    | 'integration_log'
    | 'integration_screenshot'
    | 'knowledge_base'
    | 'external_source'
    | 'user_confirmation'
  source_name: string
  source_ref?: string
  captured_at: string
  project_refs?: string[]
  summary: string
  raw_payload_ref?: string
}
```

Evidence 是业务结论的证据，不是普通日志。关键结论必须能关联 Evidence。

## 10. CaseRecord

```ts
type CaseRecord = {
  case_id: string
  case_type:
    | 'package_report_failed'
    | 'integration_failed'
    | 'diagnosis_unresolved'
    | 'data_quality_issue'
    | 'demand_followup'
    | 'capability_not_connected'
  title: string
  project_refs: string[]
  priority: 'low' | 'medium' | 'high' | 'urgent'
  status: 'created' | 'waiting_owner' | 'processing' | 'resolved' | 'closed'
  created_from: 'chat' | 'workflow' | 'automation'
  confirmed_facts: string[]
  unresolved_questions: string[]
  evidence_refs: EvidenceRef[]
  next_actions: RecommendedAction[]
  created_at: string
}
```

Case 是失败闭环对象，不是兜底话术。
