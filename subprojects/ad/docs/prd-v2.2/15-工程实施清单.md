# 工程实施清单

## 1. 实施原则

本清单用于后续研发拆解。实施原则：

- 保留当前已有能力，不推倒重来。
- 先补能力注册、权限、数据模型和防假功能，再扩展体验。
- Chat 不实现业务假逻辑。
- Workflow / Skill / MCP / 智投接口必须明确绑定。
- P0 优先打透数据报表、定时报表、包交付和权限过滤。

## 2. P0：能力注册与主链路治理

### 当前实现

已有 intent-router、intent-route-rules、context-compiler、slot-resolver。

### 修改要求

- 新增能力注册表。
- 路由结果增加 capability_id 和 capability_status。
- 路由后检查能力是否可执行。
- 未接入能力不能输出完成口吻。
- 必填槽位来自能力注册和 Workflow。
- 主 Chat 链路必须贯穿角色、偏好、项目权限、业务上下文、路由规则和能力发现结果。
- 接入受控术语词典归一化服务。
- 增加项目解析 `ProjectResolution`，区分顶部项目、用户明示项目和最终请求项目。
- Workflow / Skill / MCP 请求统一使用 `effective_project_refs`。
- 用户明示项目无权限时阻断，不能回退到顶部项目。
- 项目解析不得硬编码项目名、项目 ID 或示例 A/B，必须基于项目服务、权限列表和项目字典动态解析。
- 路由 Trace 增加术语归一化、候选意图、能力发现和追问阶段。
- Prompt 只作为结构化分类、追问表达和结果解释能力，不能替代能力注册和真实执行。

### 验收

- `delivery` 命中但包交付 Workflow 未接入时，不返回可投结论。
- `report_query` 可执行时正常调用。
- `market_intelligence` 一期不作为 P0 可执行闭环。
- 内部术语、简称和别名能先归一化，再进入路由。
- 能力未接入时不会继续追问无意义执行字段，而是进入边界说明或 Case。
- 顶部项目 A、用户问 B 项目时真实请求 B。
- 用户问无权限 B 项目时不请求顶部 A。
- 替换项目字典后验收仍通过，证明没有硬编码项目。

## 3. P0：角色与项目权限

### 当前实现

已有 role-profile-store 和 zhitou-role-mapping。

### 修改要求

- 主 Chat 链路读取真实用户角色和项目权限。
- Context Compiler 输出 PermissionContext。
- 会话、资产、自动化、报表、Case 增加项目引用。
- 历史会话打开时切换到默认项目，无权限不切换。
- 前台对无权限项目内容动态隐藏或脱敏。

### 验收

- 用户失去项目权限后，历史会话和资产不再展示该项目数据。
- Trace 仍保留完整引用。

## 4. P0：数据查询、报表与定时报表

### 当前实现

report_query 已有真实执行基础，report template、draft、scheduled task 已有基础。报表 MCP / 广告 BI 数据分析服务本身不是空白能力，已有上线和其它 Chat 复用基础；当前工程重点是小乔 Chat 侧完整绑定、补参、权限过滤、结果解析、Evidence 和资产化闭环。

### 2026-05-25 已落地进展

- 已新增 `ReportCapabilityManifest`，从当前 MCP server / tool 生成报表能力事实，并过滤配置检查、回传、联调、模板预览、归因诊断等非报表执行 tool。
- 已将 `report-query-orchestrator` 改为优先基于 Manifest 选择报表能力，再回落到策略关键词。
- 已在后台 MCP 管理页展示问数能力发现摘要，包括报表工具数、字典工具数、覆盖域和路由风险。
- 已新增 `report-capability-overrides.json` 运行时配置和 `GET/PUT /api/xiaoqiao/admin/report-capability-overrides`，支持对 tool 报表域、字典依赖和路由词做人工覆盖，并记录后台操作日志。
- 已新增 `ControlledGlossaryIndex`，支持内置 seed、运行态 JSON 和后台知识库同步；路由前只做轻量术语归一化。
- 已新增后台接口 `GET/POST /api/xiaoqiao/admin/controlled-glossary`，用于查看和同步受控术语索引。
- 已新增 `ReportQueryPlan`，记录原始问题、归一化问题、子查询、待补 slot、候选 tool、证据 refs 和执行状态。
- 当同一问题明确涉及多个报表域时，已支持按 `ReportQueryPlan` 串行执行多个报表 tool。
- 已将团队、应用类型、账户、包体、优化师纳入问数字典能力配置、预检、真实字典调用、筛选回填和 Trace `resolved_filters`；这些名称解析先由运行时 alias / 受控术语提供，不在代码里硬猜任意业务名。
- 已新增 `ReportAnswerComposer`，回答只读取结构化结果、Plan、Evidence、质量检查和下一步建议。
- 问数硬失败、缺能力、工具失败时已自动生成失败 Case；普通缺用户字段仍保持追问。
- 连弩 Chat Trace 已补充 `manifest_version`、`capability_id`、`candidate_tools`、`glossary`、`query_plan`、`preflight`、`resolved_filters`、`tool_chain`、`failure_case_id`。
- `智投Chat_广告业务（问数）测试集_预期精简版_v3.xlsx` 已接入 `test:report-query:mapping`，P0 tool mismatch / not selected 作为阻断门禁。

### 仍待实施

- Manifest 可视化和人工 override 已具备基础能力，但还缺少可编辑表单、差异预览、灰度发布和回滚。
- 团队、应用类型、账户、包体、优化师已补真实字典解析骨架；仍需补后台可编辑 alias、知识库术语同步到策略、以及更多真实返回字段样本的 id/name 映射验证。
- 后处理的 TopN、排序、环比、同期、差异比例、总计核对、多轮条件分支仍未完整落地。
- UI 结果卡片已具备基础展示，但复合查询的多结果合并展示、指标口径来源、资产化入口和端到端截图验收还需补齐。
- 连弩评测平台的逐用例回传仍需与连弩 SDK / 测试平台字段最终对齐。

### 修改要求

- 固化小乔 Chat 对已有报表 MCP 的真实绑定。
- 明确 MCP server、tool schema、入参、出参、错误码和权限失败结构。
- 查询结果仅用户保存后入资产。
- 报表草稿默认不保存。
- 报表模板跨项目复用，运行时校验权限。
- 定时报表创建必须确认数据延迟策略。
- 定时报表产物默认入资产。
- 定时报表任务增加项目字段、查看和筛选。
- 将 `E:\AI\ai-os\docs\sources\inbox\智投Chat_广告业务（问数）测试集_预期精简版_v3.xlsx` 纳入取数服务自测。
- 补齐前端组件、表格、可视化渲染、来源展示和下一步建议验收。
- 基于问数测试集反推补齐报表类型识别、日期语义、多维筛选、派生指标、排序对比、多轮条件分支、总计核对、边界处理、问数转诊断和可解释 MCP 调用需求。
- 先导出当前绑定 MCP 的 server、tool、input_schema、output_schema、错误码和权限字段，形成 `McpCapabilityManifest`。
- 将问数测试集每条用例映射为 `mcp_native`、`chat_mapping_required`、`orchestrator_postprocess`、`ui_required` 或 `unknown_or_gap`，禁止未核对 MCP schema 就写成能力缺失。
- 升级能力发现：从已披露 MCP schema 生成报表能力矩阵，路由规则和关键词策略只作为选择权重，不作为能力事实来源。
- 对已披露但未命中的 MCP tool，补充 Chat 路由规则、slot 映射、schema adapter、字段别名和 Trace 字段。
- 路由层把 `report_query` 细分为 `ad_daily_report`、`ad_hour_report`、`ad_roi_report`、`ad_retention_report`、`ad_material_report`、`ad_dictionary_lookup`、`report_diagnosis_candidate`。
- Slot 层补齐项目、日期、媒体、终端、团队、应用类型、账户、包体、优化师、ROI 类型、留存类型、自然量 / 广告量等解析和追问。
- Schema Adapter 层补齐 `timeType`、`promotionSource`、`subGroup`、`dataType`、`retentionType`、小时口径等 MCP 入参转换。
- Orchestrator 层补齐 TopN、排序、环比、同期、差异比例、总计核对、多轮继承、条件分支和问数转诊断。
- UI 层补齐结构化结果卡片、表格、图表、筛选条件、指标口径、来源、更新时间、下一步建议和资产化入口。
- 失败闭环区分 MCP 未配置、endpoint 不通、tool 未发现、权限失败、入参不匹配、返回为空、返回结构变化、解析失败，并在多轮仍不能完成时生成 Case。
- 连弩评测上报每条用例的意图、项目解析、slot、字典调用、tool 选择、真实调用、结果解析、后处理、UI 契约、Evidence / Trace 和失败分类。

### 验收

- 已有报表 MCP 能被小乔 Chat 通过能力注册发现并真实调用。
- MCP 调用失败时能定位到绑定、配置、授权、入参或解析问题，而不是笼统说能力缺失。
- 当前绑定 MCP tool 清单和问数测试集能力归属矩阵可审计，且能说明每条用例是 MCP 原生、Chat 映射、后处理、UI 展示还是未知缺口。
- 问数测试集 P0 用例通过取数服务自测。
- 前端结果卡片、表格、图表和下一步建议通过端到端验收。
- 日报、周报、月报、广告小时报表、媒体报表、自然量报表均能正确识别和路由。
- topN、最高最低、环比、转化率、ROI 等派生分析必须基于真实结果计算。
- 多轮槽位继承和条件分支有 Trace。
- 明细与总计核对能输出差异和建议。
- 问数失败能归类为 `route_error`、`slot_error`、`dictionary_error`、`tool_selection_error`、`mcp_call_error`、`result_parse_error`、`postprocess_error`、`ui_contract_error`、`permission_error` 或 `data_empty_or_unavailable`。
- 能从一次查询转报表。
- 能从报表转模板。
- 能创建定时报表。
- 未确认数据延迟策略不能启用。
- 自动产物进入资产并按项目过滤。

- 媒体包更新流程文案正确。

- 新包成功后旧包进历史。
- 新包失败生成 Case 和风险提示。

## 8.1 P0：个人记忆与知识库用户隔离

### 当前实现

Chat 消息星标保存已能真实调用 `/api/xiaoqiao/memory`，取消保存已能调用删除接口。记忆存储、搜索和 Dataki 同步已有基础。

### 修改要求

- 移除个人记忆主链路中的 `user-001` 默认用户。
- 记忆 API 必须从登录态解析 `user_scope_key`，不能信任前端传入的 `user_id`。
- 新增用户级个人知识库配置。
- 系统通用知识库只用于全员只读检索，不能写入个人记忆。
- 个人记忆同步必须使用当前用户个人知识库配置。
- 未配置个人 Key 时保存为待同步，不提示已同步。
- RAG 来源必须区分通用知识库、个人记忆、个人知识库、工具结果和外部来源。

### 验收

- 用户 A 保存的个人记忆，用户 B 无法检索、删除或同步。
- 前端传入 `user_id=user-001` 不影响后端按登录用户保存。
- 未配置个人 Key 时保存成功但状态不是 `synced`。
- 个人 Key 错误时保存成功、同步失败并展示原因。
- 个人记忆不会写入系统通用知识库。
- 包状态、联调结果和项目数据不会由个人知识库召回生成。
