# 系统分层责任与产研对接契约

## 1. 核心结论

小乔智投的产品流程是：

> Chat 负责核心意图和对话，依赖的中间服务由开发提供，系统完成绑定、调试、调用、解释和沉淀。

因此 PRD 不能把 Chat、Workflow、Skill、MCP / 智投接口混成一个大功能。每个需求都必须写清楚由哪一层负责，否则会出现前台做了假功能、后端能力无法对接的问题。

## 2. Chat 层

Chat 是用户入口和服务台。

Chat 负责：

- 接收用户自然语言。
- 识别核心意图。
- 判断是否业务域。
- 编译用户、角色、项目、权限、会话、资产、页面上下文。
- 调用受控术语词典或结构化归一化服务，做轻量术语识别。
- 查询能力注册表。
- 判断能力是否可执行。
- 判断是否需要追问。
- 承载路由前、路由后和 Workflow 运行中的追问。
- 调用 Workflow 或 Skill。
- 展示过程状态。
- 解释结构化结果。
- 输出证据、下一步建议、资产保存入口、Case 入口。
- 记录 Trace 元数据。
- 绑定 prompt 版本，但不把 prompt 当成真实业务能力。

Chat 禁止：

- 直接生成真实投放数据。
- 直接判断包是否可投。
- 直接生成上报检查结果。
- 直接生成联调结果。
- 直接伪造报表产物。
- 直接把大模型回答当作内部业务事实。
- 直接把知识库召回当作业务执行结果。
- 在能力发现前追问大量执行字段。
- 绕过项目权限展示数据。
- 绕过 Workflow 处理多步骤长流程。

## 3. Workflow 层

Workflow 是流程编排和状态管理层。

Workflow 负责：

- 多步骤流程编排。
- 异步等待和外部状态检测。
- 状态流转。
- 失败分支。
- 多个 Skill 调用的顺序和依赖。
- 证据聚合。
- 业务结论生成。
- 触发资产写入。
- 触发 Case 生成。
- 记录 Workflow Event。

一期需要的 Workflow：

- 数据报表 Workflow。
- 定时报表 Workflow。
- 包交付 Workflow。
- 异常诊断 Workflow。
- 需求协同 Workflow。
- 指标解释 Workflow。

典型例子：包交付必须由 Workflow 管理，因为它包含收到包、上报检查、等待媒体后台更新、检测新版本、联调检查、旧包归档和失败 Case，不是 Chat 一次回复能完成的任务。

## 4. Skill 层

Skill 是业务能力封装层。

Skill 负责：

- 把业务能力包装成稳定调用。
- 屏蔽底层多个接口差异。
- 对外提供明确入参、出参、错误码。
- 返回结构化业务结果。
- 返回 Evidence。
- 返回下一步建议。

一期需要的 Skill：

- 数据查询 Skill。
- 报表生成 Skill。
- 报表模板 Skill。
- 定时任务 Skill。
- 包状态查询 Skill。
- 上报检查 Skill。
- 联调检查 Skill。
- 异常诊断 Skill。
- 指标口径解释 Skill。
- 需求结构化 Skill。
- Case 生成 Skill。
- 资产写入 Skill。

Skill 不是一段自然语言 prompt，也不是 Chat 内部 if/else。它是可被 Workflow 或 Chat 绑定调用的业务服务封装。

## 5. MCP / 智投系统接口层

MCP / 智投系统接口是原子能力和真实数据来源。

它们负责：

- 查询项目投放数据。
- 查询指标口径。
- 获取数据上报报告。
- 检测媒体后台包更新。
- 检测智投后台包更新。
- 获取联调结果。
- 获取联调截图和日志。
- 获取包下载地址或 APK 地址。
- 查询历史包版本。
- 查询用户项目权限。
- 写入 Case。
- 写入资产。
- 返回原始证据引用。

PRD 不规定 MCP 内部如何实现，但必须规定它需要返回什么字段、状态、错误码和证据。

## 6. 产研对接流程

一个能力从需求到上线应按以下顺序：

1. 产品定义用户场景、状态流、数据模型、证据要求和验收标准。
2. 开发确认是否已有智投系统接口或 MCP。
3. 如无接口，先定义 MCP / 内部接口请求反馈模型。
4. 开发封装 Skill。
5. 若是多步骤流程，开发或平台侧编排 Workflow。
6. 定义受控术语、slot schema、prompt 版本和路由规则配置。
7. Chat 能力注册表绑定该 Workflow / Skill。
8. 调试真实调用链路。
9. 接入 Trace、Evidence、Asset、Case。
10. 验收是否存在假功能。

## 7. 能力未接入时的处理

能力未接入时，Chat 不能假装完成。

正确处理：

- 告知当前能力边界。
- 整理用户已提供的信息。
- 继续追问必要字段，但不要追问无意义字段。
- 如果需求明确，生成 Case。
- 如果是规划能力，标记待接入。

示例：

> 当前还没有接入该项目的媒体后台包更新检测能力，所以我不能直接判断新包是否已经更新。我可以先帮你整理项目、媒体和包版本，并生成包状态确认 Case。
