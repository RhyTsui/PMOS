# 包交付与联调状态 PRD

## 1. 总体定位

包交付是一期核心闭环之一，但它不能被简化为“联调工具”。用户真正关心的是：

- 这个包现在能不能投。
- 为什么不能投。
- 卡在哪一步。
- 谁需要处理。
- 下一步做什么。
- 旧包还能不能用。
- 新包有没有风险。
- 证据在哪里。

包交付必须由包交付 Workflow 承接。Chat 只负责识别、追问、调用、解释和沉淀。

## 2. 边界

包交付是单项目能力。用户跨项目问包时，Chat 必须追问项目或拆成多个单项目任务。

包交付一期不做强制业务拦截，不设计“禁止建监测活动”的硬限制，也不新增后台临时放行功能。系统提供可信结论、强风险提示、证据和 Case。

“可交付投放”必须由系统根据状态和证据派生，普通人工不能直接改成可投。

包的交付载体可以是下载地址或 APK 地址，但真正交付对象是带状态、证据、结论和风险说明的包资产。

## 3. 包类型

一期至少区分：

- 巨量 / 腾讯 / 快手媒体后台包。
- 官包。
- 智投分包。

不同包类型的上报检查、后台更新检测和联调触发路径不同。

## 4. 状态双层模型

包交付必须区分流程状态和业务结论。

流程状态表达包走到了哪里：

- 等待出包。
- 上报检查中。
- 上报不通过。
- 等待提审。
- 等待媒体后台更新。
- 等待智投后台更新。
- 联调检查中。
- 联调不通过。
- 联调成功。
- 已被新包替代。
- 历史可追溯。

业务结论表达用户能不能用：

- 可交付投放。
- 不建议交付。
- 待处理。
- 风险待关注。
- 历史包。

## 5. 媒体包首次流程

适用于巨量、腾讯、快手。

1. 智投收到包。
2. 包交付 Workflow 调用上报检查 Skill。
3. 上报检查 Skill 调用数据上报报告 MCP。
4. 状态进入“上报检查中”。
5. 如果上报不通过：
   - 状态为“上报不通过”。
   - 业务结论为“不建议交付”。
   - 不提示用户提审或更新包。
   - 旧包保持当前有效。
   - 返回失败项、报告、修复建议和 Evidence。
6. 如果上报检查通过：
   - 状态为“等待提审”。
   - 输出文案：“上报检查通过，等待提审。”
7. 系统检测到媒体后台更新。
8. 展示新版本号。
9. 状态进入“联调检查中”。
10. 联调成功后：
    - 状态为“联调成功”。
    - 业务结论为“可交付投放”。
11. 联调失败后：
    - 状态为“联调不通过”。
    - 业务结论为“不建议交付”。
    - 自动生成 Case。

## 6. 媒体包更新流程

适用于巨量、腾讯、快手的新包更新。

1. 智投收到新包。
2. 系统执行上报检查。
3. 上报不通过时：
   - 不提示用户更新。
   - 旧包保持当前有效。
   - 输出失败证据和修复建议。
4. 上报通过后：
   - 状态为“等待媒体后台更新”。
   - 输出文案：“上报检查通过，等待媒体后台更新。”
5. 系统检测到媒体后台新版本。
6. 展示新版本号。
7. 触发或读取联调检查。
8. 联调成功后：
   - 新包可交付投放。
   - 旧包自动标记“已被新包替代”。
   - 旧包进入历史包分类，默认不展开。
9. 联调失败后：
   - 新包标记“风险待关注”。
   - 旧包通常已经被替代，仍标记“已被新包替代”。
   - 系统提示生产验证风险。
   - 自动生成 Case。

## 7. 官方包 / 智投分包流程

1. 官包到达或更新。
2. 系统调用数据上报报告 MCP。
3. 上报不通过：
   - 状态为“上报不通过”。
   - 不触发智投分包联调。
4. 上报通过：
   - 首次包：直接触发智投分包联调。
   - 更新包：状态为“等待智投后台更新”。
   - 输出文案：“数据检查通过，等待智投后台更新。”
5. 系统检测到智投后台更新。
6. 抽取一个在投媒体分包检查。
7. 联调成功：
   - 新包可交付投放。
   - 旧包标记已被新包替代。
8. 联调失败：
   - 生成 Case。
   - 输出风险说明和下一步建议。

## 8. Chat、Workflow、Skill、MCP 职责

Chat 负责：

- 识别用户在问包交付。
- 确认项目、媒体、包类型、版本。
- 检查角色和项目权限。
- 调用包交付 Workflow。
- 解释状态、结论、证据和下一步。

Workflow 负责：

- 管理包状态机。
- 调用上报检查 Skill。
- 调用包更新检测 Skill。
- 调用联调检查 Skill。
- 处理旧包替代。
- 生成业务结论。
- 失败时生成 Case。

Skill 负责：

- 包状态查询。
- 上报检查。
- 媒体后台更新检测。
- 智投后台更新检测。
- 联调检查。
- Case 生成。
- 资产写入。

MCP / 智投接口负责：

- 数据上报报告。
- 媒体后台版本。
- 智投后台版本。
- 联调结果。
- 联调截图。
- 联调日志。
- 包下载地址或 APK 地址。
- 历史包版本。

## 9. Debug Automation 的定位

Debug Automation 是底层联调/调试能力，不是包交付产品本身。

它应被纳入：

- 联调检查 Skill。
- 包交付 Workflow 的证据来源。
- 异常诊断 Workflow 的检查项。

Debug Automation 成功不等于包一定可投。最终可投结论必须由包交付 Workflow 综合派生。
