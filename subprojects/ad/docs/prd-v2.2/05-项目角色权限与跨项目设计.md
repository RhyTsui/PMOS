# 项目角色权限与跨项目设计

## 1. 背景

小乔智投的用户权限按项目分配，并且是动态变化的。用户当前有权限，不代表未来仍有权限；用户曾经在会话或资产中查看过某项目数据，也不代表权限取消后仍可继续查看。

同时，小乔的产品目标是自由对话，不应强制每个会话只能绑定一个项目。用户确实存在跨项目分析需求，因此系统设计必须同时支持自由对话和严格权限过滤。

## 2. 设计原则

最终原则是：

> 自由对话 + 项目上下文感知 + 动态权限过滤。

这意味着：

- 会话可以跨项目。
- 资产可以跨项目。
- 自动化任务可以多项目。
- 报表模板可以跨项目复用。
- 包交付必须单项目。
- 前台展示必须基于用户当前项目权限动态过滤。
- Trace 和审计记录保留完整，不因前台过滤而丢失。

## 3. 用户、角色与项目

用户有身份，角色决定默认能力范围，项目权限决定可见数据范围。两者必须同时生效。

角色示例：

- 优化师：可以查数据、看包状态、触发联调相关能力、排查异常、提需求。
- 观察员：以查看和解释为主，不触发高风险动作。
- 设计师：以素材、创意、需求协同、部分数据查看为主。

但角色不能覆盖项目权限。优化师如果没有某项目权限，也不能查看该项目数据或包状态。

## 4. 会话项目规则

会话绑定用户，但允许跨项目。

会话需要记录：

- `project_refs`：会话涉及的所有项目。
- `default_project_ref`：会话默认项目。
- `last_active_project_ref`：最近活跃项目。
- `source_project_refs`：内容来源项目集合。

打开历史会话时：

1. 系统读取会话的 `default_project_ref` 或 `last_active_project_ref`。
2. 如果用户仍有权限，右上角项目选择器切换到该项目。
3. 如果用户无权限，不切换到无权限项目。
4. 会话中无权限项目内容隐藏或脱敏。
5. 前台提示“部分项目内容因权限变化不可见”。

暂不做会话按项目完全隔离展示。当前阶段更适合保留自由对话体验，同时做好项目字段和权限过滤。

## 4.1 本轮请求项目解析规则

右上角项目选择器代表默认项目，不代表用户本轮请求一定查询该项目。

当用户自然语言中显式提到项目时，系统必须优先解析用户明示项目，并与右上角项目做冲突判断：

- 顶部项目 A，用户问 B 项目：本轮请求项目为 B。
- 顶部项目 A，用户说“当前项目”“这个项目”：本轮请求项目为 A。
- 顶部项目 A，用户说“B 和当前项目对比”：本轮请求项目为 A + B。
- 用户明示 B 项目但无权限：不能回退查询 A，必须提示 B 无权限。
- 用户明示项目无法唯一识别：必须追问确认。

该规则适用于数据查询、异常排查、指标对比、包交付等所有业务能力。包交付仍然必须单项目；如果用户明示多个项目，Chat 应追问选择一个项目或拆成多个任务。

工程实现不得硬编码项目名、项目 ID 或示例 A/B。A/B 只表示“顶部默认项目”和“用户明示项目”。真实实现必须基于项目服务、用户权限项目列表、项目字典、项目别名、APPID 和上下文动态解析。

## 5. 资产项目规则

我的资产必须增加项目字段、项目查看和项目筛选。

资产可以是单项目，也可以是跨项目。跨项目资产中，如果用户失去部分项目权限，只隐藏或脱敏对应项目部分，其他有权限部分仍可查看。

资产列表必须按当前用户权限动态过滤：

- 单项目资产：无权限时隐藏。
- 跨项目资产：全部无权限时隐藏；部分无权限时标记部分不可见。
- 资产详情：无权限字段、图表、明细、证据需要隐藏或脱敏。

不建议物理删除历史数据，因为 Trace、审计和问题追溯仍需要完整性。产品层面的“不可见”应通过动态过滤实现。

## 6. 自动化任务项目规则

自动化任务和会话类似，可以多项目。

创建和编辑自动化任务时必须选择项目，任务列表支持项目查看和筛选。用户权限变化后：

- 无权限项目的任务不可见。
- 跨项目任务中无权限部分不可见。
- 定时报表产物进入资产后继续遵守资产权限规则。

定时报表是一期 P0，必须优先接入该规则。

## 7. 报表模板项目规则

报表模板可以跨项目复用。模板记录的是指标、维度、筛选、展示结构和时间窗口，不应被单个项目绑定死。

但模板运行时必须绑定项目，并校验用户项目权限。用户可以复用模板生成不同项目的报表，但不能借模板查看无权限项目数据。

## 8. 包交付项目规则

包交付必须单项目。

原因：

- 包版本绑定项目。
- 媒体后台更新绑定项目。
- 智投后台更新绑定项目。
- 联调状态绑定项目。
- 包是否可交付投放不能跨项目混合判断。

如果用户问多个项目的包，Chat 应：

- 追问用户选择一个项目，或
- 拆成多个独立包交付任务。

## 9. Trace 与连弩

Trace 在连弩平台完整回放。前台权限过滤不应破坏 Trace 完整性。

小乔发送 Trace 时必须携带：

- 用户。
- 角色。
- 项目引用。
- 会话。
- 消息。
- 意图。
- Workflow Run。
- Skill Call。
- MCP Call。
- Evidence。
- Asset。
- Case。

前台展示时按用户权限过滤；连弩回放按平台权限和审计规则控制。
