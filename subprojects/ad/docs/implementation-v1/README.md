## 1. 阶段定位

第四阶段不再重新讨论产品战略、需求定义和系统设计，而是把已经通过设计准入的内容转成可排期、可分工、可验收的工程实施清单。

本目录的输入来源：

- `docs/design-v1/15-设计阶段完成度核对表.md`
- `docs/design-v1/16-设计阶段缺口清单.md`
- `docs/design-v1/17-进入实施阶段准入评审.md`
- `docs/prd-v2.2/15-工程实施清单.md`

其中 `design-v1` 是准入依据，`prd-v2.2/15` 是历史工程清单和当前实现进展参考。

## 2. 实施原则

- 保留当前已有能力，不推倒重来。
- 先打通自由对话到真实执行的最低闭环，再扩展复杂 Workflow。
- Chat 负责意图、上下文、追问、编排、结果表达，不伪造 MCP / Workflow 事实。
- MCP / Skill / Workflow 由开发提供和封装，小乔 Chat 侧负责发现、绑定、调用、解析和展示。
- 设计缺口不得被写成已完成实现，必须作为阻断条件或前置契约处理。
- Trace 和资产证据分离：Trace 服务连弩回放与评测，资产证据服务用户可见闭环。

## 4. 当前准入状态

可直接进入实施拆解：

- 对话路由。
- 项目权限与跨项目上下文。
- 资产与证据沉淀。

可有条件进入实施拆解：

- 问数闭环。
- 定时报表与自动化。
- 包交付与联调。
- 异常排查。
- 指标解释。
- 需求沟通与 Case。
- 个人记忆与知识库隔离。
- 能力发现与服务绑定。
- 连弩 Trace。

不进入一期实施：

- 市场情报。
- 预测。
- 广告投放自动执行。
- 自动学习规则。

## 5. 禁止事项

- 禁止用写死项目名、项目 ID 或示例 A/B 解决项目解析。
- 禁止用 Prompt 生成内部数据、包状态、联调结论、可投结论。
- 禁止把知识库自由文本当成实时项目数据、权限、包状态事实来源。
- 禁止把测试集取数通过当成用户闭环完成。
- 禁止把“已整理需求”当成“已创建 Case”。
- 禁止把缺少字段样本的模块标记为实施完成。
