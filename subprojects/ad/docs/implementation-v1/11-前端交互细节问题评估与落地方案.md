# 前端交互细节问题评估与落地方案

## 1. 文档定位

本文补齐 Chat 前端在问数、包交付、知识库、资产、自动化、Case、状态文案中的交互边界。

## 2. 业务语言原则

用户看到的是业务语言，不应出现 Workflow、Skill、MCP 等工程词。

示例：

| 工程表达 | 用户表达 |
|---|---|
| MCP 调用成功 | 已查询 |
| Workflow 执行中 | 检查中 |
| Schema mismatch | 服务返回格式异常 |
| Capability not found | 当前能力未接入 |
| Tool timeout | 服务响应超时 |

## 3. 状态文案必须真实

结果卡中的“已查询”“已检查”“已保存”必须与真实状态一致。

- 未真实调用数据服务，不得显示“已查询”。
- 未真实调用检查能力，不得显示“已检查”。
- 未写入资产或知识库，不得显示“已保存”。
- 只生成草案，不得显示“已创建 Case”。

## 4. 左下角弹窗入口

用户已纠正：入口在左下角，不是右下角。

左下角弹窗内入口关系：

- 知识库：独立入口，跳转或配置 Dataki 个人知识库 Key。
- 资产：独立入口，进入我的资产目录和对应存储。
- 自动化：独立入口，创建和查看自动化任务。

三者不互相替代。

## 5. 三类保存动作

| 操作 | 含义 | 目标系统 |
|---|---|---|
| 保存到知识库 | 保存到 Dataki 系统，形成个人知识条目 | Dataki |
| 保存到资产 | 保存到我的资产目录和对应存储 | 小乔资产 |
| 生成 Case | 创建后台需求池或异常池记录 | 后台 Case 系统 |

保存到知识库用于经验沉淀，保存到资产用于结果回看和归档，生成 Case 用于需求或异常流转。

## 6. PC 与移动端

当前优先完成 PC 端设计。移动端后续做自适应，不在本批强制定义。

PC 端必须支持：

- 项目冲突追问。
- 权限阻断提示。
- 结果卡状态。
- 证据来源。
- 下一步建议。
- 保存到知识库、保存到资产、生成 Case 的清晰区分。

## 7. 验收规则

- 前台业务用户看不到 Workflow/Skill/MCP 工程词。
- 状态文案与真实调用、检查、保存状态一致。
- 左下角弹窗包含知识库、资产、自动化独立入口。
- 保存到知识库、保存到资产、生成 Case 的文案和落点不同。
- 移动端不作为当前阻断项，但 PC 端布局不得阻碍后续自适应。
