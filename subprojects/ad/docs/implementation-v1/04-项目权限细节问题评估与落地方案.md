# 项目权限细节问题评估与落地方案

## 1. 文档定位

本文承接 `docs/design-v1/02-项目权限与跨项目上下文系统设计.md`，补齐项目解析、权限动态变化、历史会话、资产、自动化任务和 Trace 边界。

用户已确认的核心产品原则：

- 项目 ID 和项目名属于公司主数据，不会重名。
- 顶部项目是默认上下文，不是强制执行项目。
- 用户在对话中明确提到 B 项目时，即使右上角选择 A，也应解析并请求 B；如果无权限则阻断。
- 用户在对话中切换项目后，会话默认项目更新。
- 历史会话打开时，右上角项目切换到会话当时的默认项目。
- 历史会话、资产、自动化任务都按最新项目权限动态展示。

## 2. 项目解析与冲突

项目主数据不允许项目 ID 和项目名重名，因此系统不需要设计“项目名重名确认”。但项目别名、APPID、用户口语表达仍可能产生多个候选，需要追问确认。

解析优先级：

1. 用户本轮显式项目名或项目 ID。
2. 用户本轮显式 APPID。
3. 用户本轮项目别名。
4. 当前会话已确认项目。
5. 顶部选择项目。
6. 用户常用项目偏好。

顶部项目只在用户没有明确项目时作为默认项目。如果用户显式提到 B 项目，顶部 A 项目不能覆盖 B。

## 3. 权限执行原则

权限必须在工具调用前拦截，而不是等结果返回后再隐藏。

统一链路：

```text
用户身份
  -> 当前角色
  -> 最新项目权限
  -> 对话项目解析
  -> effective_project_refs
  -> Tool / MCP / Workflow 调用
  -> 结果展示过滤
```

业务工具只能接收 `effective_project_refs`，不能接收未经权限过滤的用户原始项目输入。

## 4. 跨项目查询

自由对话目标下，问数和分析允许跨项目，但每个项目都必须单独校验权限。

跨项目查询在会话时拦截权限：

- 全部有权限：继续执行。
- 部分无权限：当前版本建议阻断并提示无权限项目，不做“部分表格隐藏”。
- 全部无权限：阻断。

这样可以避免表格、图表、总结三层展示出现不一致。

包交付是单项目能力，不支持跨项目执行。

## 5. 历史会话与权限变化

用户权限是动态的，历史会话不能因为曾经可见就永久可见。

规则：

- 历史会话绑定默认项目和相关项目集合。
- 会话包含任一失权项目且无法安全拆分时，当前版本直接不展示该会话。
- 打开历史会话时，右上角项目切换到会话当时的默认项目；如果该默认项目已无权限，则不展示会话。
- 不做会话内容按项目局部裁剪，避免结论和证据断裂。

## 6. 资产与自动化任务

我的资产、自动化新增和编辑都需要项目字段、项目查看和筛选。

规则：

- 查询结果只有用户保存后才进入资产。
- 自动化任务产物默认进入资产。
- 资产和自动化任务都绑定项目集合。
- 用户权限变化后，失权项目相关资产不可见。
- 自动化任务运行时用户权限变化，任务暂停且不可见。
- 报表模板可以跨项目复用，但模板不保存具体项目数据。

## 7. Trace 边界

Trace 在连弩平台，研发和测试可完整回放。当前版本不处理历史回放随权限变化动态收敛的问题。

边界规则：

- 前台普通业务用户不展示完整 Trace。
- 前台最多展示 trace id、执行状态、脱敏错误摘要。
- Trace 可保存完整项目引用、路由、调用和解析信息，作为研发与测试环境内部调试资产。
- 不能把 Trace 当成普通用户可见资产。

## 8. 验收规则

- 顶部 A，用户问 B，系统请求 B；B 无权限则阻断，不请求 A。
- 用户在对话中切换项目，会话默认项目更新。
- 打开历史会话时，顶部项目切换到会话当时默认项目。
- 权限撤销后，相关历史会话不展示，相关资产不可见，自动化任务暂停且不可见。
- 包交付请求只能包含一个项目。
- Trace 完整回放不出现在普通业务前台。
