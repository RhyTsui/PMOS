# 第一批验收矩阵与自测门禁

## 1. 文档定位

本文承接：

- `15-第一批代码实施任务拆解与验收门禁.md`
- `17-第一批代码落地执行计划与文件边界.md`

本文目标是把第一批问数最低闭环的发布准入条件落成可执行验收矩阵。

本文不替代代码实现文档，不扩展新需求。它只回答一个问题：

> 第一批代码做到什么程度，才算可以进入验收或发布前联调？

## 2. 验收总原则

第一批验收不是“能回答一句自然语言”。

必须同时满足：

1. 路由正确。
2. 项目和权限正确。
3. 能力发现真实。
4. 字典和 slot 补齐真实。
5. MCP 调用真实。
6. 结果解析正确。
7. UI 状态真实。
8. Timeline 可解释且不展示伪 CoT。
9. Trace 可追踪。
10. 测试脚本和人工验收都通过。

禁止把以下结果算作通过：

- 只命中意图但没有真实工具调用。
- 测试集映射通过但用户闭环未完成。
- MCP 报错但前端显示“已查询”。
- 空结果展示为失败。
- 无权限时仍调用 MCP。
- 用顶部项目覆盖用户明示项目。
- 用自然语言拼接数据结论。

## 3. 自测脚本门禁

当前已有脚本：

| 脚本 | 命令 | 门禁含义 |
|---|---|---|
| TypeScript 检查 | `npm run ts-check` | 类型无错误 |
| UI 保护检查 | `npm run validate:ad-ui` | `ts-check` + UI guardrail |
| 问数自测 | `npm run test:report-query` | 问数选择、输入构造、结果组合基础路径 |
| 问数测试集映射 | `npm run test:report-query:mapping` | `智投Chat_广告业务（问数）测试集_预期精简版_v3.xlsx` 的能力映射 |
| 角色映射自测 | `npm run test:role-mapping` | 登录角色到智投角色映射稳定 |
| 构建 | `npm run build` | Next 和 server 构建通过 |

发布前建议顺序：

```text
npm run ts-check
npm run test:report-query
npm run test:report-query:mapping
npm run test:role-mapping
npm run validate:ad-ui
npm run build
```

说明：

- `test:report-query:mapping` 只证明测试集用例和当前能力映射关系，不等于用户闭环完成。
- `validate:ad-ui` 只证明 UI 保护规则基础通过，不等于视觉验收完成。
- `build` 通过不代表业务闭环通过。

## 4. 测试集来源

问数测试集来源：

```text
docs/sources/inbox/智投Chat_广告业务（问数）测试集_预期精简版_v3.xlsx
```

当前映射脚本：

```text
ad/frontend/src/scripts/report-query-testcase-mapping.ts
```

要求：

- 测试集用例必须保留优先级。
- P0 用例必须进入第一批验收。
- P1/P2 可作为缺口归档，但不能阻断第一批最低闭环，除非影响 P0 主链路。
- 多工具编排用例要区分“当前未支持”和“错误命中”。

## 5. 验收矩阵

### 5.1 路由与项目权限

| 编号 | 场景 | 输入示例 | 必须结果 | 阻断条件 |
|---|---|---|---|---|
| R-01 | 问数意图识别 | 昨天消耗多少 | `intent_type=report_query` | 路由到 general 或 help |
| R-02 | 顶部项目与明示项目冲突 | 顶部 A，问 B 昨日 ROI | 使用 B 作为 effective project | 请求 A |
| R-03 | 明示项目无权限 | 顶部 A，问无权限 B | 阻断，不调用 MCP | 回退 A 或仍调用 B |
| R-04 | 指代当前项目 | 这个项目昨天消耗 | 使用顶部项目 | 追问已知项目或伪造项目 |
| R-05 | 跨项目查询 | A 和 B 昨日消耗对比 | 逐项目校验权限 | 未校验就调用 |

验收证据：

- Runtime / metadata 中能看到项目解析来源。
- MCP 入参只能来自 `effective_project_refs`。
- 无权限场景没有 MCP 调用记录。

### 5.2 能力发现与预检

| 编号 | 场景 | 必须结果 | 阻断条件 |
|---|---|---|---|
| C-01 | 报表 MCP 已配置 | 能进入 report capability manifest | Chat 仍判定 MCP 缺失 |
| C-02 | 字典 MCP 已配置 | 能识别为 dictionary capability | 直接跳过字典 |
| C-03 | 报表能力缺失 | `CapabilityPreflight` 标记 missing | 继续调用不存在 tool |
| C-04 | 字典能力缺失 | 阻断或降级追问 | 继续调用报表 tool |
| C-05 | MCP 已披露但 Chat 未映射 | 归类为 `mcp_native_chat_mapping_gap` | 归因为 MCP 缺失 |

验收证据：

- capability id。
- selected tool。
- missing capability。
- preflight ok / failed。
- 归因分类。

### 5.3 问数执行

| 编号 | 问题类型 | 输入示例 | 必须结果 |
|---|---|---|---|
| Q-01 | 日报 | 昨天消耗、激活、ROI | 日报能力命中，返回表格 |
| Q-02 | 小时 | 今天每小时消耗趋势 | 小时能力或小时粒度参数命中 |
| Q-03 | ROI | 近 7 天首日 ROI | ROI 能力或日报能力 + ROI 字段命中 |
| Q-04 | 留存 | 近 7 天次留 | 留存能力命中 |
| Q-05 | 素材 | 昨天素材消耗排行 | 素材能力命中 |
| Q-06 | 字典筛选 | 巨量 Android 昨日消耗 | 先解析媒体和终端，再查报表 |

验收证据：

- selected question type。
- selected capability。
- tool input。
- raw result preview。
- normalized rows / columns。
- result status。

### 5.4 失败闭环

| 编号 | 失败场景 | 必须结果 | 阻断条件 |
|---|---|---|---|
| F-01 | 字典无匹配 | 追问或提示补充，不调用报表 | 继续查报表 |
| F-02 | 报表 tool 超时 | 展示查询失败和重试建议 | 展示“已查询” |
| F-03 | schema mismatch | 展示解析失败，保留排查信息 | 展示空表或成功 |
| F-04 | 空结果 | 展示查询条件和放宽建议 | 展示为系统失败 |
| F-05 | 部分成功 | 展示成功部分、失败部分、影响 | 只展示成功或只展示失败 |
| F-06 | 权限失败 | 展示无权限，不调用或停止结果输出 | 输出数据事实 |

验收证据：

- `ToolCallEnvelope.result_status`。
- `tool_error_safe`。
- `tool_error_type`。
- `tool_error_stage`。
- recommended actions。

### 5.5 MessagePart 与前端展示

| 编号 | 场景 | 必须结果 | 阻断条件 |
|---|---|---|---|
| U-01 | 有 `message_parts` | 前端优先按协议渲染 | 忽略协议只渲染自然语言 |
| U-02 | 无 `message_parts` | 旧消息兼容展示 | 旧消息损坏 |
| U-03 | Timeline | 展示结构化执行过程 | 展示伪 CoT 或“我正在思考” |
| U-04 | ToolCard | 展示真实工具调用摘要 | 展示未发生的工具调用 |
| U-05 | Table | 使用真实 rows / columns | 前端拼表 |
| U-06 | Chart | 使用真实 `viz_spec` | 无数据时伪造图表 |
| U-07 | ActionList | 来自 recommended actions | 前端临时拼接业务结论 |
| U-08 | SourceRefs | 可追溯到 MCP / 知识库 / 附件 / 口径 | 无来源仍展示证据 |

验收证据：

- 消息 metadata。
- `message_parts`。
- 截图。
- 前端状态文案。
- 来源面板。

## 6. 发布准入等级

### 6.1 必须全部通过

以下任一失败都不能发布：

- R-02 顶部项目冲突。
- R-03 无权限阻断。
- C-01 报表能力发现。
- C-02 字典能力发现。
- Q-01 日报查询。
- Q-06 字典筛选。
- F-02 MCP 失败不伪成功。
- F-04 空结果正确展示。
- U-03 Timeline 不展示伪 CoT。
- G-01 到 G-10 前端保护。
- `npm run ts-check`。
- `npm run validate:ad-ui`。
- `npm run test:report-query`。
- `npm run test:report-query:mapping`。
- `npm run build`。

### 6.2 可带缺口发布前评审

以下可作为已知缺口进入评审，但必须记录：

- P1/P2 测试集未全部覆盖。
- 多工具复杂编排未全部支持。
- 图表只支持基础折线或表格降级。
- Trace 字段等待连弩 SDK 最终冻结。
- 部分历史消息没有 `message_parts`，但兼容展示正常。

### 6.3 明确不能算通过

- 只通过 `test:report-query:mapping`。
- 只通过 `build`。
- 只通过前端截图。
- 只返回自然语言总结。
- 用 mock 数据展示成功。
- 工具调用失败但生成看似完整的分析结论。

## 7. 人工验收清单

人工验收必须至少覆盖：

1. 新会话问数。
2. 历史会话问数结果回看。
3. 顶部项目切换后问另一个项目。
4. 无权限项目提问。
5. 字典筛选提问。
6. 空结果。
7. MCP 失败或模拟失败。
8. 表格展示。
9. 图表展示。
10. 来源和下一步建议。
11. 移动端基础可用。
12. 页面布局未被重构。

## 8. 输出物要求

第一批验收完成后，至少沉淀：

- 自测脚本输出。
- 测试集映射报告。
- P0 用例执行结果。
- 失败闭环截图。
- 前端四态截图。
- 项目权限冲突用例截图或日志。
- Trace 样本。
- 未通过项清单。

## 9. 与后续批次的边界

第一批验收不覆盖：

- 包交付状态机。
- 联调触发。
- 异常排查 Workflow。
- 定时报表调度。
- 资产真实落库。
- 个人知识库 Key 配置。
- Case 真实创建。
- 市场情报。
- 预测。
- 广告投放自动执行。

这些模块不得因为第一批问数验收通过而被标记为完成。
