# 包交付与联调细节问题评估与落地方案

## 1. 文档定位

本文承接 `docs/design-v1/09-包交付与联调系统设计.md` 和 `docs/design-v1/09A-包交付状态机与服务对接细化设计.md`，补齐首包、新包、历史包、上报检查、后台更新检测、联调触发、可投结论和失败 Case。

包交付是单项目能力，不支持跨项目执行。

## 2. 用户已确认的业务规则

### 2.1 媒体包

巨量、腾讯、快手的包在媒体后台更新。系统检测到媒体后台更新才会触发再次联调。检测到媒体后台更新后，前台展示为新版本号，并显示联调中。

首次流程：

1. 智投收到包。
2. 获取数据上报报告 MCP。
3. 上报检查通过后，提示用户“上报检查通过，等待提审”。
4. 媒体后台更新检测到新包。
5. 触发联调。
6. 联调成功后，包进入可交付投放。

更新包流程：

1. 智投收到新包。
2. 上报检查。
3. 上报检查通过后，状态为“上报检查通过，等待媒体后台更新”。
4. 检测到媒体后台更新。
5. 展示新版本号，进入联调中。
6. 联调成功后，新包可投，旧包自动标记为“已被新包替代”。

### 2.2 官方包

官方包的智投分包检测到官包更新后触发再次联调。系统会抽一个在投的媒体分包检查。

首次流程：

1. 智投收到官方包。
2. 获取数据上报报告 MCP。
3. 上报检查通过后，直接分包联调。

更新包流程：

1. 检测到官包更新。
2. 上报检查。
3. 上报检查通过后，状态为“数据检查通过，等待智投后台更新”。
4. 智投后台更新后触发联调。
5. 联调成功后，新包可投，旧包自动标记为“已被新包替代”。

## 3. 状态机

一期底层状态沿用用户给出的状态集合，但前台可按媒体包/官方包文案差异展示。

首包状态：

- 等待出包。
- 上报检查中。
- 上报不通过。
- 上报检查通过，等待提审。
- 数据检查通过，等待智投后台更新。
- 上报检查通过，等待媒体后台更新。
- 联调检查中。
- 联调不通过。
- 联调成功。

新包状态：

- 新包上报检查中。
- 新包上报不通过。
- 新包上报检查通过，等待媒体后台更新。
- 新包数据检查通过，等待智投后台更新。
- 新包联调检查中。
- 新包联调不通过。
- 新包联调成功。

历史包状态：

- 当前有效。
- 已被新包替代。
- 历史包。

历史包默认收起，不展开。

## 4. 失败处理

上报检查不通过：

- 不提示用户去提审或更新包。
- 旧包保持当前有效。
- 展示失败原因和报告来源。

联调不通过：

- 不提示用户去建监测活动。
- 展示失败原因。
- 自动生成 Case。
- 用户可再次发起联调，但必须满足上报检查通过。

新包联调不通过：

- 因为包已经更新，旧包一般仍在投，但已被标记为“已被新包替代”。
- 前台表达为“联调失败”，列出失败原因。
- 用户可再发起联调。
- 不做复杂风险态，只给出失败原因和下一步动作。

## 5. 联调触发与校验

用户单独触发联调不需要额外显式权限，优化师角色会触发；但当前系统已有会话中的角色权限处理，实施时必须沿用现有权限处理。

触发联调前必须校验：

- 项目权限通过。
- 包属于单项目。
- 包上报检查已通过。
- 包下载地址可访问。

未通过上报检查的包不会触发联调。

## 6. 包匹配与下载地址

用户已确认：

- 不存在多媒体同包。
- 禁止同版本多包，后续由业务侧约束。
- 包下载地址不会过期。
- 每个包只有一个 APK 地址。
- 系统保障 APK 地址可访问。

因此一期不设计复杂多 APK 选择、过期恢复、多包匹配。

## 7. 可投结论

“可交付投放”必须由系统根据上报检查、后台更新检测、联调结果派生，禁止人工直接改成可投。

当前不增加后台人工强制改可投功能，避免 B 端业务临时开放把系统状态机变复杂。后续如业务确需临时开放，再单独评估后台控制能力。

## 8. MCP / Workflow 边界

Chat 负责：

- 识别用户要查包、查状态或触发联调。
- 解析项目和包。
- 校验权限和上报检查前置状态。
- 调用包服务、上报检查 MCP、联调 Workflow。
- 展示状态、报告、失败原因、下一步建议。

MCP / Workflow 负责：

- 数据上报报告。
- 媒体后台更新检测。
- 智投后台更新检测。
- 联调检查。
- 截图和报告结果。
- 失败原因枚举。

Chat 不能伪造包状态、联调结论、截图或可投结论。

## 9. 验收规则

- 首包媒体包上报通过后展示“等待提审”。
- 更新包媒体包上报通过后展示“等待媒体后台更新”。
- 官方包更新包上报通过后展示“数据检查通过，等待智投后台更新”。
- 上报不通过时不允许触发联调。
- 联调不通过自动生成 Case。
- 新包联调成功后旧包自动进入“已被新包替代”，历史包默认收起。
- 可投状态只能由系统派生，不能人工直接修改。
