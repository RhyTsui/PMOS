# 异常排查细节问题评估与落地方案

## 1. 文档定位

本文承接 `docs/design-v1/10-异常排查系统设计.md` 和 inbox 文档《异常排查细节问题和解决方案评估.md》。

异常排查不是普通问答，而是 AI 广告系统的 Diagnostic OS。目标是把“数据不对”这种模糊表达拆成异常类型、链路、层级、证据、已检查项、未检查项、无法检查项和是否需要升级 Case。

## 2. 异常分类树

一级分类固定为六类：

| 一级分类 | 本质 |
|---|---|
| 数据延迟 | 数据还没到 |
| 数据缺失 | 数据没产生 |
| 回传失败 | SDK/MMP/API/postback 失败 |
| 归因异常 | attribution 逻辑异常 |
| 口径差异 | 统计逻辑不同 |
| 权限/展示问题 | 用户看到的数据不完整 |

二级分类：

- 数据延迟：SKAN 延迟、ETL 未完成、流式计算积压、API 同步延迟、分区未生成。
- 数据缺失：计划无数据、某媒体无数据、某时段无数据、某维度被过滤。
- 回传失败：SDK 未上报、MMP 回传失败、API 签名错误、postback 失败、token 失效。
- 归因异常：click 丢失、install 未匹配、SKAN 覆盖、归因窗口错误、去重失败。
- 口径差异：时区不同、汇率不同、去重逻辑不同、ROI 窗口不同、自然量是否包含、BI 与媒体口径差异。
- 权限/展示问题：无账户权限、行级过滤、数据脱敏、字段隐藏、当前仅看部分媒体。

## 3. 最小诊断字段

通用最小字段：

| 字段 | 是否必须 |
|---|---|
| 项目 | 是 |
| 时间范围 | 是 |
| 指标 | 是 |
| 数据来源 | 是 |
| 查询维度 | 否 |
| 媒体 | 否 |
| 账户 | 否 |

不同异常类型需要追加字段：

- 数据延迟：ETL 批次、分区状态、回传成熟度、当前延迟分钟数。
- 回传失败：app_id、event_name、MMP、postback_status、sdk_version。
- 归因异常：click_time、install_time、attribution_window、device_type、media_source。
- 口径差异：report_a、report_b、timezone、currency、metric_definition。

系统应自动从当前会话、当前页面、项目配置、工具结果中补齐，不能一上来把所有字段都甩给用户。

## 4. 真实检查与 Fake Observability

已检查项、未检查项、无法检查项必须区分。

| 类型 | 含义 |
|---|---|
| 已检查 | 系统实际调用能力检查过 |
| 未检查 | 理论应该检查但还没检查 |
| 无法检查 | 权限、API、数据限制导致不能检查 |

禁止伪检查。只有真实调用过 ETL、API、postback、BI、权限等检查能力，才能在结果中写“已检查”。否则只能标为“未检查”或“无法检查”。

## 5. 诊断置信度

不展示伪精确百分比。采用等级：

| 等级 | 条件 |
|---|---|
| 高 | 有直接证据 |
| 中 | 有间接证据，排除部分原因 |
| 低 | 主要依赖推理 |
| 未知 | 数据不足 |

诊断结论必须说明证据强度、链路覆盖率、是否依赖 AI 推断。

## 6. Case 生成

用户已确认：多轮仍无法定位时，Case 标题、优先级等由后台提示词控制生成，不需要负责人字段。

生成时机：

| 条件 | 是否生成 |
|---|---|
| 自动诊断失败 | 是 |
| 超过 3 轮追问 | 是 |
| 涉及平台接口异常 | 是 |
| 数据链路断裂 | 是 |
| 权限问题 | 一般否 |
| 用户主动要求 | 是 |

Case 字段：

```json
{
  "case_title": "【回传异常】B项目 iOS D1付费事件缺失（2026-05-25）",
  "diagnostic_type": "postback_failure",
  "priority": "P1",
  "project": "B项目",
  "symptom": "",
  "affected_scope": "",
  "checked_items": [],
  "unchecked_items": [],
  "unable_to_check_items": [],
  "suspected_root_causes": [],
  "missing_information": [],
  "temporary_workaround": "",
  "evidence": []
}
```

## 7. 验收规则

- “数据不对”进入 Diagnostic Intent，不直接泛泛追问。
- 诊断结果必须展示已检查、未检查、无法检查。
- 没有真实调用的检查项不得标为已检查。
- 诊断置信度用高/中/低/未知，不用伪精确百分比。
- 多轮无法定位、平台接口异常、数据链路断裂时生成 Case。
- Case 不包含建议负责人字段。
