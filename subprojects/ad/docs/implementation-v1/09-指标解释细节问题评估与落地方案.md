# 指标解释细节问题评估与落地方案

## 1. 文档定位

本文承接 `docs/design-v1/11-指标解释与知识库检索系统设计.md`，补齐内部口径库、外部解释、媒体指标差异、异常排查衔接和记忆沉淀边界。

## 2. 核心结论

指标口径解释必须优先接内部口径库。外部联网解释只作为补充，不能覆盖内部口径。

用户已确认：

- 内部口径库无结果时允许外部解释，因为用户可能问的是外部行业指标。
- 外部解释和内部口径冲突时，优先内部口径。
- 指标解释不进入个人记忆或通用知识自动沉淀。
- 用户问“为什么媒体后台不一样”时，先按指标解释处理，再追问是否继续排查。
- 指标口径各项目统一；不同媒体的媒体指标需要区分；当前不需要时间版本。

## 3. 检索与融合规则

检索顺序：

1. 内部结构化口径库。
2. 受控术语词典。
3. 媒体指标说明。
4. 通用知识库操作手册。
5. 外部联网解释。
6. 通用大模型补充表达。

冲突规则：

- 内部口径库命中时，内部口径为主解释。
- 媒体指标和内部指标差异要并列展示，不合并成一个口径。
- 外部解释只能标注为行业补充。

## 4. “媒体后台不一样”的处理

该问题第一步不是异常排查，而是指标解释。

推荐流程：

1. 解释内部口径与媒体后台口径差异。
2. 展示可能差异来源：时区、归因窗口、去重逻辑、自然量是否包含、币种、回传延迟。
3. 追问用户是否需要继续排查具体项目和时间。

只有用户确认继续排查，或问题中已给出项目、时间、媒体和指标，才进入异常排查 Workflow。

## 5. 数据模型要求

内部口径库至少需要：

```json
{
  "metric_code": "D1_ROAS",
  "display_name": "D1 ROAS",
  "definition": "",
  "formula": "",
  "scope": "all_projects",
  "media_specific": false,
  "media": null,
  "source": "internal_metric_registry",
  "updated_at": "2026-05-26"
}
```

媒体指标需要带 `media` 字段，例如巨量、腾讯、快手。

## 6. 验收规则

- 内部口径命中时，答案必须展示内部来源。
- 内部无结果时可联网解释，并标注为外部补充。
- 内外冲突时内部优先，不能给出外部优先结论。
- “媒体后台不一样”先解释口径，再询问是否排查。
- 指标解释不自动写入个人记忆或通用知识库。
