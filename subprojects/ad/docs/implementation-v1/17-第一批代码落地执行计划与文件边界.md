# 第一批代码落地执行计划与文件边界

## 1. 文档定位

本文承接：

- `14-AgentRuntimeContract与总控运行链路实施方案.md`
- `15-第一批代码实施任务拆解与验收门禁.md`
- `16-智投Chat架构收敛评估与计划调整建议.md`

本文目标是把第一批最低闭环从“任务包”落成可执行代码实施边界。

第一批只聚焦问数最低闭环，不扩展包交付、异常排查、定时报表、资产落库、个人知识库 Key、正式 Case 创建。

## 2. 当前实施目标

第一批必须打通：

```text
用户自然语言问数
  -> Intent Router
  -> ProjectResolution / PermissionCheck
  -> CapabilityPreflight
  -> Slot / Dictionary
  -> Report MCP ToolCall
  -> ResultParser
  -> ResponseContract / MessagePart
  -> 当前聊天渲染体系展示
  -> Trace 记录
```

最低闭环成功标准：

1. 能正确识别问数意图。
2. 能处理顶部项目和用户明示项目冲突。
3. 能在无权限时阻断，不调用 MCP。
4. 能真实发现并调用问数 MCP。
5. 能先字典解析，再报表查询。
6. 能区分成功、空结果、失败、部分成功。
7. 前端文案和真实执行状态一致。
8. Timeline 不展示伪 CoT。
9. 不引入新的聊天渲染框架。

## 3. 实施批次

### P0-1 项目解析与权限冲突

目标：

- 用户明示项目优先于顶部项目。
- 明示项目无权限时阻断，不回退顶部项目。
- 跨项目问数逐项目校验权限。

主要涉及：

- `intent-router.ts`
- `intent-route-engine.ts`
- `context-compiler.ts`
- `conversation-context.ts`
- `report-query-orchestrator.ts`
- 会话发送链路中的项目上下文传递

验收：

- 顶部 A，用户问 B，请求 B。
- 顶部 A，用户问无权限 B，阻断且不请求 A。
- 用户问“这个项目”，未明示项目时可使用顶部项目。
- 项目不明确时追问，不伪造默认项目。

### P0-2 能力发现和预检

目标：

- 问数能力来自 MCP tools/list、报表能力 manifest、字典能力 manifest、admin override。
- MCP 已披露但 Chat 未命中时，归类为 Chat 映射缺口，不默认写成 MCP 缺失。
- 字典能力缺失或失败时，不调用报表 tool。

主要涉及：

- `report-capability-manifest.ts`
- `report-capability-override-store.ts`
- `report-query-policy-store.ts`
- `mcp-server-store.ts`
- `mcp-discovery.ts`
- `report-query-orchestrator.ts`

验收：

- 报表 tool 能进入能力清单。
- 字典 tool 能进入能力清单。
- 禁用关键 tool 后，preflight 返回 unavailable / missing。
- 字典缺失时停止报表查询。

### P0-3 问数执行链路

目标：

- 支持日报、小时报表、ROI、留存、素材、字典查询。
- 按受控术语归一化后的文本选择报表能力。
- 查询结果必须来自真实 MCP 调用。
- 解析失败、schema mismatch、权限失败、空结果不能展示为成功。

主要涉及：

- `controlled-glossary-index.ts`
- `slot-resolver.ts`
- `report-query-orchestrator.ts`
- `report-answer-composer.ts`
- `ReportQueryResultCard.tsx`
- `result-utils.ts`

验收：

- 每类 P0 问数至少有一条可执行路径。
- MCP 调用失败时 result_status 不是 success。
- 空结果有空结果原因和放宽条件建议。
- 部分成功展示成功部分、失败部分和影响。

### P0-4 Result Protocol / MessagePart

目标：

- `ResponseContract` 能派生 `message_parts`。
- `message_parts` 只作为展示协议，不替换 message schema。
- Timeline 由真实事件派生，不展示模型内部推理。

建议最小类型：

```ts
type MessagePart =
  | { type: 'text'; data: { text: string } }
  | { type: 'timeline'; data: { events: AgentProcessEvent[] } }
  | { type: 'tool_call'; data: ToolCallEnvelope }
  | { type: 'table'; data: { columns: string[]; rows: Record<string, unknown>[] } }
  | { type: 'chart'; data: { viz_spec: unknown } }
  | { type: 'action_list'; data: { actions: string[] } }
  | { type: 'source_refs'; data: { refs: SourceRef[] } }
```

主要涉及：

- `types/index.ts`
- `agent-runtime.ts`
- `report-query-orchestrator.ts`
- `report-answer-composer.ts`
- 会话消息 metadata 挂载逻辑

验收：

- 有 `message_parts` 时前端优先协议渲染。
- 无 `message_parts` 时兼容旧消息。
- `tool_call` 绑定真实工具调用。
- `table` / `chart` 来自真实问数结果。
- `action_list` 来自 recommended actions。

### P0-5 前端 UI 四态和 Timeline

目标：

- 保持现有聊天页面框架。
- 在现有渲染体系内补齐成功、空结果、失败、部分成功。
- “思维链”产品语义收敛为“执行过程”。

主要涉及：

- `ChatContainer.tsx`
- `ReportQueryResultCard.tsx`
- `DataVizRenderer`
- `result-utils.ts`

禁止：

- 不引入 `assistant-ui`。
- 不新增独立聊天渲染框架适配层。
- 不替换 Header、Sidebar、Workspace、Drawer、路由、全局状态。
- 不替换 message schema、conversation store、send message API。

验收：

- 旧消息仍可展示。
- 新问数结果优先按 MessagePart / ReportQueryResult 展示。
- 空结果不展示为失败。
- 失败不展示为成功。
- Timeline 不出现“我正在思考”或伪 CoT。
- 全局 antd 样式无污染。

### P0-6 Trace 与验收门禁

目标：

- 每次业务问数有 trace_id。
- Trace 覆盖 route、project、capability、tool call、parse、response。
- 连弩字段最终以 SDK 文档为准，小乔不内建评测平台。

主要涉及：

- `trace.ts`
- `evaluation-adapter.ts`
- `evaluation-runtime-runner.ts`
- `agent-runtime.ts`

验收：

- trace_id 能关联 conversation_id、message_id、user_id、intent、project、tool_call。
- 发送失败不阻断用户回答。
- 原始错误内部可见，前端只显示脱敏错误。

## 4. 文件边界

### 4.1 允许优先修改

| 文件/模块 | 允许改动 |
|---|---|
| `intent-router.ts` | 问数意图、低置信度、上下文偏置、业务域识别 |
| `intent-route-engine.ts` | 多候选评分、角色规则、配置规则融合 |
| `context-compiler.ts` | 项目、角色、上下文、能力信息进入路由上下文 |
| `report-query-orchestrator.ts` | preflight、slot、字典、tool select、result parser、MessagePart 派生 |
| `report-capability-manifest.ts` | MCP tools/list 到问数能力 manifest |
| `report-query-policy-store.ts` | 能力配置、字典能力、默认规则 |
| `agent-runtime.ts` | 事件标准化、Timeline 事件派生 |
| `types/index.ts` | 增加兼容型协议类型 |
| `ChatContainer.tsx` | 现有渲染体系内消费 MessagePart / Timeline |
| `ReportQueryResultCard.tsx` | 问数四态和下一步建议展示 |

### 4.2 谨慎修改

| 文件/模块 | 约束 |
|---|---|
| `useConversation.ts` | 只允许接入 runtime 输出和 metadata，不重写 send message API |
| `conversation-store.ts` | 只允许兼容新增 metadata，不改消息主 schema |
| API route | 只允许补运行时输出，不改已有请求入参兼容性 |
| 全局 CSS | 原则上不改；必须改时不得影响 antd 和页面布局 |

### 4.3 禁止作为第一批主线修改

- Header。
- Sidebar。
- Workspace。
- Drawer。
- 全局路由。
- 全局状态架构。
- 登录和权限主框架。
- 包交付状态机。
- 异常排查 Workflow。
- 资产落库。
- 个人知识库 Key 配置。
- 正式 Case 创建。

## 5. 接口与数据兼容规则

### 5.1 message schema

现有 message 主字段不做破坏性变更。

新增内容只能进入：

- `metadata.response_contract`
- `metadata.message_parts`
- `metadata.tool_call_envelopes`
- `process_events`

### 5.2 send message API

请求入参保持兼容。

允许响应 metadata 增加：

```ts
{
  trace_id?: string
  runtime_id?: string
  response_contract?: ResponseContract
  message_parts?: MessagePart[]
  tool_call_envelopes?: ToolCallEnvelope[]
}
```

前端不得依赖自然语言判断业务成功状态。

### 5.3 MCP 调用

MCP 入参必须来自：

- `effective_project_refs`
- slot resolver
- 字典解析结果
- report query policy
- capability manifest

禁止：

- 使用顶部项目覆盖用户明示项目。
- 未经权限校验就调用 MCP。
- 字典失败后继续调用报表 tool。
- MCP 失败时伪造业务数据。

## 6. 验收用例

### 6.1 项目与权限

| 用例 | 预期 |
|---|---|
| 顶部 A，用户问 B 昨日消耗 | 调用 B |
| 顶部 A，用户问无权限 B | 阻断，不调用 MCP |
| 用户问这个项目昨日 ROI | 使用顶部项目 |
| 用户问 A 和 B 对比，B 无权限 | 阻断或只展示有权限范围，不请求 B |

### 6.2 问数执行

| 用例 | 预期 |
|---|---|
| 昨日消耗 | 日报 tool 调用成功 |
| 今天每小时 ROI | 小时 tool 或小时粒度参数命中 |
| 近 7 日留存 | 留存能力命中 |
| 素材消耗排行 | 素材能力命中 |
| 媒体/终端中文筛选 | 先字典解析，再报表 |

### 6.3 失败闭环

| 场景 | 预期 |
|---|---|
| 字典无匹配 | 追问或提示补充，不调用报表 |
| 报表 tool 超时 | 展示查询失败和可重试建议 |
| schema mismatch | 展示解析失败，保留排查信息 |
| 空结果 | 展示查询条件和放宽建议 |
| 部分工具成功 | 展示部分成功和缺失影响 |

### 6.4 前端展示

| 场景 | 预期 |
|---|---|
| 成功 | 表格/图表/来源/下一步建议 |
| 空结果 | 空结果原因/查询条件/放宽建议 |
| 失败 | 失败阶段/脱敏原因/下一步 |
| Timeline | 结构化执行过程，不展示伪 CoT |
| 旧消息 | 兼容展示 |

## 7. 发布门禁

第一批不得发布，除非全部满足：

- P0 问数测试集基础路径通过。
- 项目冲突用例通过。
- 无权限用例不调用 MCP。
- 字典失败用例不调用报表 tool。
- MCP 失败不会展示“已查询”。
- 空结果不展示为失败。
- 部分成功可解释影响。
- MessagePart 可被前端消费。
- Trace 至少本地可记录完整链路。
- 页面布局无结构性变化。

## 8. 明确不做

第一批不做：

- 引入 LangGraph / DeerFlow 运行时。
- 引入 assistant-ui 或其他聊天渲染框架。
- 多 Agent 编队。
- 包交付真实状态机。
- 异常排查真实 Workflow。
- 定时报表调度。
- 资产真实落库。
- 个人知识库 Key 配置。
- Case 真实创建。
- 市场情报、预测、广告投放自动执行。

这些模块可以继续设计或进入后续批次，但不能阻塞问数最低闭环的第一批代码落地。
