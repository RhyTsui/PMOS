# 小乔智投第四阶段工程实施总清单

## 1. 总体目标

第四阶段目标是把小乔智投从“设计已定义”推进到“可真实执行、可验收、可回放、可沉淀”的工程闭环。

最低闭环标准：

1. 正确路由。
2. 自动补齐信息或追问。
3. 真实调用 MCP / Skill / Workflow 完成执行。
4. 正确解析执行结果。
5. 提供下一步建议。
6. 提供证据来源。
7. 记录 Trace、资产、Case 或失败原因。
8. 系统无力完成时，多轮确认后生成 Case 并告知用户等待处理。

## 2. 批次总览

| 批次 | 目标 | 模块 | 准入状态 |
|---|---|---|---|
| 第一批 | 打通自由对话到真实执行的最低闭环 | 对话路由、项目权限、能力发现、问数最小闭环、Trace 基础发送 | 可启动 |
| 第二批 | 补齐高频用户资产和知识闭环 | 定时报表、资产证据、个人记忆、指标解释、需求沟通 | 有条件启动 |
| 第三批 | 补齐复杂 Workflow 场景 | 包交付、异常排查、失败 Case 复盘 | 有条件启动 |
| 后续期 | 扩展增长与自动化能力 | 市场情报、预测、广告投放自动执行、自动学习规则 | 不启动 |

## 3. 第一批：最低真实执行闭环

### 3.1 对话路由

当前依据：

- `docs/design-v1/01-对话路由系统设计.md`
- `docs/design-v1/06-问数知识策略与配置治理系统设计.md`
- `docs/design-v1/13-能力发现与服务绑定执行闭环系统设计.md`

工程目标：

- 用户自然语言先进入路由、术语归一化、项目解析、能力发现和预检。
- 路由结果必须包含意图、候选能力、最终能力、缺失 slot、追问策略和失败分类。
- 路由规则、运行时配置、知识库、MCP / Workflow 能力必须分层治理。

前端职责：

- 展示追问、阻断、执行中、完成、失败 Case 等状态。
- 不展示内部候选 prompt 文本，不把工具名暴露成用户必须理解的入口。

后端职责：

- 编排 `RouteContext`、`ProjectResolution`、`PermissionContext`、`CapabilityPreflight`。
- 未通过预检时不进入真实工具调用。
- 能力缺失时不继续追问无意义执行字段。

MCP / Workflow / Skill 职责：

- 提供能力注册、schema、健康状态和错误结构。
- 不由 Chat 猜测工具是否存在。

验收标准：

- 用户问 B 项目时，即使顶部选择 A，也不能请求 A 数据。
- 用户问无权限项目时阻断，不回退顶部项目。
- 已上线 MCP 未命中时能归类为能力发现或绑定问题。
- 未真实调用工具时不输出完成口吻。

阻断缺口：

- `D-GAP-013`：能力发现快照与测试集映射样本不足。

### 3.2 项目权限与跨项目上下文

当前依据：

- `docs/design-v1/02-项目权限与跨项目上下文系统设计.md`

工程目标：

- 顶部项目只是默认上下文，用户明示项目优先。
- 会话、资产、自动化任务都绑定项目引用，并按最新权限动态展示。
- 包交付为单项目能力，问数和自动化允许多项目。

前端职责：

- 打开历史会话时，右上角项目切换到会话当时默认项目；无权限时不切换并提示。
- 我的资产、自动化新增和编辑增加项目字段、项目查看和筛选。
- 对无权限项目内容展示遮蔽状态。

后端职责：

- 所有工具调用统一使用权限校验后的 `effective_project_refs`。
- 读取会话、资产、任务时按最新项目权限过滤。
- 保留 Trace 原始项目引用，不因前端遮蔽删除。

验收标准：

- 权限变化后，历史会话和资产中的失权项目数据不可见。
- 跨项目分析可用，但每个项目都必须经过权限校验。
- 包交付请求只能绑定一个项目。

阻断缺口：

- `D-GAP-006`：多项目部分可见展示文案和遮蔽粒度需统一。

### 3.3 能力发现与服务绑定

当前依据：

- `docs/design-v1/04A-MCP能力发现与问数归属矩阵.md`
- `docs/design-v1/13-能力发现与服务绑定执行闭环系统设计.md`

工程目标：

- 从运行态 MCP / Skill / Workflow 生成能力事实，而不是用关键词假设能力存在。
- 每个业务意图绑定 capability id、schema version、健康状态、输入输出摘要和错误分类。
- 能力发现结果进入路由、预检、Trace 和后台管理。

前端职责：

- 后台展示能力发现摘要、健康状态、覆盖域和风险。
- 对人工 override 提供可编辑表单、差异预览、灰度发布和回滚。

后端职责：

- 维护 CapabilityRegistry。
- 记录服务绑定、预检、调用、解析和失败分类。
- 对已披露但未命中的 MCP tool 输出绑定缺口。

验收标准：

- 能列出当前可用报表 MCP、字典 MCP、包交付 Workflow、诊断 Workflow。
- MCP disconnected、tool not found、schema mismatch、权限失败能分开识别。
- 后台 override 不直接改能力事实，只改变路由权重或适配策略。

阻断缺口：

- `D-GAP-013`：能力发现快照验收样本不足。

### 3.4 问数最小闭环

当前依据：

- `docs/design-v1/04-数据查询与报表系统设计.md`
- `docs/design-v1/04A-MCP能力发现与问数归属矩阵.md`
- `docs/design-v1/07-问数编排与结果呈现系统设计.md`
- `docs/design-v1/07A-问数闭环与测试集验收细化设计.md`

工程目标：

- 报表 MCP 已上线能力必须被发现、绑定、调用、解析。
- 问数链路覆盖报表域识别、slot 补参、字典解析、真实报表调用、后处理、UI 渲染、下一步建议。
- 查询结果只有用户保存后写入资产。

前端职责：

- 展示结构化结果卡片、表格、图表、筛选条件、指标口径、来源、更新时间、下一步建议。
- 提供保存到我的资产入口。
- 对空结果、部分成功、权限失败、解析失败展示不同状态。

后端职责：

- 根据 Manifest 选择报表 tool，不靠关键词硬猜。
- 处理日期、媒体、终端、团队、应用类型、账户、包体、优化师等 slot。
- 支持 TopN、排序、环比、同期、差异比例、总计核对、多轮继承、条件分支。
- 失败时生成可分类错误，必要时创建 Case。

MCP 职责：

- 提供真实 server、tool、input schema、output schema、错误码、权限失败结构。

验收标准：

- `智投Chat_广告业务（问数）测试集_预期精简版_v3.xlsx` 的 P0 用例通过取数自测。
- 不只验证 MCP 调用，还要验证 UI 渲染、来源、下一步建议和失败分类。
- 未能调用真实报表 MCP 时不能输出数据结论。

阻断缺口：

- `D-GAP-001`：缺报表 MCP 成功、空结果、权限失败、schema mismatch 返回样本。
- `D-GAP-002`：测试集不覆盖前端组件、可视化渲染、下一步建议。

### 3.5 Trace 基础发送

当前依据：

- `docs/design-v1/14-连弩Trace评测接入系统设计.md`

工程目标：

- 每次真实业务请求都有 `trace_id`。
- Trace 记录路由、项目解析、术语归一化、能力发现、预检、真实调用、结果解析、证据、资产、Case、闭环状态。
- 小乔只生成并发送结构化 Trace，不重建连弩评测平台。

前端职责：

- 不需要向普通用户展示完整 Trace。
- 可在调试或后台场景展示 trace id、发送状态和错误摘要。

后端职责：

- 生成 `XiaoqiaoTraceEnvelope`。
- 发送到连弩或记录发送失败。
- Trace 失败不阻断用户主回答，但生产配置缺失应在发布前阻断。

连弩职责：

- 完整回放。
- 测试集管理。
- 断言规则、证据规则、评测报告。

验收标准：

- 问数请求能回放到路由、项目、slot、字典、报表 MCP、解析和 UI 类型。
- 工具未真实调用时 Trace 不能标记为 `completed`。
- 失败 Case 在 Trace 中包含 `case_refs`。

阻断缺口：

- `D-GAP-008`：TraceEnvelope 与连弩 SDK 字段映射未最终冻结。

## 4. 第二批：高频资产与知识闭环

### 4.1 定时报表与自动化任务

当前依据：

- `docs/design-v1/08-定时报表与自动化任务系统设计.md`
- `docs/design-v1/13A-资产与证据沉淀系统设计.md`

工程目标：

- 定时报表创建时必须确认数据延迟策略。
- 自动化任务绑定项目，允许多项目。
- 定时报表和自动化产物默认进入资产。

前端职责：

- 自动化新增和编辑增加项目字段。
- 支持项目查看、筛选、任务状态、执行记录和产物入口。

后端职责：

- 维护任务状态、执行记录、数据延迟策略、产物资产引用。
- 自动产物按项目权限动态过滤。

阻断缺口：

- `D-GAP-014`：调度服务返回状态、延迟策略、产物资产引用样本需补。

### 4.2 资产与证据沉淀

当前依据：

- `docs/design-v1/13A-资产与证据沉淀系统设计.md`

工程目标：

- 即时问数结果只有用户保存后入资产。
- 自动化产物默认入资产。
- EvidenceRef 支撑结论来源，AssetRecord 支撑回看和复用。
- 权限变化后动态隐藏失权项目内容。

前端职责：

- 我的资产支持项目字段、项目筛选、归档、来源查看。
- 证据展示必须脱敏，不暴露无权限原始数据。

后端职责：

- 创建 AssetRecord、EvidenceRef、AssetVisibilityResult。
- 按最新项目权限过滤资产和证据。

验收标准：

- 未保存的即时查询结果不出现在我的资产。
- 用户保存后能看到来源消息、项目、证据。
- 失权项目数据不可见。

阻断缺口：

- `D-GAP-012`：敏感级别、脱敏规则、原始引用展示权限未细化。

### 4.3 个人记忆与知识库隔离

当前依据：

- `docs/design-v1/03-个人记忆与知识库用户隔离系统设计.md`

工程目标：

- 个人记忆按登录用户隔离，不能继续使用默认 `user-001`。
- 左下角弹窗提供知识库入口、个人知识库 Key 配置、校验状态。
- 系统通用知识库只读，个人记忆写入用户个人知识库。

前端职责：

- 在左下角弹窗增加知识库按钮。
- 支持知识库跳转地址、个人 Key 填写、状态校验、同步失败提示。

后端职责：

- 记忆 API 从登录态解析用户作用域，不信任前端传入 user_id。
- 未配置个人 Key 时保存为待同步，不提示已同步。
- RAG 来源区分通用知识库、个人记忆、个人知识库、工具结果和外部来源。

阻断缺口：

- `D-GAP-007`：个人知识库配置交互和校验反馈需补完整流程。

### 4.4 指标解释

当前依据：

- `docs/design-v1/11-指标解释与知识库检索系统设计.md`

工程目标：

- 指标口径解释必须先接内部结构化口径库。
- 外部联网只作为行业背景补充，不覆盖内部口径。
- 内外冲突时展示冲突说明和内部优先原因。

前端职责：

- 展示指标定义、公式、适用范围、来源、更新时间、冲突说明。

后端职责：

- 优先查询内部口径库。
- 外部资料只作为补充来源。
- EvidenceRef 绑定口径来源。

阻断缺口：

- `D-GAP-009`：内部口径库结构化字段样本不足。

### 4.5 需求沟通与 Case

当前依据：

- `docs/design-v1/12-需求沟通与Case闭环系统设计.md`

工程目标：

- 模糊需求先追问并形成结构化草稿。
- 用户确认后调用真实服务创建 Case 或需求池记录。
- 不能把整理文案当成已提交。

前端职责：

- 展示结构化草稿、缺失字段、确认入口、提交结果。

后端职责：

- 按需求类型生成追问模板。
- 调用真实 Case / 需求池服务并返回编号。
- 绑定原始对话、Evidence、Trace。

阻断缺口：

- `D-GAP-011`：需求类型追问模板、确认字段、提交标准需补。

## 5. 第三批：复杂 Workflow 闭环

### 5.1 包交付与联调

当前依据：

- `docs/design-v1/09-包交付与联调系统设计.md`
- `docs/design-v1/09A-包交付状态机与服务对接细化设计.md`

工程目标：

- 包交付为单项目能力。
- 上报检查通过后，媒体包等待媒体后台更新，官方包等待智投后台更新。
- 检测到后台更新后触发联调。
- 可投结论由 Workflow / MCP 证据派生，禁止人工直接改为可投。
- 联调失败自动生成 Case。

前端职责：

- 展示当前包、历史包、新版本、状态、报告、失败原因、Case。
- 历史包默认收起，旧包在新包成功后标记为已被新包替代。

后端职责：

- 维护包交付状态机。
- 解析上报检查、后台更新检测、联调报告。
- 生成可投 / 不可投结论和失败 Case。

MCP / Workflow 职责：

- 数据上报报告 MCP。
- 媒体后台更新检测接口。
- 智投后台更新检测接口。
- 联调检查 Workflow / Skill。

阻断缺口：

- `D-GAP-003`：缺上报检查报告真实字段样本。
- `D-GAP-004`：缺媒体后台 / 智投后台更新检测字段样本。
- `D-GAP-005`：缺联调报告、截图、失败原因枚举样本。

### 5.2 异常排查

当前依据：

- `docs/design-v1/10-异常排查系统设计.md`

工程目标：

- 支持没量、没回传、ROI 下降、数据不一致、联调失败等诊断。
- 没有 Evidence 的原因只能标记为假设，不输出确定结论。
- 多轮仍无法定位时生成 Case。

前端职责：

- 展示诊断结论、证据链、假设、风险、下一步建议。

后端职责：

- 调用诊断 Workflow。
- 汇总 EvidenceRef。
- 区分确定结论和待验证假设。

阻断缺口：

- `D-GAP-010`：诊断 Workflow 返回样本不足。

### 5.3 失败 Case 复盘

工程目标：

- 所有多轮仍不能完成、工具失败不可恢复、能力缺失、权限阻断的场景，都要沉淀失败 Case 或可评测样本。
- Case 必须包含原始问题、已确认信息、缺失信息、已调用能力、失败原因、下一步建议。

验收标准：

- 失败不会静默结束。
- 用户知道当前无法完成的原因和等待处理路径。
- 产研能通过 Trace / Case 复盘失败链路。

## 6. 后续期能力

以下能力不进入一期工程实施：

- 市场情报：二期。
- 预测：三期。
- 广告投放自动执行：四期。
- 自动学习规则：当前只允许作为规则候选、Case 样本、评测样本沉淀，不能按裸 Agent 自学习实施。

## 7. 全局验收门禁

### 7.1 功能门禁

- 所有业务结论必须来自真实工具、Workflow、结构化口径库或明确知识来源。
- 所有工具调用必须经过项目权限校验。
- 所有失败必须有分类、用户可理解反馈和下一步建议。
- 所有自动化产物默认进入资产。

### 7.2 防假功能门禁

- 无真实工具调用，不得输出数据、包状态、联调结论、可投结论。
- 未命中能力不得假装能力不存在，必须区分未发现、未绑定、不可用、无权限。
- 知识库不能替代实时业务数据。
- 设计缺口未关闭时，只能标记为有条件实施或阻断。

### 7.3 测试门禁

- 问数测试集 P0 用例必须通过。
- 项目冲突和权限阻断必须有回归用例。
- MCP 空结果、权限失败、schema mismatch 必须有样本。
- Trace 至少覆盖路由、项目、能力、调用、解析、闭环状态。
- UI 验收必须覆盖结果渲染、来源、下一步建议、保存资产入口。
