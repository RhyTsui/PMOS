# 小乔智投第一批最低闭环实施清单

## 1. 批次目标

第一批只解决“自由对话到真实问数执行”的最低闭环，不扩展包交付、定时报表、资产中心、异常诊断等复杂场景。

交付目标：

1. 能正确识别问数类业务意图。
2. 能处理顶部项目和用户明示项目冲突。
3. 能从运行态发现已上线 MCP 能力。
4. 能在追问前完成项目、权限、能力、slot、schema 预检。
5. 能真实调用问数 MCP。
6. 能解析结果并驱动 UI 展示。
7. 能提供证据来源和下一步建议。
8. 能发送或记录 Trace。
9. 失败时能分类、追问、重试或生成 Case，不输出完成口吻。

## 2. 工程任务包总览

| 任务包 | 目标 | 主要责任方 | 准入状态 |
|---|---|---|---|
| P1-01 路由主链路收敛 | 统一 RouteDecision、ProjectResolution、CapabilityPreflight | Chat 后端 | 可实施 |
| P1-02 项目权限执行底座 | 工具调用只使用有效项目，展示按最新权限过滤 | Chat 后端 / 前端 | 可实施，文案需补 |
| P1-03 全局能力发现最小版 | 运行态 MCP / Skill / Workflow 形成 CapabilityRegistry | Chat 后端 / 后台 | 有条件实施 |
| P1-04 问数 MCP 真实执行 | 报表域路由、slot、字典、报表 tool、结果解析 | Chat 后端 / MCP | 有条件实施 |
| P1-05 问数 UI 闭环 | 成功、空结果、失败、部分成功的结果展示和建议 | 前端 | 有条件实施 |
| P1-06 Trace 基础发送 | 生成 TraceEnvelope，发送连弩或记录失败 | Chat 后端 / 连弩 | 有条件实施 |
| P1-07 第一批验收集 | 覆盖路由、项目、能力、调用、解析、UI、Trace | 测试 / Chat 后端 | 有条件实施 |

## 3. P1-01 路由主链路收敛

### 3.1 当前基础

已有基础：

- intent router。
- intent route rules。
- context compiler。
- slot resolver。
- report query orchestrator。
- controlled glossary index。

主要问题：

- 路由、项目解析、能力发现和预检仍容易分散。
- 顶部项目上下文可能被误当成本轮请求项目。
- 能力不可用、缺 slot、权限失败、schema 不匹配的分类需要统一。

### 3.2 实施内容

后端需要形成统一路由输出：

```ts
type FirstBatchRouteDecision = {
  route_id: string
  conversation_id: string
  message_id: string
  raw_text: string
  normalized_text: string
  intent_key: string
  intent_domain: 'report_query' | 'general_answer' | 'unsupported'
  confidence: number
  project_resolution: ProjectResolution
  capability_candidates: CapabilityCandidate[]
  selected_capability?: CapabilityCandidate
  preflight: CapabilityPreflightResult
  next_action:
    | 'ask_clarification'
    | 'call_service'
    | 'answer_general'
    | 'create_case'
    | 'show_boundary'
}
```

必须写进代码的规则：

- 明示项目优先于顶部项目。
- 明示项目无权限时阻断，不回退顶部项目。
- 能力未发现或不可用时不继续追问业务执行字段。
- 缺必填 slot 时只追问能让执行继续的字段。
- 未真实调用工具不得输出数据结论、提交成功、执行完成。

动态配置：

- route terms。
- 术语 alias。
- 能力权重。
- 追问文案。
- 失败文案。

### 3.3 验收

- 顶部选 A，用户问 B 项目，最终请求 B。
- 顶部选 A，用户问无权限 B，阻断且不请求 A。
- 用户问“今天消耗”，缺项目时按上下文或追问，不伪造项目。
- 用户问非业务通用问题时可进入 `general_answer`，但不得访问内部项目数据。
- 已上线 MCP 发现失败时，错误归类为能力发现或绑定问题。

## 4. P1-02 项目权限执行底座

### 4.1 实施内容

后端统一输出：

```ts
type ProjectResolution = {
  ui_selected_project_ref?: string
  explicit_project_mentions: Array<{
    raw: string
    project_ref?: string
    confidence: number
    matched_by: 'exact_name' | 'alias' | 'app_id' | 'history' | 'fuzzy'
  }>
  effective_project_refs: string[]
  resolution_source:
    | 'explicit_user_project'
    | 'ui_selected_project'
    | 'cross_project_compare'
    | 'history_inherited'
    | 'clarification_required'
  conflict_detected: boolean
  clarification_needed: boolean
  permission_status: 'allowed' | 'partial_allowed' | 'denied' | 'unknown'
}
```

工具请求必须统一携带：

```ts
type ProjectAwareExecutionContext = {
  user_scope_key: string
  role_id: string
  allowed_project_refs: string[]
  project_resolution: ProjectResolution
  effective_project_refs: string[]
}
```

前端需要支持：

- 项目冲突追问。
- 无权限提示。
- 部分项目不可见提示。
- 最终查询项目展示。

### 4.2 第一批只做的范围

第一批必须覆盖：

- Chat 本轮请求项目解析。
- 问数工具调用项目校验。
- Trace 项目字段。
- UI 展示最终查询项目。

第一批不强制完成：

- 所有历史会话动态遮蔽。
- 我的资产项目筛选。
- 自动化任务项目权限过滤。

这些放到第二批资产和自动化闭环中完成。

### 4.3 验收

- 项目别名冲突时必须追问。
- APPID 明确时优先按 APPID 匹配。
- 跨项目问数时每个项目都做权限校验。
- 能力只支持单项目时，提示选择一个项目或拆分任务。

## 5. P1-03 全局能力发现最小版

### 5.1 实施内容

第一批不要求完成所有业务域的全量能力注册，但必须完成最小可用能力发现：

```ts
type CapabilityCandidate = {
  capability_id: string
  domain: 'data_report' | 'dictionary' | 'general_answer'
  intent_keys: string[]
  binding_type: 'mcp_tool' | 'skill' | 'workflow' | 'internal_api' | 'model_answer'
  binding_ref: string
  status: 'available' | 'degraded' | 'unavailable' | 'missing'
  schema_version?: string
  required_slots: string[]
  project_scope: 'none' | 'single_project' | 'multi_project_allowed'
}
```

能力来源：

- MCP `tools/list`。
- 已有 report capability manifest。
- 运行时 override。
- Skill / Workflow 合约只做只读纳入，不在第一批强制全量接通。

后台治理第一批必须提供：

- 能力发现摘要。
- 报表工具数。
- 字典工具数。
- unavailable / schema mismatch / disconnected 统计。
- 某条问数测试用例命中的 capability。

### 5.2 不允许的实现

- 不能只用关键词判断“系统有能力”。
- 不能 MCP 已披露但 Chat 未命中时写成 MCP 缺失。
- 不能由知识库声明能力可执行。

### 5.3 验收

- 当前运行态可用报表 tool 能出现在能力清单。
- 当前运行态可用字典 tool 能出现在能力清单。
- 禁用某个 tool 后，路由能进入不可用或缺能力分支。
- schema 变化后能标记 schema mismatch 或 adapter 缺口。

阻断项：

- `D-GAP-013`：需要补能力发现快照与测试集问题映射样本。

## 6. P1-04 问数 MCP 真实执行

### 6.1 实施内容

问数后端链路：

```text
raw user text
  -> term normalization
  -> report question type
  -> project resolution
  -> slot resolution
  -> dictionary calls
  -> report tool selection
  -> schema adapter
  -> mcp call
  -> result parser
  -> result composer
  -> ui contract
```

必须支持的 `ReportQuestionType`：

- `ad_daily_report`
- `ad_hour_report`
- `ad_roi_report`
- `ad_retention_report`
- `ad_material_report`
- `ad_dictionary_lookup`
- `report_diagnosis_candidate`

必须支持的 slot：

- 项目 / appId。
- 日期和时间粒度。
- 媒体。
- 终端。
- 团队。
- 应用类型。
- 账户。
- 包体。
- 优化师。
- ROI 类型。
- 留存类型。
- 自然量 / 广告量。

字典解析要求：

- 媒体、终端、团队、应用类型、账户、包体、优化师必须走字典 tool 或已验证 alias。
- 字典空结果或多候选时不继续调用报表 tool。
- 字典 tool 不可用时不能伪造 ID。

结果解析输出：

```ts
type FirstBatchReportResult = {
  status:
    | 'success'
    | 'partial_success'
    | 'empty'
    | 'missing_input'
    | 'dictionary_unmatched'
    | 'permission_denied'
    | 'tool_failed'
    | 'parse_failed'
    | 'not_configured'
  question_type: ReportQuestionType
  tool_name?: string
  input_summary: Record<string, unknown>
  rows: Array<Record<string, unknown>>
  columns: string[]
  date_range?: { startDate: string; endDate: string }
  resolved_filters: Record<string, unknown>
  evidence_refs: string[]
  recommended_actions: RecommendedAction[]
}
```

### 6.2 第一批后处理范围

第一批必须做：

- 表格列提取。
- 数值列识别。
- 空结果说明。
- 复合查询分块。
- 基础下一步建议。

第一批可延后：

- TopN。
- 环比 / 同比。
- 差异比例。
- 总计与明细核对。
- 复杂派生指标。

### 6.3 验收

- 问数测试集 P0 用例能完成能力映射。
- 日报、小时、ROI、留存、素材至少有可执行路径或明确缺口。
- 字典解析失败时不调用报表 tool。
- MCP 调用失败时状态不是 `success`。
- 解析失败时生成工程排查 Case 或失败记录。

阻断项：

- `D-GAP-001`：缺报表 MCP 成功、空结果、权限失败、schema mismatch 返回样本。

## 7. P1-05 问数 UI 闭环

### 7.1 实施内容

第一批 UI 至少支持四类状态：

| 状态 | 展示要求 |
|---|---|
| 成功 | 条件摘要、核心摘要、表格、来源、更新时间、下一步建议 |
| 空结果 | 空结果原因、查询条件、放宽条件建议 |
| 失败 | 失败位置、失败原因、可执行下一步 |
| 部分成功 | 成功子结果和失败子结果分块展示 |

结果卡必须展示：

- 最终查询项目。
- 时间范围。
- 筛选条件。
- 数据来源。
- 工具调用状态摘要。
- 下一步建议。

第一批只预留，不强制完成：

- 保存到我的资产真实落库。
- 高级图表。
- 复合查询计划可视化。

### 7.2 验收

- 成功结果不能只输出自然语言，必须有结构化结果区域。
- 失败结果不能复用成功卡片样式。
- 空结果必须和 tool 失败区分。
- 下一步建议必须随状态变化。

阻断项：

- `D-GAP-002`：现有测试集主要覆盖取数，不覆盖前端组件、可视化渲染、下一步建议。

## 8. P1-06 Trace 基础发送

### 8.1 实施内容

第一批 Trace 至少覆盖：

```ts
type FirstBatchTraceEnvelope = {
  trace_id: string
  conversation_id: string
  message_id: string
  user_id: string
  role_id: string
  route_context: {
    original_utterance: string
    normalized_terms: unknown[]
    candidate_intents: unknown[]
    final_intent: string
  }
  project_context: {
    ui_selected_project_ref?: string
    explicit_project_refs: string[]
    effective_project_refs: string[]
    conflict_status: 'none' | 'needs_confirm' | 'blocked_no_permission'
  }
  capability_context: {
    selected_capability_id?: string
    candidate_capabilities: unknown[]
    preflight_status: 'passed' | 'need_followup' | 'blocked'
    missing_slots: string[]
  }
  execution_context: {
    tool_calls: TraceToolCallRecord[]
  }
  result_context: {
    result_status: string
    ui_contract_type?: string
    evidence_refs: string[]
    case_refs: string[]
  }
  completion_status: TraceCompletionStatus
}
```

发送策略：

- 本地开发允许关闭。
- 测试 / 生产发布前必须配置。
- 发送失败不阻断用户回答。
- 发送失败必须记录本地状态，支持重试或告警。

### 8.2 验收

- 每次问数请求有 `trace_id`。
- 项目冲突能从 Trace 看到顶部项目、明示项目、最终项目。
- 工具未调用时 Trace 不得标记 `completed`。
- 工具失败时 Trace 有错误类型和 call id。

阻断项：

- `D-GAP-008`：TraceEnvelope 与连弩 SDK 字段映射未最终冻结。

## 9. P1-07 第一批验收集

### 9.1 必测场景

路由与项目：

1. 顶部 A，用户问 B 项目昨天消耗，请求 B。
2. 顶部 A，用户问无权限 B，阻断，不请求 A。
3. 用户问“这个项目昨天消耗”，请求顶部项目。
4. 用户问 B 和当前项目对比，校验 A+B 权限。
5. 项目别名多候选，追问确认。

问数：

1. 日报查询。
2. 小时报表查询。
3. ROI 查询。
4. 留存查询。
5. 素材查询。
6. 媒体筛选。
7. 终端筛选。
8. 团队筛选。
9. 包体筛选。
10. 优化师筛选。

失败：

1. 字典空结果。
2. 字典多候选。
3. MCP tool 不可用。
4. MCP 权限失败。
5. MCP schema mismatch。
6. MCP 返回空 rows。
7. 结果解析失败。

UI 与 Trace：

1. 成功卡展示结构化表格和来源。
2. 空结果卡展示放宽条件建议。
3. 失败卡展示失败位置和下一步。
4. Trace 能回放路由、项目、能力、调用、解析。

### 9.2 门禁

第一批完成必须满足：

- P0 问数用例不出现 tool mismatch / not selected。
- 项目冲突用例不出现静默请求顶部项目。
- 字典失败不继续调用报表 tool。
- 无真实 tool call 不输出数据结论。
- Trace 覆盖核心阶段。
- UI 有成功、空结果、失败、部分成功四态。

## 10. 第一批不做范围

为避免再次失焦，第一批不做：

- 包交付状态机和联调触发。
- 定时报表创建和调度。
- 我的资产真实落库。
- 个人知识库 Key 配置。
- 指标解释完整口径库。
- 需求沟通真实 Case 创建。
- 异常排查 Workflow。
- 市场情报、预测、广告投放自动执行。

这些进入第二批、第三批或后续期。

## 11. 第一批交付顺序

1. 固定项目解析和权限底座。
2. 固定能力发现最小版。
3. 固定问数报表域、slot、字典、schema adapter。
4. 固定真实 MCP 调用和结果解析。
5. 固定 UI 四态展示契约。
6. 固定 Trace 基础发送。
7. 接入第一批验收集。
