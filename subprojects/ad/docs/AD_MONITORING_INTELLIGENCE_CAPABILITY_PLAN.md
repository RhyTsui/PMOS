# 广告监测系统智能化能力建设规划

## 一、背景与目标

### 1.1 业务背景

广告监测系统的核心工作是：
1. **系统问题排查**：监测链接配置、包配置、事件上报、数据入库等
2. **操作问题排查**：账户授权、API 对接、数据采集等
3. **投放策略分析**：媒体效果、ROI、留存等
4. **游戏问题定位**：归因准确性、回推成功率等

**痛点**：
- 缺乏系统性监控，每次投放有反馈都要人力检查
- 归因逻辑复杂，不同端逻辑不同，投放人员无法自助理解，次次问次次解释
- 与媒体数据对账频繁，口径差异大，排查成本高
- 需要批量分析能力（不是单个设备，而是一批数据的特征分析）

### 1.2 目标定位

**明确边界**：这不是一个"监控告警系统"，而是**智能化分析与解释层**。

**核心职责**：
- ✅ 帮助用户**理解**现有数据和逻辑（归因解释、口径说明）
- ✅ 帮助用户**查询**和**对比**数据（跨系统对账、用户分群）
- ✅ 帮助用户**诊断**问题（基于现有数据的根因分析）
- ✅ 生成**报告和解释**（自然语言、可视化）

**不是我们的职责**：
- ❌ 实时监控系统（后端/运维职责）
- ❌ 数据管道/ETL（数仓职责）
- ❌ 数据采集和存储（数仓职责）
- ❌ 实时告警基础设施（后端/运维职责）

## 三、我们能交付什么

### 3.1 核心能力（不依赖数仓重构）

#### 能力 1：归因逻辑解释引擎

**目标**：让归因逻辑可解释，投放人员可以自助理解

**实现方式**：
- 基于现有 MCP 工具（设备归因结果、用户行为上报、预处理结果等）
- 追溯归因链路（点击 → 预处理 → 归因匹配 → 结果）
- 解释为什么归因到某个渠道（优先级、时间窗口、去重逻辑）
- 对比分析（为什么不是其他渠道）

**依赖**：
- ✅ 现有 MCP 工具（已具备）
- ❌ 不需要数仓提供新数据

**交付物**：
- 归因解释查询功能（Chat 交互）
- 归因链路可视化
- 归因逻辑文档自动生成

**工作量**：2 周

#### 能力 4：多层级下探归因分析

- 最差的几个是哪些？
- 历史趋势：是差了很多天？还是之前很好现在在衰退？
- 每个层级背后的分类标签（策略标签、素材标签等）
- 多团队对比：多个团队投同一个游戏，数据对比、各层级对比、各策略对比

**实现方式**：
- 多层级数据查询（媒体 → 账户 → 广告组 → 广告 → 素材）
- 每层级的性能指标（成本、ROI、激活率、注册率等）
- 层级下钻（drill-down）：从大盘 → 媒体 → 账户 → 广告组 → 广告 → 素材
- 排序与筛选：找出最差的 N 个
- 趋势分析：对比历史数据，识别趋势（持续差、衰退、突然变差等）
- 策略标签透视：每个层级的策略分类（素材类型、应用类型、投放策略等）
- 对比分析：跨团队、跨策略、跨层级的对比

**依赖**：
- ✅ 现有 MCP 工具（广告明细表、媒体报表等）
- ⚠️ 需要广告层级数据（广告组、广告、素材）
- ⚠️ 需要策略标签数据（素材标签、应用类型标签等）

**交付物**：
- 多层级下探分析功能
- 每层级的最差 TOP N 列表
- 趋势分析图表
- 策略标签透视
- 跨团队/策略对比报告

**工作量**：3 周

**风险**：中
- 广告层级数据可能不完整
- 策略标签可能缺失
- 多层级查询性能可能有问题

#### 能力 5：用户质量分析与风控

**目标**：从多维度指标分析用户质量，识别假量和异常用户，评估投放效果

**核心场景**：
- **多维度指标分析**：
  - 量级指标：消耗量级
  - 互动指标：点击率、转化率
  - 获客指标：激活率、注册率
  - 变现指标：首日付费率、七日付费率、付费成本、注册成本、有效成本、激活成本
  - 留存指标：留存、次留、7留
  - 价值指标：LTV、ARPU、付费次数
  
- **用户质量评估**：
  - 假用户检测：注册后没有用户行为的
  - 充值异常：充值都是6元的（可能是刷单）
  - 用户付费分层：高价值用户 vs 低价值用户 vs 无价值用户
  
- **用户活跃与粘性分析**：
  - 用户活跃度：登录频率、在线时长
  - 用户粘性：回访率、留存率
  - 用户生命周期：从注册到付费的转化路径
  
- **风控识别**：
  - 假量识别：是否存在买入假量
  - 异常行为：批量注册、批量充值、异常IP
  - 欺诈检测：刷单、薅羊毛、机器人

**实现方式**：
- 多指标关联分析：从消耗 → 点击 → 转化 → 激活 → 注册 → 付费 → 留存，全链路分析
- 用户分层：按付费金额、活跃度、留存等维度对用户分层
- 异常检测：识别异常行为模式（注册后无行为、充值金额单一、批量操作等）
- 对比分析：不同渠道/媒体的用户质量对比
- 风控规则：基于历史数据建立风控规则，识别假量和欺诈

**依赖**：
- ✅ 现有 MCP 工具（激活表、注册表、付费表、用户行为表）
- ⚠️ 需要用户行为数据（登录、游戏行为等）
- ⚠️ 需要充值明细数据（充值金额、充值时间等）
- ⚠️ 需要用户画像数据（设备信息、IP、地域等）

**交付物**：
- 多维度用户质量分析报告
- 用户分层分析（高价值/低价值/无价值）
- 假量识别报告
- 异常用户列表
- 风控建议

**工作量**：3 周

**风险**：中-高
- 用户行为数据可能不完整
- 充值明细数据可能缺失
- 风控规则需要持续优化

### 3.2 需要数仓支持的能力

#### 能力 6：长线 ROI 与 LTV 跟踪

**目标**：跟踪长线 ROI、LTV、留存，计算回本天数，预测未来趋势

**核心场景**：
- **长线 ROI 跟踪**：
  - 按渠道/媒体跟踪 7天/14天/30天/60天/90天 ROI
  - 识别哪些渠道的长线 ROI 更好
  - 对比不同渠道的 ROI 曲线
  
- **LTV 跟踪**：
  - 按渠道/媒体/用户群跟踪 LTV 曲线
  - 识别高价值用户来源
  - 预测最终 LTV
  
- **留存跟踪**：
  - 次留、3留、7留、14留、30留、60留、90留
  - 按渠道/媒体/用户群对比留存曲线
  - 识别留存差的渠道
  
- **回本天数计算**：
  - 计算每个渠道/媒体的回本天数
  - 识别回本慢的渠道
  - 优化投放策略
  
- **预测**：
  - 预测未来 7天/14天/30天的 ROI
  - 预测最终 LTV
  - 预测回本时间

**实现方式**：
- 长线数据聚合：按天/周/月聚合 ROI、LTV、留存数据
- 曲线分析：绘制 ROI 曲线、LTV 曲线、留存曲线
- 回本天数计算：基于历史数据计算回本天数
- 预测模型：基于时间序列分析预测未来趋势

**依赖**：
- ⚠️ 需要长线数据（至少 90天的用户行为数据）
- ⚠️ 需要数仓提供预聚合的长线指标
- ⚠️ 需要预测模型基础设施

**交付物**：
- 长线 ROI 跟踪报告
- LTV 曲线分析
- 留存曲线对比
- 回本天数计算报告
- 未来趋势预测

**工作量**：4 周

**风险**：高
- 强依赖数仓提供长线数据
- 预测模型需要持续优化
- 数据量大，性能可能有问题

**决策**：**暂缓**，等数仓重构完成后再评估

- 跨团队/策略对比报告

**风险**：中
- 跨表查询性能可能有问题
- 多层级查询性能可能有问题

**备选方案**：
- 如果用户分群跨表查询性能不行，只做简单分群统计
- 如果广告层级数据不完整，只做到广告组级别
- 如果策略标签缺失，先不做标签透视

---

### Phase 4：用户质量分析与风控（3 周）

**目标**：多维度用户质量分析，识别假量和异常用户

**任务**：
- Week 1：多维度指标关联分析（消耗 → 点击 → 转化 → 激活 → 注册 → 付费 → 留存）
- Week 2：用户分层 + 异常检测（假用户、充值异常、批量操作）
- Week 3：风控规则 + 对比分析

**依赖**：
- ✅ 现有 MCP 工具（激活表、注册表、付费表）
- ⚠️ 用户行为数据（登录、游戏行为等）
- ⚠️ 充值明细数据（充值金额、充值时间等）
- ⚠️ 用户画像数据（设备信息、IP、地域等）

**交付物**：
- 多维度用户质量分析报告
- 用户分层分析（高价值/低价值/无价值）
- 假量识别报告
- 异常用户列表
- 风控建议

**风险**：中-高
- 用户行为数据可能不完整
- 充值明细数据可能缺失
- 风控规则需要持续优化

**备选方案**：
- 如果数据不完整，先做基础的质量分析
- 风控规则可以先基于简单规则，后续再优化

---

### Phase 5：长线 ROI 与 LTV 跟踪（4 周，后续）

**目标**：跟踪长线 ROI、LTV、留存，计算回本天数，预测未来趋势

**前置条件**：
- ⚠️ 数仓重构完成
- ⚠️ 数仓提供预聚合的长线指标（至少 90天的数据）
- ⚠️ 预测模型基础设施

**任务**：
- Week 1：长线数据聚合（7天/14天/30天/60天/90天 ROI、LTV、留存）
- Week 2：曲线分析（ROI 曲线、LTV 曲线、留存曲线）
- Week 3：回本天数计算 + 渠道对比
- Week 4：预测模型（时间序列分析）

**交付物**：
- 长线 ROI 跟踪报告
- LTV 曲线分析
- 留存曲线对比
- 回本天数计算报告
- 未来趋势预测

**风险**：高
- 强依赖数仓重构完成
- 预测模型需要持续优化
- 数据量大，性能可能有问题

**决策**：**暂缓**，等数仓重构完成后再评估

### Phase 4：暂缓项（等数仓重构完成）

- 批量异常诊断
- 实时监控与告警

**前置条件**：
- 数仓重构完成
- 数仓提供预聚合监控数据
- 数仓提供归因方式分布数据

## 五、风险与缓解

### 风险 1：数仓重构时间不确定

**影响**：Phase 4 的能力无法按时交付

**缓解**：
- Phase 1-3 不依赖数仓重构，可以先做
- Phase 4 等数仓重构完成后再评估
- 如果数仓长期无法提供数据，考虑用现有 MCP 工具做简单的聚合（性能可能差）

---

### 风险 2：跨表查询性能问题

**影响**：Phase 3 用户分群分析无法实现

**缓解**：
- 先验证跨表查询性能
- 如果性能不行，降级为简单分群统计（不做跨表关联）
- 或者让数仓提供预聚合的分群数据

---

### 风险 3：口径映射不完整

**影响**：Phase 2 跨系统数据对比的准确性

**缓解**：
- 先覆盖高频场景（主要媒体、主要游戏类型）
- 逐步补充口径映射
- 在对比结果中明确标注"口径可能不完全对齐"

---

## 六、总结

### 我们能做的（12 周）

1. **归因解释引擎**（2 周）- 让归因逻辑可解释
2. **跨系统数据对比**（2 周）- 帮助对比我们的数据与媒体数据
3. **用户分群分析**（2 周）- 分析新设备老账号等
4. **多层级下探归因**（3 周）- 从大盘异常逐层下探到媒体、账户、广告组、广告、素材、策略
5. **用户质量分析与风控**（3 周）- 多维度用户质量分析，识别假量和异常用户

### 我们需要数仓支持的能力（后续）

6. **长线 ROI 与 LTV 跟踪**（4 周）- 跟踪长线 ROI、LTV、留存，计算回本天数，预测未来趋势
   - 依赖数仓重构完成
   - 需要长线数据和预测模型

### 我们不能做/不应该做的

1. **批量异常诊断** - 需要数仓提供预聚合数据（暂缓）
2. **实时监控与告警** - 这是后端/运维的职责（不做）

### 决策原则

1. **不做数仓/后端的职责**：我们不建监控基础设施，不做数据管道
2. **聚焦智能化层**：我们做归因解释、数据对比、用户分群、问题诊断
3. **不强做硬做**：如果数仓无法提供数据，相关能力暂缓
4. **渐进式交付**：先做不依赖数仓的能力，再等数仓重构完成后做依赖项

### 下一步

1. **立即开始**：Phase 1 归因解释引擎
2. **并行准备**：梳理口径映射（为 Phase 2 做准备）
3. **技术验证**：验证跨表查询性能（为 Phase 3 做准备）
4. **需求确认**：确认用户质量分析的数据需求（为 Phase 4 做准备）
5. **长期规划**：与数仓团队沟通长线数据需求（为 Phase 5 做准备）

## 附录：场景清单

### 高频场景

1. **归因失败排查**：为什么这个设备归因失败？
2. **归因结果解释**：为什么这个设备归因到了巨量？
3. **媒体数据对账**：我们的消耗和媒体差这么多，为什么？
4. **运营数据对账**：运营大盘指标和归因结果对不上，为什么？
5. **注册率低排查**：注册率低，是回流用户多还是新增用户少？
6. **归因方式占比异常**：OAID 归因占比下降了，为什么？
7. **大盘成本异常下探**：今天成本很差，是哪个媒体/账户/广告组/广告/素材差？
8. **策略效果对比**：这批策略的广告 vs 那批策略的广告，哪个效果好？
9. **素材效果分析**：哪个素材导致的成本上升？这个素材投放了哪些广告？
10. **多团队对比**：多个团队投同一个游戏，各团队的数据对比
11. **用户质量分析**：这个渠道的用户质量怎么样？假量多吗？
12. **假量识别**：有没有注册后没有行为的用户？充值都是6元的异常？
13. **用户付费分层**：高价值用户来自哪个渠道？低价值用户呢？
14. **ROI 对比**：不同渠道的 7天/14天/30天 ROI 对比
15. **LTV 分析**：哪个渠道的 LTV 最高？

### 低频场景

1. **配置错误排查**：监测链接设错了，怎么排查？
2. **包配置问题**：包放错了，怎么排查？
3. **内部 IP 过滤**：有多少是内部 IP 访问？
4. **自然量计算**：自然量占比多少？
5. **趋势分析**：这个媒体/账户/广告是持续差，还是最近才变差？
6. **回本天数计算**：这个渠道的回本天数是多少？
7. **未来 ROI 预测**：未来 30天的 ROI 会是多少？
