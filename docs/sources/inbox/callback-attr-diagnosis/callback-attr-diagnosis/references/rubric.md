# Callback Attr Diagnosis Rubric

用途：复盘或自检 `callback-attr-diagnosis` 输出质量；只定义评分维度和常见扣分。

## 评分维度

- 参数一致性：`app_id`、`media_id`、日期、平台、事件是否与用户问题和上下文解析结果一致。
- 分支正确性：是否先确认 SDK / API / iOS-Harmony / 其它平台分支，再使用对应证据。
- 总量优先级：是否以 aggregate 总量为主，避免用 sample、存在性或单条样本替代整体判断。
- 证据链完整性：是否分别覆盖 base event、attr-require、attr-res、callback/delivery、媒体或报表口径。
- 主辅证据区分：是否避免让 `804`、`push_media_code`、非当前分支的 `feedback-res` 抢主因。
- 口径表达：是否明确“无数据”“未归到目标媒体”“归到自然量/其它媒体”“回推缺口”的区别。

## 严重扣分

- 错误参数查到 0 行后，直接输出业务无数据结论。
- Android SDK 分支未做总量对账，就说回调正常或不正常。
- `sdk_income_total > 0` 被写成 SDK 回推闭环正常。
- 目标媒体未命中但 `ORGANIC` 或其它媒体存在，被写成无归因结果。
- API / SDK / iOS-Harmony 分支证据混用，并纳入根因判断。
- 把媒体后台、报表、系统归因、回推任务的不同口径直接等同。

## 通过标准

- 参数与上下文一致，且 0 行证据经过有效性复核。
- 结论前已展示当前分支所需的关键聚合总量。
- 根因只来自当前分支主证据，辅助证据有明确标注。
- 对异常使用精确表述：缺口在哪里、从哪一层到哪一层断开、下一步该查什么。
