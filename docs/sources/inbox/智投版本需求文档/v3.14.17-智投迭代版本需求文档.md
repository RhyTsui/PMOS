## 一、背景

### 1.1 业务背景

智投当前核心业务链路覆盖账户授权、项目初始化、归因配置、报表查询、素材加工、包管理和媒体数据采集。近期问题集中在四类：

1. 巨量账户授权确认链路因同账户多组织、升级版组织筛选、管家账户处理、代理绑定配置不完整而影响核心授权流程。
2. 归因与报表存在计算异常或缺失，包括预约归因实时数据、腾讯搜索广告新增素材类型、日周月报汇总指标、腾讯点击设备 ID 解析。
3. 项目初始化、事件配置、预约报表、gssdk 应用列表、回推配置、包下载地址等核心流程仍依赖人工处理。
4. 小红书、渠道分成、Applovin 以及 Q3 多媒体采集需求需要提前纳入版本储备和调研。

本版本不是重做智投整体系统，而是在既有系统基础上收敛影响授权、归因、报表和初始化效率的迭代需求，输出统一评审口径。

### 1.2 要解决的问题

| 问题 | 具体表现 | 影响 |
| --- | --- | --- |
| 授权确认阻塞 | 同投放账户多组织重复展示，升级版组织筛选不稳定，多管家账户处理与代理绑定配置不完整 | 巨量账户授权效率下降，容易误选、漏配 |
| 归因与报表缺失 | 预约归因数据未完整展示，新增素材类型采集后未加工，日周月报汇总指标不足，腾讯设备 ID 解析不准 | 报表数据偏少或口径不一致，影响投放判断 |
| 人工介入过多 | 腾讯融合归因、核心事件、有效事件、预约报表、gssdk 应用列表、回推配置、包地址依赖人工处理 | 新项目初始化慢，配置遗漏风险高 |
| 采集能力待完善 | 小红书、渠道分成、Applovin、Q3 多媒体采集未形成统一规划 | 后续需求临近时研发评估和接入压力大 |

### 1.3 解决方案

1. 将巨量授权链路作为 P1 主收口，明确账户去重、组织筛选、管家账户、代理绑定的前后端口径。
2. 将归因与报表异常作为 P1 主收口，优先解决直接影响报表展示和归因准确性的缺口。
3. 将人工配置项归入 P2 自动化优化，默认只影响新项目或新增链路，不回写历史数据。
4. 将采集类中长期需求归入 P3，区分本版储备、提前调研和 Q3 候选，不默认承诺全部在 v3.14.17 完成开发。

### 1.4 决策依据

- 用户明确指定本版本号为 `v3.14.17`。
- 用户明确指定输出模板为 `docs/sources/inbox/需求文档模板v2.0.docx`。
- 需求按用户给定优先级归类：授权与归因报表为 P1，去人工化为 P2，数据采集完善为 P3。
- 历史数据处理遵循用户约束：腾讯设备 ID 解析修复不刷新历史数据，新项目默认回推配置不修改历史项目。

## 五、开发说明

### 5.1 巨量账户授权

#### 5.1.1 数据列表展示规则

1. 投放账户列表以投放账户为唯一展示对象。
2. 同一投放账户存在于多个组织时，列表只展示一条。
3. 组织字段合并展示该投放账户所属的多个组织。
4. 示例：
   - 原始数据：账户 A 在组织 a 和组织 b 下均存在。
   - 页面展示：账户 A 一条，组织展示为 `[a, b]`。

#### 5.1.2 搜索升级版组织筛选规则

1. “搜索升级版组织”只展示升级版组织。
2. 非升级版组织不在该搜索框下展示，也不参与该筛选逻辑。
3. 筛选组织后，展示该组织下所有投放账户。
4. 同账户多组织时，筛选结果仍按投放账户去重。
5. 示例：
   - 筛选组织 a：展示投放账户 1 一条。
   - 筛选组织 b：展示投放账户 1 一条。
   - 同时筛选组织 a 和 b：展示投放账户 1 一条。

#### 5.1.3 确认授权管家账户规则

1. 投放账户的 `manager_account_id` 仍只支持一个。
2. 当同一账户存在多个管家账户时，确认授权只提交第一个。
3. 示例：
   - 账户 A，管家账户 `[a1, b1]`。
   - 授权提交账户 A，管家账户 `a1`。
4. 原因：
   - 账户管理列表页面“管家账户”暂不支持展示和维护 2 个。
   - 后续后端会优化为直接从媒体获取最新组织结构，不再从账户列表获取管家账户。

#### 5.1.4 账户绑定代理规则

1. 账户绑定代理支持按日期区间配置不同代理。
2. 每个代理配置需要分别维护：
   - 生效开始日期
   - 生效结束日期
   - 代理
   - 付款模式
   - 结算方式
3. 支持入口：
   - 授权确认流程中设置。
   - 账户列表中二次修改。
4. 默认建议：
   - 同一账户下代理日期区间不允许重叠。
   - 代理配置缺少付款模式或结算方式时，不允许保存或给出明确提示。

### 5.2 归因与报表

#### 5.2.1 实时数据预约归因

1. 实时数据开启预约归因开关时，展示预约相关数据。
2. 本版优先支持计算归因到预约时间的预约量。
3. 同时点击公测广告和预约广告，且最终算到公测的量，暂不支持实时计算。
4. 对暂不支持实时计算的数据，应在页面或接口返回中保持一致降级口径，避免被误认为 0。

#### 5.2.2 广告素材新增素材类型

1. 腾讯搜索广告新增素材类型已采集但未进入加工环节时，需要补入加工链路。
2. 该素材类型需要展示到广告素材报表中，否则会造成报表数据偏少。
3. 为彻底解决同类问题，后续新增素材类型默认进入报表展示。
4. 对未知或新素材类型，建议按“其他/未知素材类型”兜底展示，不应直接丢弃。

#### 5.2.3 日周月报汇总口径指标

1. 日周月报汇总口径下，指标范围需要和日报一致。
2. 默认指标需要和日报一致。
3. 可导出指标需要和日报一致。
4. 如存在特殊计算逻辑，应二次确认。
5. 未确认前可降级处理：
   - 暂不展示特殊指标。
   - 或展示 `-` 并保留提示。
   - 或仅在导出中暂不提供该特殊指标。

#### 5.2.4 腾讯点击设备 ID 解析

1. 腾讯获取点击时存在设备 ID 未准确解析的问题。
2. 本版按媒体文档完善点击数据中的设备 ID 解析逻辑。
3. 修复只影响新增处理数据。
4. 历史数据暂不考虑刷新。

### 5.3 核心流程去人工化

#### 5.3.1 腾讯融合归因

1. 当前 `app_version` 需要手动配置。
2. 新项目默认全部用户范围，不需要隔离用户。
3. 老项目之前已经处理过，本版不修改历史项目。
4. 腾讯 `appid` 改为自动获取。
5. 自动获取失败时，需要返回明确错误原因，方便人工补充。

#### 5.3.2 核心事件自动新增

1. 新游戏核心事件自动调用平台接口完成新增。
2. 目标是避免核心事件缺失导致上报错误。
3. 重复新增需要幂等处理，不应生成重复事件或导致初始化失败。

#### 5.3.3 付费目标支持有效事件

1. 付费想选择有效事件时，当前必须选择 `465`。
2. `465` 不是事件上报，不在平台事件管理中。
3. 本版改为支持选择“有效事件”。
4. 系统内部兼容 `465` 特殊口径，用户不需要理解或选择 `465`。

#### 5.3.4 预约项目报表自动处理

1. 预约项目中开启预约功能后，需要自动处理报表相关配置。
2. 当前由人工处理的动作改为系统自动触发。
3. 建议触发时机为：预约功能开启并保存成功后。

#### 5.3.5 gssdk 项目初始化

1. gssdk 项目初始化时，默认按广告出包规范生成通用应用列表。
2. 获取包列表时自动填入包名。
3. 暂时支持手动修改，避免自动生成结果不符合特殊项目。

#### 5.3.6 新项目默认回推配置

1. 新项目初始化时，回推开关默认都开启。
2. 三大媒体安卓默认 SDK 自定义回推。
3. 巨量、腾讯的 iOS/鸿蒙默认融合归因。
4. 小游戏抖小传巨量默认关闭。
5. 小游戏微小传腾讯默认关闭。
6. 其它默认 API 回传。
7. 不修改历史数据。
8. 功能不变，初始化后可手动修改。

#### 5.3.7 包列表下载地址

1. 包列表中展示包管理平台的包下载地址。
2. 下载地址以包管理平台返回结果为准。
3. 无下载地址时展示“未生成”“暂无下载地址”或同类空态，不阻塞包列表展示。

### 5.4 采集数据完善

#### 5.4.1 小红书消耗

1. 小红书消耗展示到报表中。
2. 取消手动录入，避免重复。
3. 检查报表相关逻辑，确保自动采集数据和历史手动录入逻辑不会重复计算。

#### 5.4.2 渠道分成

1. 支持渠道分成配置。
2. 支持跨项目配置。
3. 微信小游戏和 iOS 可在后台录入。
4. 全局报表增加分成勾选功能。
5. 默认不勾选。
6. 勾选后，ROI/LTV/付费成本按分成后付费金额计算。
7. 增加“分成后付费金额”指标。
8. 该项为 6 月大概率存在的需求，建议提前评估。

#### 5.4.3 Applovin 媒体数据

2. 采集指标：
   - 花费

   - 分 campaign（广告系列）
   - 分素材（广告）
4. 该项为 7 月必备需求，建议提前调研。

#### 5.4.4 Q3 多媒体采集
