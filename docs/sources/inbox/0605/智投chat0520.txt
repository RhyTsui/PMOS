 企业化程度我会这样评价：

  当前方案企业化程度：6.5/10

  架构方向已经像企业级系统了，但治理、权限、审计、稳定性、可观测、配置管理还不够完整。现在更像“高级产品原型 + 可
  扩展技术架构”，还没到“企业级可长期运行的情报基础设施”。

  要做到 8.5/10 以上，需要补上企业化治理层。

  1. 配置治理

  现在有 Source、Crawl、Dataki、Prompt、热词配置，但还缺：

  - 配置版本
  - 修改人
  - 修改时间
  - 生效状态
  - 回滚
  - 灰度启用
  - 配置变更日志

  企业化系统里，Prompt、Source、热词、权重变更都会影响 Agent 判断，必须可追溯。

  建议增加：

  Config Versioning
  Config Audit Log
  Config Rollback

  2. 权限与角色

  现在默认所有后台能力都可用，但企业化需要区分：

  - 查看行业动态结果
  - 修改 Source
  - 修改 Crawl 配置
  - 修改 Prompt
  - 修改 Dataki 知识库配置
  - 触发手动采集
  - 查看失败日志
  - 重试入库
  - 删除或禁用 Source

  建议角色：

  - 管理员
  - 情报配置维护者
  - 只读分析用户
  - 运维排障用户

  v0.7 可以不做复杂权限，但接口和数据结构要预留 created_by、updated_by、operator。

  3. 审计能力

  企业化必须知道：

  - 谁改了 Source
  - 谁改了 Prompt
  - 谁触发了采集
  - 谁同步了知识库
  - 哪个版本的 Prompt 生成了哪次评价
  - 哪个 Source 影响了哪次 Chat 回答

  建议所有关键动作进入审计日志：

  source_enabled
  source_disabled
  prompt_updated
  crawl_triggered
  dataki_sync_started
  dataki_sync_failed
  evaluation_generated

  4. 可观测性

  当前调试能力有“最近抓取、最近入库、去重日志、失败日志”，这是排障基础，但企业化还需要指标化：

  - 采集成功率
  - 入库成功率
  - 去重率
  - 平均采集耗时
  - 平均入库耗时
  - 每个 Source 最近成功时间
  - 每个 Provider 可用率
  - 高影响事件数量
  - Chat 引用次数
  - RAG 召回成功率

  建议增加：

  Health Dashboard / Metrics API

  即使 v0.7 不做页面，也要有接口或日志结构。

  5. 稳定性与容错

  企业级运行需要定义失败策略：

  - Crawl4AI 失败后是否立即 Playwright fallback
  - Playwright 失败后是否重试
  - Dataki 失败是否保留待同步队列
  - Prompt 生成失败是否降级为规则摘要
  - 采集任务是否支持幂等
  - 重复任务是否合并
  - 同一 Source 超时是否影响其他 Source

  建议加：

  Retry Queue
  Dead Letter Log
  Idempotency Key

  6. 数据生命周期

  行业动态数据不能无限堆。

  需要定义：

  - 原始抓取内容保存多久
  - 清洗正文保存多久
  - 入库后的本地副本保存多久
  - 调试日志保存多久
  - 失败日志保存多久
  - 旧版本是否保留
  - 是否支持归档

  v0.7 可以先写默认策略：

  - 原始抓取内容保留 30 天
  - 调试日志保留 30 天
  - 事件和入库记录长期保留
  - 文章版本保留最近 5 个版本

  7. 安全与合规

  爬虫和外部内容采集要考虑：

  - robots / 来源限制
  - 请求频率
  - 外部链接安全
  - 敏感内容过滤
  - 不把未验证社区内容写成确定事实
  - 不把外部原文大段复制到用户回答里

  这部分尤其重要，因为行业动态会进入知识库，后续 Agent 会引用。

  建议增加：

  Source Compliance Policy
  Content Safety Filter
  Citation Policy

  8. Prompt 企业化

  Prompt 不只是文案，需要治理：

  - Prompt 版本
  - Prompt 生效范围
  - Prompt 关联 Skill
  - Prompt 关联评价结果
  - Prompt 回滚
  - Prompt 测试用例

  行业摘要 Prompt 和风险分析 Prompt 影响很大，必须有版本和审计。

  9. Agent 输出可解释

  企业化系统里，Agent 的“高影响”判断不能黑箱。

  每个高影响结论需要能追溯：

  - 引用了哪些 Source
  - 命中了哪些热词
  - Source Weight 是多少
  - confidence 怎么来的
  - impactScore 怎么来的
  - 使用哪个 Prompt 版本
  - 是否同步到知识库

  这会影响用户信任和后续复盘。

  10. SLA / 运行目标

  如果作为企业级基础设施，需要定义运行目标：

  - 每日采集必须在几点前完成
  - 每个 Source 失败多久告警
  - Dataki 同步失败多久告警
  - Chat 触发采集最长等待多久
  - 超时后如何返回

  建议 v0.7 先定：

  - Chat 实时触发最长等待 20 秒
  - 超时后返回“正在采集，稍后可重试”
  - 定时采集每日 9 点前完成
  - Source 连续失败 3 次进入失败日志
  - Dataki 同步失败保留待重试
