Presentation Layer 需要解决什么

实际上有五大问题。
1 信息压缩
当前：

100行内容

用户不看。

应该：

一句结论

展开看细节

例如：

注册数增长15%

[查看原因]

2 渐进式披露
第一层：

结论

第二层：

关键指标

第三层：

明细

第四层：

原始数据
而不是：

直接输出3000字
3 多模态数据展示

企业AI绝大部分是：

指标
表格
图表
状态
流程

不是纯文本。

因此正文必须支持：

Metric Card

Table

Chart

Timeline

Flow

Status

Action
4 行动导向

很多AI只会说：

发现问题

结束。

企业AI必须：

发现问题

下一步建议

立即执行

例如：

激活异常

[查看原因]

[开始排查]

[创建Case]
5 AI运行体验

这是你之前一直在讨论的：

思维链体验

但不要暴露 CoT。

应该是：

正在理解问题

正在匹配能力

正在查询数据

正在生成结果

这种 Runtime UX。

正文渲染的核心链路

你现在要明确这条链：

SemanticResultContract
→ regions[]
→ blocks[]
→ componentBinding
→ renderer.validate()
→ renderer.render()
→ Message Surface

其中：

Disclosure Layer
只负责“过程与依据”

正文渲染
只负责“结果怎么呈现”

两者不能混。

正文层的关键对象

建议正式定义：

SemanticResultContract {
  answer_markdown?: string
  regions: Region[]
  actions?: ActionContract[]
  disclosure_ref?: string
}
Region {
  region_id: string
  region_type:
    | 'summary'
    | 'metric_cards'
    | 'table'
    | 'chart'
    | 'insight'
    | 'recommendation'
    | 'actions'
    | 'artifact'
  title?: string
  priority: number
  blocks: Block[]
  componentBinding: ComponentBinding
}
Block {
  block_id: string
  block_type:
    | 'markdown'
    | 'metric_card'
    | 'data_table'
    | 'chart'
    | 'finding'
    | 'recommendation'
    | 'action_group'
    | 'empty_state'
  data: unknown
}
这次正文补充的目标

不是改 Disclosure，而是解决：

1. AI 正文不能只是一坨 markdown
2. 结果卡、表格、图表、动作区不能各自抢渲染
3. answer_markdown、summary、visualizations、actions 要有固定归属
4. 不允许前端从 raw_result 猜 UI
5. 不允许每个业务组件私有定义结构
6. 所有正文内容必须从 SemanticResultContract / regions[] 来
和 Disclosure 的边界

正文区域：

右侧过程与依据：

raw info

一句话：

Disclosure 解释“为什么可信”；正文渲染负责“结果如何高质量呈现”。
