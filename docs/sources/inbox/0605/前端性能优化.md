会话历史加载应该做成“会话列表轻量化 + 消息窗口化 + 虚拟滚动 + Artifact 懒加载 + 历史摘要压缩”，而不是简单分页。

1\. 会话列表：分页 + 游标加载

前端策略：

首屏只取 20～30 条。

滚动到底部再加载下一页。

支持按 updated\_at desc 排序。

搜索时走独立搜索接口，不在前端全量过滤。



2\. 消息详情：按时间窗口加载

点击某个会话时，不加载全部消息，只加载最近 N 条。

户向上滚动时，再加载更早消息

核心体验：

默认打开看到最新上下文。

向上滚动自动补历史。

加载旧消息时保持滚动位置不跳动。

不要把历史消息全部塞进 React state。



3\. 消息渲染：虚拟列表

消息超过 100 条后，必须用虚拟滚动。

评估采用react-virtuoso



4.消息分层加载

消息不要一条记录里塞所有内容。

大对象延迟加载

规则：

正文消息首屏加载。

表格、图表、证据、trace、raw\_result 进入懒加载。

用户展开“查看详情”时再请求。

大表格不要直接塞进消息体，走数据视图组件按需取数。



5.历史压缩：摘要层替代超长上下文

对超过一定长度的会话，后端生成历史摘要。

前端展示为已折叠较早历史 · 查看摘要 · 展开原文

适合场景：

长周期需求讨论

多轮排查

战略 / 需求 / 设计 / 实施多阶段会话

Agent 执行记录很长的任务



6.搜索与跳转：不能靠前端全量加载

搜索接口单独设计

点中搜索结果后 也就是加载目标消息上下各 20 条



7\. 附件 / 表格 / 图表：统一懒加载

点击后再加载

大表格继续分页
