 # Chat 回答模板、来源与项目上下文改造计划

  ## Summary

  把 imported/projects 的 chat 生成链路从硬编码提示词改成后台可配置提示词控制。第一版使用本地持久化 prompt store，
  admin/prompts 编辑后立即影响 /api/chat。

  主对话只展示“用户可读回答 + 短摘要 + 建议动作”。“已识别条件”“参数说明”“tool arguments”“datatype 来源”“知识库失败诊
  断”统一进入来源/执行详情，不再作为普通用户正文或主卡片内容暴露。

  ## Key Changes

  - 新增本地持久化 prompt store，替换 admin/prompts 当前 demo 内存数据：
      - 保存位置复用 runtime data 目录风格，类似 runtime-config.json。
      - GET/POST/PUT /api/xiaoqiao/admin/prompts 读写真实本地配置。
      - 支持按 workflow/intent 查找启用中的 prompt：help、diagnosis、demand、debugging、general。
      - 没有配置时使用内置默认 prompt 作为兜底，但不再让 demo 数据成为真源。
  - 改造 /api/chat 生成链路：
      - buildSystemPrompt() 拆成“系统基础约束 + 后台 prompt + 知识库上下文 + 项目 metadata 约束”。
      - 后台 prompt 可控制：回答格式、结果摘要、来源说明规则、是否输出下一步动作。
      - result.summary 不再用截断正文，也不再为空；改为独立短摘要，优先由模型按 prompt 输出，失败时从正文提取首个有效
        结论句。
      - result.structured_payload 只放机器可读数据、来源、执行详情、知识库诊断，不直接驱动主对话展示过程字段。
  - 调整前端展示职责：
      - ChatContainer 主消息保留 Markdown 正文。
      - ResultMessageCard 只展示 summary、next_actions、必要的业务状态，不展示“已识别条件”“参数说明”。
      - 条件解析、工具参数、MCP 返回、知识库诊断、datatype 来源继续通过右侧来源/执行详情查看。
      - 主对话中的知识库失败提示统一为：“知识库暂不可用，已继续用可用信息回答。”
  - 项目上下文改造：
      - useConversation.ts 不再把右上角项目上下文拼进用户正文。
      - /api/chat 请求体新增隐藏字段，例如 metadata.projectContext 或 projectContext 保持后端使用，但不进入 message。
      - 系统提示词保留约束：“当前项目范围只作为查询参数，不要在正文重复 APPID / 项目 ID。”
      - 历史消息仍保存用户原始输入，不保存拼接后的项目说明。
  - 知识库失败诊断增强：
      - searchKnowledge() 每个失败分支都返回统一 diagnostics：stage、listEndpoint、searchEndpoint、
        knowledgeBaseIds.length、httpStatus、message、timeoutMs。
      - trace、thinking step、tool_result、metadata 都写入诊断详情。
      - 用户正文只给降级提示，不展示地址、Key、HTTP 细节。
      - admin 测试入口和 chat 使用同一套知识库解析/检索 helper，避免测试成功但 chat 失败原因不一致。
  - datatype 来源追踪：
      - 不在 /api/chat 内新增 datatype 业务含义。
      - 工具调用 arguments/result 在执行详情里完整展示来源。
      - 如果外部 MCP、报表服务或查数策略返回 datatype/dataType/roi_data_type，在执行详情标明来源为“工具入参”“工具返
        回”或“策略默认值”。
      - 主对话不复述 datatype，除非用户明确询问字段含义。

  ## Public Interfaces / Types

  - 扩展 PromptConfig：
      - 增加可选 content 或通过 PromptVersion.content 读取当前版本正文。
      - binding.workflow 作为 chat 选择 prompt 的主键。
      - enabled/status=active 共同决定是否参与生成。
  - 扩展 /api/chat 请求体：
      - 保留 message/history/intent。
      - projectContext 作为隐藏上下文继续支持；实现时可迁移到 metadata.projectContext，但保持向后兼容。
  - 扩展 /api/chat done payload：
      - result.summary: 面向用户的短摘要。
      - result.next_actions: 面向用户的建议动作。
      - metadata.source_refs: 来源列表。
      - metadata.knowledge_diagnostics: 仅用于来源/执行详情。
      - metadata.prompt_config: 当前命中的 prompt id/version/name，供排查，不在正文展示。

  ## Test Plan

  - 后台提示词：
      - 创建/更新 active prompt 后，调用 /api/chat，确认系统 prompt 使用新内容。
      - 禁用 prompt 后，确认回退到内置默认 prompt。
      - 重启 dev 服务后，确认 prompt 配置仍保留。
      - 右侧来源/执行详情仍能看到 tool arguments、tool result、知识库诊断和 prompt 命中信息。
      - result.summary 为空或模型未产出摘要时，前端展示兜底短摘要，不展示整段截断正文。
  - 项目上下文：
      - 选择项目后发送消息，网络请求体包含隐藏项目上下文。
      - 用户消息内容只保存原始输入。
      - 模型回答不主动复述 APPID / 项目 ID。
  - 知识库检索：
      - 缺配置、列表超时、无知识库、search HTTP 非成功、低相关结果全部覆盖。
      - 用户正文只展示温和降级提示。
      - trace/执行详情包含 endpoint、知识库数量、HTTP 状态和失败阶段。
  - datatype 来源：
      - 模拟工具入参带 dataType: total，确认只在执行详情出现。
      - 模拟工具返回带 roi_data_type，确认来源标记正确。
      - 主回答不把 datatype 当业务结论复述。

  ## Assumptions

  - 第一版提示词真源采用本地持久化，不接外部配置后台。
  - 主对话保留摘要和建议动作；条件、参数、执行过程只放来源/执行详情。
  - 不改变模型服务、知识库服务、MCP 服务的外部协议，只增强本地编排、追踪和展示。
