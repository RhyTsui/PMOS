  4. Agent 路由设计拆解
  是的，现在主要靠关键词和正则分发。核心入口在 /E:/AI/ai-os/subprojects/ad/frontend/src/src/lib/intent-router.ts:214，/
  api/chat 里还有一套 detectIntent/selectMcpTool，形成双路由。交叉命中很容易发生，比如：

  - “巨量应用列表”会被媒体词命中到联调。
  - “ROI 怎么样”会被路由到 forecast/prediction，而业务上应先是查数/分析。
  - “异常波动”可能在 monitor、diagnosis、report query 之间漂移。
  - 缺少可解释的候选路由评分、置信度阈值、追问策略和历史上下文约束。

  建议产品设计：

  - 第一层：任务类型判定，不直接选人格 Agent。类型包括 ask_data、analyze_anomaly、debug_integration、delivery_package、
    create_demand、metric_explain、scheduled_report。
  - 第二层：Slot 抽取，抽项目、媒体、日期、指标、维度、目标动作、证据。
  - 第三层：Skill Contract 匹配，以能力契约为中心，不以关键词为中心。
  - 第四层：Tool Plan 生成，明确前置工具、主工具、质量检查、结果组件。
  - 第五层：置信度与追问，低置信度不硬路由，展示确认选项。
  - 第六层：可观测，每次路由保存候选、分数、拒绝原因、最终原因，便于回归。
