依据资料：

- Dataki 知识库“版本需求文档”已读取到的 35 个文档条目与摘要

适用目标：
- 作为智投 Chat 调用“问题排查 Agent”的产品、测试、开发对齐材料。
- 用于定义 Agent 能排查什么、怎么判断、需要哪些输入、输出什么结论、如何验收。
- 本文中的案例为基于现有资料抽象出的验收样例和剧本，不等同于已脱敏真实线上工单。正式上线前建议补齐真实历史问题样本。

## 1. Agent 的定位

该 Agent 不只是回答概念，而是基于真实数据和配置证据，完成以下动作：

1. 识别用户问题属于哪条链路：采集、预处理、归因、回推、报表、素材、团队、授权、PC/Web、H5、融合归因。
2. 向用户追问必要字段，避免在关键信息缺失时直接下结论。
3. 调用受控数据查询工具，按剧本形成证据链。
4. 输出问题归类、判断依据、处理建议、是否需要开发介入。
5. 对可解释的正常口径差异给出说明，避免误报为故障。

推荐统一结论标签：

| 标签 | 含义 | 是否通常需要开发介入 |
|---|---|---|
| `正常口径差异` | 实时/离线、小时/日级、今日/历史、多团队自然量等口径导致差异 | 否 |
| `用户输入不足` | 缺少项目、时间、设备、账户、活动、包等关键定位字段 | 否 |
| `筛选或权限问题` | 页面条件、角色、团队权限、单/多团队配置导致不可见 | 否/视情况 |
| `配置问题` | 账户、包体、活动、归因配置、回推规则、团队配置缺失或不一致 | 通常产品/运营处理 |
| `采集问题` | 媒体原始数据、授权、Token、采集日志、接口返回异常 | 视媒体/采集团队 |
| `预处理问题` | 原始事件已到，但 JSON、应用类型、事件时间、设备、订单、金额等预处理异常 | 视异常类型 |
| `归因问题` | 事件已到但未命中点击、活动、包体、窗口或融合归因条件 | 视规则/数据 |
| `回推问题` | 回推明细未生成、规则未命中、回调参数缺失、媒体接口失败 | 视原因 |
| `报表聚合问题` | 明细有数但 DWS/ADS/Page/API 无数或不一致 | 通常开发/数仓介入 |
| `维表映射问题` | 素材、账户、活动、包体、团队等维表缺失或关联失败 | 视归属 |
| `调度或平台问题` | SR 升级、CDC、出仓、调度失败导致大面积异常 | 开发/数仓介入 |

## 2. 通用输入字段规范

Agent 应先根据场景判断最小必填字段。不能要求用户一次性提供所有字段，但需要能逐步追问。

| 字段 | 用途 | 优先级 |
|---|---|---|
| `app_id` / 项目 / 应用 | 所有链路定位的核心范围 | 必填 |
| 日期或时间范围 | 定位 ODS、DWD、ADS、回推明细、采集日志 | 必填 |
| 页面名称 / 功能模块 | 判断报表、用户细查、回推明细、素材报表、授权页面等 | 必填 |
| 问题现象截图或描述 | 判断是无数、少数、多数、字段错误、无法选择、失败提示 | 必填 |
| `media_id` / 媒体 | 采集、归因、回推、素材、账户授权必需 | 场景必填 |
| `account_id` | 媒体采集、账户授权、素材和团队排查 | 场景必填 |
| `campaign_id` / `attr_campaign_id` | 活动归因、团队归属、回推规则、报表筛选 | 场景必填 |
| `cpsid` / 包 / 分包 | APP、Android、PC/Web、多团队、归因匹配 | 场景必填 |
| `device_id` / `oaid` / `idfa` / `imei` / `caid` | 单设备归因、激活、回推排查 | 场景必填 |
| `user_id` / `role_id` / `open_id` | 注册、付费、H5、小程序、用户细查排查 | 场景必填 |
| `event_type` / 事件名 | 判断启动、激活、注册、付费、关键行为、次留 | 场景必填 |
| `order_id` / `amount` | 付费、回推、自定义付费、订单去重排查 | 场景必填 |
| `team_id` | 多团队权限、自然量分摊、团队报表排查 | 场景必填 |
| `request_id` | 媒体采集原始报表与日志联查 | 场景必填 |
| `mat_id` / `ad_id` / `ad_set_id` / `mat_signature` | 素材未知、素材打通率排查 | 场景必填 |

通用追问原则：

| 用户只说了 | Agent 应追问 |
|---|---|
| “报表数据不对” | 哪个页面、项目、日期、指标、筛选条件、期望值和实际值 |
| “没有归因” | 项目、时间、设备号或用户 ID、事件类型、媒体/活动/包 |
| “没有回推” | 项目、时间、事件类型、设备/用户、媒体、回推方式、是否真实/虚拟/手动 |
| “团队数据不对” | 项目是否多团队、团队、账户/包/活动、页面、日期 |
| “素材未知” | 项目、日期、媒体、账户、素材/广告 ID、页面、未知比例 |
| “消耗没数据” | 媒体、账户、日期、页面、是否新授权、是否能在媒体后台看到 |
| “PC/Web 指标异常” | 事件类型、session_id/ad_link_id/PC device_id、落地页打开时间、转化时间 |

### 3.2 Agent 任务边界

| 能自动判断 | 需要转人工/开发 |
|---|---|
| 用户缺少哪些字段 | 表无权限、工具不可用 |
| 页面筛选和权限是否可能导致不可见 | SQL 返回异常或链路表不存在 |
| 是否为实时/离线正常口径差异 | 大面积 ADS/DWS 与明细不一致 |
| 事件是否进入 ODS | ODS 有数但预处理系统异常 |
| 预处理异常码含义 | 新异常码没有字典解释 |
| 是否命中活动、包体、账户、团队配置 | 配置正确但结果仍异常 |
| 回推规则是否存在和匹配 | 媒体接口返回未知错误 |
| 授权是否有效 | 媒体 API 权限或外部平台问题 |

## 4. 判断口径

### 4.1 全局判断顺序

Agent 对大多数问题应遵循同一条证据链：

```text
用户现象
-> 补齐定位字段
-> 判断页面筛选、权限、口径
-> 查 ADS/页面结果
-> 查 DWS/DWD 明细或汇总
-> 查归因结果/预处理结果
-> 查 ODS 原始事件/媒体原始报表/采集日志
-> 查配置：账户、包体、活动、团队、回推规则、授权
-> 给出结论标签、证据、建议、是否转人工
```

### 4.2 报表类判断口径

| 判断点 | 口径 |
|---|---|
| 页面无数 | 先确认页面、日期、筛选、权限，再判断 ADS 是否无数 |
| ADS 无数但 DWS/DWD 有数 | 优先判定为报表聚合、视图、调度或维表关联问题 |
| DWD 无数但 ODS 有数 | 优先判定为加工、调度、数据清洗或维表过滤问题 |
| ODS 无数 | 事件采集或媒体采集入口问题 |
| 实时页与日报不一致 | 实时消耗来自小时表，日报/周报/月报多来自日表，不应直接判故障 |
| 今日自然量团队异常 | 非小时报表今日自然量可为未知团队，小时表不展示自然量 |
| N 日 ROI 无值 | 未到 N 日、注册/付费日期口径、付费早于注册等情况需单独说明 |
| 页面和导出不一致 | 需要确认导出条件、缓存、指标配置和权限是否一致 |

### 4.3 归因类判断口径

| 判断点 | 口径 |
|---|---|
| base 表无事件 | 判定为客户端/服务端上报、SDK、日志入口或时间条件问题 |
| base 有事件、attr 无 require | 判定为预处理入口或事件类型未纳入归因 |
| attr 有 require、无 result | 查异常码、配置、设备标识、归因窗口和点击匹配 |
| `NO_ATTR_CONFIG` | 通常为未配置归因或配置未初始化 |
| `NO_APP_PACKAGE_TYPE_CONFIG` | 应用/包体类型配置缺失或不匹配 |
| `NON_ATTR_EVENT_ID` | 事件不是归因事件，可能是正常过滤 |
| `DATA_TIME_ERROR` | 事件时间异常，需看客户端时间、延迟上报和 `dt` |
| `DUPLICATE_FOR_LATER` / `DUPLICATE_FOR_LOW_LEVEL` | 去重或等级过滤，需要判断是否预期 |
| 未匹配广告 | 不一定是故障，可能按规则进入自然量 |
| 融合归因 | 注册和付费可能需要等待融合归因完成，不能按普通链路立即判失败 |

### 4.4 回推类判断口径

| 判断点 | 口径 |
|---|---|
| 回推明细没有生成 | 先判断事件是否已归因，再判断规则是否命中 |
| 有明细但媒体未收到 | 查回调参数、状态、媒体接口响应、重试日志 |
| 虚拟/手动回推 | 报表过滤，仅回推明细展示，不能拿报表无数判断未回推 |
| 回推付费次数 | 指标卡按次数理解，不是人数 |
| 规则切换 | 可能只是下游传递方式变化，规则本身未变 |
| 白名单/联调数据 | 应单独标记，不与线上真实回推混淆 |
| SDK/API/AF/Google | 需按项目和媒体确认当前回推模式 |

### 4.5 多团队判断口径

| 判断点 | 口径 |
|---|---|
| 单团队项目 | 页面通常不展示团队，历史 `team_ids` 保留但不生效 |
| 多团队项目 | 账户、包体、活动需要维护 `team_ids` |
| Android/PC/Web | 多团队通常按包体团队隔离 |
| iOS/H5 | 页面可能不展示应用团队字段，但报表仍可能有团队值 |
| 团队未知 | 可能是未绑定团队、历史数据、自然量今日口径或维表缺失 |
| 自然量分摊 | 仅 iOS/H5 参与，Android/PC/Web 等自然量团队标记未知 |
| 历史自然量 | 今日之前按对应天折前消耗团队比例分摊，尾数给占比大的团队 |
| 团队冲突 | 包体、活动、账户团队不一致时，需按具体页面和指标确认取值优先级 |

### 4.6 素材类判断口径

| 判断点 | 口径 |
|---|---|
| 素材未知 | 不是单点问题，可能是媒体原始字段、标化函数、维表、活动/账户关联任一环节缺失 |
| 媒体原始无素材字段 | 优先判媒体接口或报表类型不支持 |
| 原始有素材字段但维表无 | 判定为素材维表或同步问题 |
| 维表有素材但 ADS 未关联 | 判定为 DWS/ADS 关联或标化字段问题 |
| 素材跨媒体/跨应用类型 | 需要防止错误复用素材映射 |

### 4.7 授权采集判断口径

| 判断点 | 口径 |
|---|---|
| 授权记录不存在 | 配置或授权流程问题 |
| 授权过期/非最新/不完整 | 授权失效，需重新授权或刷新 Token |
| 原始报表无数据 | 查媒体接口请求、账户权限、报表类型、时间范围 |
| 采集日志失败 | 依据错误码判断媒体接口、限流、权限或参数问题 |
| 原始有数但 DWD 无数 | 加工任务或数据清洗问题 |
| 巨量新版组织账号 | 需兼容新版组织关系和最多四级 `team_id` |
| B站 OAuth2.0 | 需优先检查新版 MAPI OAuth2.0 授权链路 |

### 4.8 PC/Web 判断口径

| 判断点 | 口径 |
|---|---|
| 落地页打开 | 实时归因，结果落入 `dwd_ad_attr_basic_info_i` |
| 落地页转化 | 找同 `session_id` 的落地页打开归因结果 |
| 下载器/启动器启动 | 通过 `ad_link_id` 映射 Web 与 PC `device_id` |
| 超过 20 分钟未匹配 | 可处理为自然量 |
| 最近 2 天待归因事件 | 找事件时间最近 7 天落地页打开 |
| 归因结束后再上报 | 不再覆盖属性和归因结果 |
| 周/月指标 | 设备画像按天去重，周/月不能简单累计日数据 |

## 5. Agent 输出模板

### 5.1 标准输出

```text
结论：<结论标签>
置信度：高/中/低

问题定位：
<用一句话说明问题落在哪条链路>

证据：
1. <查到的页面/表/字段/状态>
2. <查到的配置或异常码>
3. <与用户现象的对应关系>

处理建议：
1. <业务/运营/产品可处理项>
2. <需要开发或数仓处理项>

是否需要开发介入：是/否
需要补充的信息：<如仍缺字段则列出>
```

### 5.2 低置信度输出

当关键数据缺失或工具不可用时，Agent 不能伪造结论，应输出：

```text
当前只能定位到：<已确认事实>
还不能下最终结论，因为缺少：<字段/权限/查询结果>
建议下一步查询：<具体表/工具/字段>
```

## 6. 案例集

### 6.1 报表类案例

| 案例 ID | 用户问题 | 输入样例 | 预期排查 | 预期结论 |
|---|---|---|---|---|

## 7. 验收集

### 7.1 验收维度

| 维度 | 验收标准 |
|---|---|
| 场景识别 | 用户自然语言问题能正确归入场景 ID，准确率建议不低于 90% |
| 追问能力 | 关键信息缺失时能追问最小必要字段，而不是泛泛要求“提供更多信息” |
| 查询编排 | 能按场景调用正确的数据工具，顺序符合 ODS -> DWD/DWS -> ADS -> 配置或反向回溯逻辑 |
| 判断口径 | 能区分故障和正常口径差异，尤其是实时/日报、虚拟回推、多团队自然量 |
| 证据输出 | 每个结论至少给出 2 条可核查证据；低置信度时明确缺失信息 |
| 处理建议 | 建议能落到责任方：产品/运营配置、测试复核、开发/数仓、媒体平台 |
| 安全合规 | 不泄露 Token、回调完整敏感参数、用户隐私字段；查询必须遵循用户权限 |
| 稳定性 | 数据工具失败时能降级说明，不编造查询结果 |

### 7.4 评分标准

建议每条验收用例按 10 分制评分：

| 项目 | 分值 | 说明 |
|---|---:|---|
| 场景识别正确 | 2 | 能识别正确场景 ID 和链路 |
| 追问字段正确 | 1 | 缺字段时只追问必要字段 |
| 查询步骤正确 | 2 | 调用表/工具顺序合理 |
| 结论正确 | 2 | 问题标签和责任归因准确 |
| 证据充分 | 2 | 至少给出关键表、字段、状态或异常码 |
| 建议可执行 | 1 | 给出明确下一步处理动作 |

上线建议门槛：

| 等级 | 标准 |
|---|---|
| 可内测 | 核心 P0 用例平均分不低于 8 分，无严重误判 |
| 可灰度 | 全量验收集平均分不低于 8 分，P0 结论准确率不低于 90% |
| 可正式上线 | 全量验收集平均分不低于 8.5 分，正常口径差异误判率低于 5% |

严重误判定义：

| 误判 | 说明 |
|---|---|
| 把正常口径差异判成系统故障 | 例如实时/日报差异、虚拟回推报表过滤、今日自然量未知 |
| 跳过前置链路直接判定下游问题 | 例如事件未归因却直接判媒体回推失败 |
| 编造查询结果 | 工具未返回或无权限时仍输出具体表数据 |
| 泄露敏感信息 | 输出完整 Token、完整回调敏感参数或用户隐私 |
| 错误责任归属 | 把配置缺失判成开发 Bug，或把调度异常判成用户筛选问题 |

## 10. 与开发沟通建议

建议用以下顺序推动：

1. 先确认 MVP 范围：优先做 `RPT-001`、`ATTR-001`、`CB-001`、`TEAM-001`、`COLL-001` 这 5 类 P0 场景。
2. 让开发按第 8 节封装工具，先返回结构化 JSON，不要求 Agent 自由写 SQL。
3. 产品/测试用第 6、7 节案例和验收集做评测，记录 Agent 的错误类型。
4. 对高频误判补充判断口径，不要只改 Prompt，要补齐工具输出字段。
5. 灰度阶段保留“需要人工复核”标签，避免低置信度问题自动下结论。
